# 선수 카드 평가식 전수 감사

이 문서는 구속 보완 전 v23의 감사 결과다. 이후 55 고정 평가의 개선 내용과 v24 검증은 [구속 결측 보완](VelocityEstimation.md)을 따른다.

2026-09-09 현재 데이터와 사용자 첨부 EX·레전드 이미지로 조사했다. **원본 기록부터 재계산한 Cost·능력치의 계산 불일치는 0건이다. 그러나 EX 선정과 Cost 판정의 기준 충돌, 미관측 능력치의 기본값 의존, 일반 카드와 특수 판본의 평가 분리가 해결되지 않았다.** 원작 표시값과 다르다는 사실만으로 일반 카드 평가식의 계산 버그라고 단정하지 않는다.

## 범위와 재현

- 1982~2025년 44개 연도, 원본 선수 시즌 **17,333건**을 Normalized 기록부터 메모리에서 다시 생성하고 기존 검증기를 실행했다. 능력치 **103,998항목**, Cost, 두 파생 Trace, Cost 입력 근거, 포지션·보직을 기존 Editor 데이터와 비교했다.
- Runtime 선수·카드 **18,326건**의 기본 연결·능력치 범위·Cost 범위를 확인했다. 이 중 원본 기록 선수 17,333건은 Editor와 Cost·능력치·선수 유형·포지션도 대조했다. 나머지는 Research 보충 939건과 생성 대체 선수 54건이며, 이 993건을 원본 기록 평가식 재계산 건수에 포함하지 않았다.
- 현재 일반 카드 참조 로더가 허용하는 **50,189개 정답 항목**, 추가 조사 DB의 **229개 카드 자료별 판본**을 대조했다. 229개는 동일 실물 카드가 Access DB와 인벤에서 각각 관측된 경우를 포함한다. 선수 229명 또는 독립 표본 229개를 뜻하지 않는다.
- EX 후보 88건을 현재 정본에서 다시 선정했다. 과거 선정과 선수는 모두 같고 Cost 미달은 52건이다.
- 자료와 설정의 입력 SHA-256을 기록했고 감사 중 입력 변경은 0건이었다. 게임 데이터·밸런스·발급 정책을 수정하거나 게시하지 않았다.

프로젝트 루트에서 실행한다. 로컬 Research 자료와 Normalized 캐시가 필요하다.

```powershell
python Tools/KBOImporter/audit_card_formula.py
```

상세 결과: [전수 감사 JSON](../../Research/PyaMaeCardDb/CardFormulaAudit/audit.json), [일반 참조 전체 오차](../../Research/PyaMaeCardDb/CardFormulaAudit/normal-reference-comparisons.json). 도구는 Research 아래 보고서만 기록한다.

## 1. EX 성과 1위와 Cost 10 조건이 서로 다른 평가를 사용한다

`evaluate_special_cards.py`는 자격 표본을 충족한 선수의 `costDerivationTrace.continuousValue`로 EX를 선정한다. `synthetic_bake.py`의 `assign_origin_year_costs`는 그 값으로 초기 Cost를 계산한 뒤 기록 회귀 모델로 다시 평가한다. 확보한 일반 카드가 있으면 `apply_annual_reference_overrides`가 마지막에 그 관측 Cost로 대체한다.

| 현재 EX 1위의 Cost 미달 원인 | 건수 |
|---|---:|
| 기록 회귀 모델 최종값 | 33 |
| 일반 카드 참조값 적용 | 19 |
| 합계 | 52 |

2014 밴헤켄은 시즌 성과 값 10.15817497, 초기 Cost 10이지만 회귀 예측 9.24668448을 반올림해 최종 Cost 9가 된다. 첨부 EX는 Cost 10이다. 이 차이는 단순 합산·반올림 구현 오류가 아니라 **일반 카드 가격 모델을 EX 발급 조건으로도 사용하는 구조의 충돌**이다. 52명을 전부 10으로 올리면 일반 카드 가격까지 변경되므로 해결책으로 채택하지 않았다.

현재는 차순위까지 찾아도 유효 Cost 10 후보가 없는 연도·역할이 미달 52건 중 14건이다. 이전 보고서의 16건은 과거 데이터 집계다.

로컬 관측에는 2002 송진우와 2005 손민한의 `EX / Cost 9` 자료도 있다. 손민한은 Access `too:777`과 인벤 `1338`, 송진우는 Access `too:826`이다. 옛 판본·재평가 시점 확인 없이 모든 원작 EX의 Cost가 항상 10이었다고 단정할 수 없다. 웹 추가 검색에서도 이 세 관측의 판본 이력을 확정할 직접 근거를 확보하지 못했다. 현재 게임의 EX Cost 10 규칙은 별도 설계 계약으로 유지한다.

## 2. 미확보 능력치는 경기력 차이를 표현하지 못하는 기본값에 의존한다

원본 투수 **7,592시즌 모두** `FastballVelocityKph` 입력이 없다. 수식 단계의 Velocity는 모두 중립값 55다. 일반 카드 참조로 구속을 대체한 뒤에도 원본 투수 중 **4,451시즌은 표시값 55**다. 이 4,451건에는 관측값 자체가 55인 카드도 포함되므로 모두 미관측 건수라고 해석하지 않는다.

구속의 공통 기준은 실측 110~170km/h를 표시 25~100으로 변환하는 설정이다. 실제 입력이 없다는 것이 문제이며, EX 사진의 표시 구속 66을 실측 66km/h로 넣어서는 안 된다. 관측 표시 구속을 활용하려면 판본·연도와 표시 수치라는 근거를 유지해야 한다.

참조 대체 전 타자도 주력 3,666건, 송구 3,753건, 수비 3,753건이 해당 항목 근거 없이 중립값으로 평가된다. 1988 김성한의 주력·수비 기본값 55가 대표 사례다. 기록이 없다는 이유로 실제 능력이 평균이라는 결론을 낼 수 없으며, 새 자료가 없는 선수의 평가에서 이 불확실성을 따로 취급해야 한다.

## 3. 일반 카드 최종 일치율이 수식 정확도를 과장할 수 있다

일반 카드 참조 **50,189항목의 최종 오차는 전부 0**이다. 이는 확보된 일반 카드 7,543시즌을 직접 동기화하는 정책의 결과다. 아래는 해당 대체를 제거하고 보존된 수식 출력으로 비교한 평균 절대 오차다.

| 항목 | 타자 MAE | 투수 MAE |
|---|---:|---:|
| Cost | 0.31 | 0.26 |
| 교타 / 체력 | 3.32 | 4.28 |
| 장타 / 구위 | 3.04 | 5.06 |
| 주력 / 변화구 | 6.93 | 4.94 |
| 송구 / 제구력 | 5.63 | 5.89 |
| 수비 / 구속 | 8.21 | 8.22 |
| 정신력 | 4.81 | 4.92 |

수비의 평균 부호 오차는 -3.43으로 과소평가 방향이다. 송구 표본은 Access에서 해당 항목을 확인한 1,907개이며 웹 카드의 번트를 송구로 비교하지 않았다. 나머지 항목별 표본 수는 상세 JSON에 있다.

이 수치는 전체 확보 자료에 대한 재현 오차이며 새로운 선수·시대에 대한 독립 예측 성능이 아니다. 배포 Cost 나무 모델은 구조 선택 후 전체 확보 표본으로 재학습한다. `fit_record_trees.py`가 그 구분을 명시하고 있으므로 이번 집계를 Holdout 성적으로 다시 부르지 않는다. 현재 일반 카드 학습 범위는 2013년까지이며, 2014년 이후 자료와 특수 카드 이미지는 자동으로 학습·보정에 반영되지 않는다.

## 4. 첨부 사진은 모든 능력치에 일정한 보너스를 주는 방식으로 복원되지 않는다

| 동일 선수 시즌 | 현재 기본값 | 첨부 카드 표시값 | 판본 |
|---|---|---|---|
| 2014 밴헤켄 | 82 / 55 / 84 / 83 / 81 / 80 | 87 / 66 / 86 / 85 / 84 / 83 | EX |
| 2014 서건창 | 86 / 68 / 92 / 73 / 79 | 87 / 70 / 84 / 80 / 78 | EX |
| 1986 선동열 | 87 / 55 / 90 / 88 / 83 / 86 | 92 / 68 / 90 / 93 / 90 / 90 | 레전드 |
| 1988 김성한 | 81 / 92 / 55 / 55 / 76 | 86 / 91 / 77 / 82 / 83 | 레전드 |

투수 순서는 체력·구속·구위·변화구·제구력·정신력, 타자 순서는 교타·장타·주력·수비·정신력이다. 타자 번트는 게임 Arm과 다른 항목이므로 제외했다. 특히 서건창은 원작보다 현재 주력이 8 높고 수비가 7 낮아 일률적인 +2로는 맞출 수 없다.

이는 **기본 시즌과 원작 특수 판본의 차이**이지 동일 등급의 정답 오차가 아니다. 현재 EX는 기본 능력치 보정 0, 레전드·커리어 하이는 Peak 시즌에 전 능력치 +2를 적용한다. 첨부 레전드가 가리키는 연도는 현재 큐레이션의 Peak와도 다를 수 있다. 예를 들어 현재 선동열 레전드는 1993년 Peak를 사용하므로 위 1986년 행은 실제 발급된 레전드와의 일대일 비교가 아니다. 이미지의 육성·촬영 시점도 미확인이므로 일반 선수 평가 학습의 정답으로 섞지 않는다.

## 5. 보직 차이와 오래된 평가 스냅샷

Editor와 Runtime 보직이 다른 선수는 46건이었다. 전부 원본과 Runtime의 서로 다른 PlayerSeasonId로 동률 순서를 계산해 마무리·셋업 상한을 적용한 차이이며, Runtime ID로 다시 계산하면 46건 모두 재현된다. Cost·능력치 차이는 없다. 이는 계산 오류로 집계하지 않았다. 다만 검수 화면과 실제 발급 보직이 달라질 수 있으므로 향후 비교 도구는 Runtime의 최종 보직을 함께 보여주는 것이 좋다.

기존 `SpecialCardCurationEvaluation/evaluation.json`의 입력 파일 중 **19개가 현재 해시와 다르다**. 기존 Bake 검증기는 이를 거부하므로 과거 레전드 재료 정책을 그대로 재사용해 새 발급을 진행할 수 없다. 이번 EX 순위는 현재 파일에서 독립 계산했으며, 기존 커리어 하이 112장·레전드 20장의 재발급·정책 갱신을 실행했다는 뜻은 아니다.

## 개선 우선순위와 검증 한계

1. 일반 시즌 평가와 특수 카드의 등급·Cost·판본별 능력치 정의를 분리하고 EX 성과 1위/Cost 10의 충돌을 해결한다. 원본 일반 카드 가격을 임의 승격하지 않는다.
2. 구속·주력·수비 결측부터 보완한다. 실제 기록, 일반 카드 표시값, 특수 판본 표시값, 추정값을 구분해 입력한다.
3. 일반 카드만으로 주력·수비 평가를 다시 검증하고, 시대·선수 분리 검증을 통과한 변경만 적용한다. 첨부 EX·레전드 네 장에 맞춰 공통 계수를 조절하지 않는다.
4. 결정된 정본을 기준으로 특수 카드 평가·Peak·큐레이션 재료를 다시 생성한 뒤 발급 검증을 수행한다.

원본 재계산을 두 차례 실행했고 최종 감사에서 값·Trace 불일치 0건, 미설명 보직 차이 0건이다. 평가·회귀·참조·특수 카드 57개와 보직·대체 선수·Research 보충 경로 28개를 합쳐 기존 Python 테스트 **85개가 통과**했다. Unity 컴파일·EditMode·실제 경기 대량 시뮬레이션은 이번에 실행하지 않았다. 평가식·밸런스 수치를 바꾸지 않았으므로 경기력 개선이나 밸런스 검증 완료를 주장하지 않는다.
