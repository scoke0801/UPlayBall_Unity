# 번트 독립·송구의 수비 통합 변경안

사용자 확정: 송구는 수비에 포함하며 번트는 별도 주요 스탯이다.
타자 6축은 Contact, Power, Speed, Bunt, Defense, BatterMental로 한다.
EX 원본 10코스트와 레전드 원본 9~10코스트 규약은 변경하지 않는다.

## 기존 코드와 필요한 의미 변경

| 경로 | 현재 | 변경 |
|---|---|---|
| PlayerAbility / AbilityRatings | 4번째 축 Arm | 4번째 축 Bunt; 다른 능력치 순서는 유지 |
| BatterAttributes | Bunt를 Contact·Mental에서 매번 계산 | Bunt를 생성·저장한 독립값으로 소비 |
| FieldingProfile.Derive | Arm으로 송구 판정 | Defense로 Range·Hands·Arm을 파생; 번트가 수비에 영향 주지 않음 |
| DetailedMatchEngine / HistoricalMatchConfiguration | Arm 전술 보너스를 수비에 전달 | Defense 보너스만 수비에 전달; 중복 적용 금지 |
| 성장판 | bunt ID 블록이 Arm을 올리고 DefensiveFocus를 제공 | 번트 능력치 상승; 수비 Trait 연결은 제거·재검토 |
| 수비 유학·자연 성장·역할 평가 | 별도 Arm 가중치 | 송구 가중치를 Defense로 합산; 번트의 수비 가치 대체 금지 |
| 카드 팝업·수집·성장·신규 선수 화면 | 송구 축과 파생 번트 표시가 공존 | 6축 독립 번트 표시·보너스 출처 제공 |
| 원본 카드 수집 | DB 어깨→Arm, 일부 웹 번트 제외 | 번트 출처를 별도로 읽음; 어깨 관측을 번트로 재해석하지 않음 |
| 베이크·세이브 | 배열 4번째 값이 Arm | 버전을 올리고 재저작; 배포 전 세이브 마이그레이션은 만들지 않음 |

전역 문자열 치환만으로 구현하지 않는다. `FieldingProfile.Arm`은 수비의 파생 송구값이므로
유지할 수 있지만 `PlayerAbility.Arm`을 번트로 바꾸는 곳과 같은 처리를 해서는 안 된다.
새 번트 관측이 없는 선수는 결측과 추정 근거를 기록한다. 희생번트 횟수만으로 성공률이나
번트 능력치를 확정하지 않는다. 관측된 번트 수치를 우선하고 미관측 추정 정책은 별도로 검증한다.

## 적용 순서와 검증

1. Core·Simulation·Game 연결을 함께 수정한 후보를 컴파일한다. 번트가 다르고 수비가 같은
   선수의 수비 결과가 같으며, 수비가 다르고 번트가 같은 선수의 번트 접촉 평가가 같은지 검사한다.
2. 성장·강화·팀컬러·전술·훈련·스냅샷에서 번트의 독립값이 보존되는지 검사한다.
   수비 보너스가 송구에 한 번만 적용되는지 확인한다.
3. 원본 번트 관측·결측 정책을 포함해 44년 Editor/Runtime 후보를 새 경로에 재발급한다.
   원본 카드 코스트·레전드 기준 시즌·EX 취소 규약은 유지한다.
4. 세이브 및 베이크 버전을 올리고 Fast/Full 로더와 전체 EditMode 테스트를 실행한다.
5. 기존 상세 경기와 같은 연도·시드로 대량 비교한다. 팀 승률·타율·ERA·홈런·득점·BB/K 외에
   희생번트·번트 안타·번트 실패·송구 실책·도루 저지를 따로 검증한다.
   상세/간이 비교와 능력별 전력 격차도 검사한다. 결과 개선 없이 수치만 적용하지 않는다.
6. 카드·성장·신규 선수 UI에서 독립 번트값과 보너스 내역, 기존 6축 배치의 해상도·입력을 확인한다.
7. 검증 후보만 백업 후 정본에 적용한다.

## 현재 상태

설계 확정·경로 조사까지 완료했으며 게임 코드와 콘텐츠의 번트 전환은 아직 적용하지 않았다.
전역 식별자 치환 스크립트는 자동 승인 검토에서 송구·수비 의미 훼손 위험으로 거부되었다.
Core `PlayerAbility.Arm`과 기존 경기 입력이 유지됨을 확인했다.
이 문서는 파일별 의미를 구분한 구현 검토안이며 번트 기능 완료 보고가 아니다.
