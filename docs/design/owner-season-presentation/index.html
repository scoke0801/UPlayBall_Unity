04

ImageGen 아트 디렉션

표와 버튼은 게임의 언어 그대로

평소에는 밝고 조밀한 정보 UI를 유지한다. 정규시즌 마감은 작은 페넌트와 순위, 포스트시즌은 대진 연결선과 구장 띠 이미지, 우승 결산은 트로피와 조명으로 강조한다.

우승만 크게, 패배도 존중하며

우승 장면은 짧은 전면 연출을 허용한다. 준우승·탈락·강등에서는 색종이와 승리 음악을 사용하지 않고, 결과와 다음 행동을 먼저 보여준다.

이미지는 시각 콘셉트다. 생성 이미지의 문구·수치·행 수·대진 연결 및 메뉴 배치는 구현 명세가 아니다. 위 HTML 미리보기와 아래 규칙이 정본이다. 실제 Unity에서는 배경·트로피·장식만 이미지로 만들고 모든 수치·텍스트·버튼·표는 Native uGUI/TMP로 그린다. 이미지의 8팀 표·좌측 메뉴·‘팀 승리 기여도’는 채택하지 않으며, 실제 조 인원·기존 Shell·검증된 기록만 사용한다.

내장 ImageGen 사용 · 최종 생성·수정 프롬프트 · 확인한 기존 덕아웃 화면 · 기존 공용 Shell을 바꾸거나 이미지 전체를 게임 화면으로 붙이지 않는다.

한 번의 사건, 한 번의 공개

개별 경기·핵심 관전·결과만 보기·정규시즌 일괄 진행은 같은 확정 결과를 소비한다. 일괄 진행 중 작은 순위 알림은 요약하고 정규시즌 종료에서 멈춘다.

이미 계산된 우승·시즌 기록은 마지막 경기 결과를 사용자가 확인하기 전까지 홈·알림·헤더에서 공개하지 않는다. 연출 Skip은 결과 공개를 완료할 뿐 경기나 급여 Command를 재호출하지 않는다.

반복 플레이와 접근성

처음에는 전체 연출, 다시 열 때는 정적인 보고서. 음악은 설정 볼륨을 따르고 UI 안내와 가이드는 연출 종료 후 재개한다.

키보드 포커스는 건너뛰기 → 주 행동 순서. 색뿐 아니라 ‘우승·탈락·승격권’ 텍스트를 사용한다. 1280×720에서 주 행동을 고정하고 표 본문만 스크롤한다.

06

포스트시즌 규칙 제안

구단주 전용 신규 정책 · 구현 시 기준 문서에 반영

조별 상위 4팀 토너먼트

  • 정규시즌 결과를 잠근 뒤 같은 Owner 순위 Resolver에서 시드를 받는다. 커리어의 SelectSeeds를 그대로 호출하지 않는다.
  • 준결승 1위–4위 / 2위–3위, 3전 2선승. 결승 5전 3선승. 준결승 상위 시드 홈 1–1–1, 결승 2–2–1.
  • 승수·홈 배정 등 순수 규칙의 재사용은 가능하나 구단주 Runtime·계약·카드·선수 상태는 별도로 소유한다.
  • 모든 AI 조도 같은 규칙과 DetailedMatchEngine을 사용한다. 등급 전체 왕중왕전은 이번 범위에 포함하지 않는다.

소수 조와 무승부

  • 4팀 이상: 상위 4팀. 2~3팀 조: 상위 2팀이 결승만 진행. 1팀 조는 현행 편성 오류로 처리하며 우승을 만들지 않는다.
  • 정규시즌 무승부는 기존 순위 규칙을 유지. PS 무승부는 시리즈 승수에 포함하지 않고 별도 GameId로 추가 경기한다.
  • 무승부 뒤 홈 배정은 아직 결착 나지 않은 승패 경기 슬롯을 유지한다. 무승부 경기의 투구 부하·카드 소모·재정은 실제 경기로 1회 반영한다.
  • 시리즈 시작 전 1휴식 라운드를 기본 제안한다. 자동 진행은 작업 단위별 취소 가능해야 하며 무승부가 이어져도 우승을 임의 판정하지 않는다.
신규 정책의 재정 영향: PS 홈 경기 수입은 기존 홈 경기 정산 모델을 재사용하고 프리미엄 배율·별도 우승 재화 보상은 이번 버전에 추가하지 않는다. 실제 PS 경기 수에 따른 수입·급여 여력 변화는 다수 시즌 검증이 필요하다. 시리즈 길이·휴식값은 Owner 전용 Balance로 저작해 커리어 기본값을 바꾸지 않는다.

포스트시즌 시작 이후 해당 시즌 종료까지 1군 등록·트레이드는 잠근다. 현재 25인 내 타순·수비 배치, 덕아웃 방침, 보유 전술 준비는 기존 권한으로 허용한다. 계약 연장은 허용한다. 별도 실시간 교체 명령은 신설하지 않는다. 잠금은 UI 표시와 Game 검증 양쪽에서 같은 사유를 반환해야 한다.

결산은 다음 선택의 근거다

보고서 영역필수 데이터플레이어가 가져갈 판단
시즌 성과정규시즌 최종 순위·승패무 / PS 단계·시리즈 전적 / 다음 등급과 변경 사유‘4위로 승격권을 확보했지만 준결승에서 탈락했다.’ 두 결과를 독립적으로 이해.
팀 기록정규시즌 득점·실점·득실차·팀 타율·ERA 및 리그 순위. PS 기록은 별도 보기.실점이 많았는지, 득점이 부족했는지 확인. 시즌 합계만으로 특정 전술을 패인이라 단정하지 않음.
선수 기록기존 리더보드 규정 충족 선두·우리 선수 강조·기록 상세 링크누가 기여했는지 확인. 별도 MVP 선정식이 없으면 MVP·골든글러브 수상을 발명하지 않음.
구단 운영실제 시즌 수입·지출, 지급 예정 선수/스태프 급여, 현금, 만료 임박 계약 수‘시즌 종료 잔액’과 ‘급여 지급 후 예상 잔액’을 구분. 지급 성공 뒤에만 확정 정산으로 표시.
다음 행동현재 Query가 반환한 차단 사유와 기존 업무 Route계약 갱신 / 재정 확인 / 선수단 검토 중 필요한 곳으로 이동. 재진입하면 같은 결산 페이지 복원.

예시 문구: “팀 ERA 리그 8위. 투수진 기록을 확인하세요.”는 관측 사실에 기반한다. “투수 교체가 늦어 시즌을 망쳤습니다.”처럼 실행 기록과 비교 근거가 없는 인과 설명은 사용하지 않는다. 팀컬러 효과 역시 해당 경기 입력으로 검증된 값만 상세에 표시한다.

Global 메뉴는 추가하지 않는다. 기존 Shared.League.Standings 작업면 안에 정규시즌/포스트시즌 Selector를 두고, Shared.League.RankHistory의 기존 순위 흐름을 연결한다. 시즌 결산은 Owner 전용 Local 화면 ‘시즌 결산’ 1개를 제안하며 역사 기록의 시즌 선택에서도 연다.

PS는 전역·로컬 Route를 추가하지 않는 화면 내부 보기다. 경기 준비/Match Center는 원래 화면과 선택 시즌을 보존한다. 계약·재정 화면으로 이동했다 돌아오면 Snapshot 버전을 비교해 Preview만 갱신한다.

시즌 마감 버튼은 Preview의 시즌·상태 버전을 Command에서 재검증한다. 클릭 중 중복 입력을 막고, 오래된 Preview는 재조회한다. 재조회 실패를 성공 연출로 덮지 않는다.

기억에 남는 순간 추가

구장·트로피 장식, 짧은 전환·음향·순위 강조를 적용한다. 실제 3해상도에서 표·한글·포커스·주 행동을 확인한다.

게이트: 1280×720 / 1920×1080 / 2560×1440, 동작 줄이기, 결과만 보기, 반복 시즌.

검증 체크리스트 — 구현 시 통과해야 완료
  • Core/Simulation noEngineReferences 유지와 대상 asmdef 컴파일 오류 0.
  • EditMode: Owner 최종 순위와 PS 시드 일치, 동률/무승부/소수 조/홈 배정, 시리즈 조기 종료 후 불필요 경기 미생성.
  • 결정론: 같은 Seed·입력에서 개별 진행/일괄 진행/저장 후 재개 결과와 이벤트 일치. 연출 속도·Skip이 결과를 바꾸지 않음.
  • 집계: 정규 기록이 PS 진행 전후 동일. PS BoxScore와 별도 팀·선수 누적 합계 일치. 완료 시즌 조회 시 로스터 이월 후에도 선수 식별 유지.
  • 정산: 계약 갱신 필요·급여 부족·미리보기 노후화·중복 클릭·Commit 후 재시작에 이중 차감/새 시즌 이중 생성 없음.
  • 통계: 신규 PS 경로 1,000시즌 이상 권장. 총 경기 수·무승부 추가 경기·시드별 우승률·수입/잔액 분포·진행 시간 보고. 결과는 조 규모·등급별로 나누고 임의 우승률 목표에 맞춰 보정하지 않음.
  • 밸런스 수치를 변경한다면 정규·PS를 분리하여 대량 경기의 타율·ERA·홈런·득점·BB/K를 기존 기준과 비교해 보고. 이번 HTML 기획 작업은 수치 변경 없음.
  • Unity 실제 화면/입력: 미공개 결과 누출 없음, ESC·복귀·계약 화면 왕복, 가이드/결과음 중복 없음, 장시간 3시즌 연속 흐름 검증.
