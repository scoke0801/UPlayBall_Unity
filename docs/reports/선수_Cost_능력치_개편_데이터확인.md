# 선수 Cost·능력치 개편 데이터 확인

## 적용 결과

1982~2025년 44개 연도, 363개 구단 시즌을 재생성했다. Source 선수 시즌 17,333개와
Replacement 54개를 프로젝트의 Editor·Runtime Archive에 반영했다.
Source Cost 변경은 11,950개, 시즌 주포지션 변경은 712개다.

이번 작업은 코드 수정·JSON 재생성·데이터 확인까지다. 사용자 요청에 따라 테스트, 컴파일,
Unity 실행, 경기 시뮬레이션은 수행하지 않았다. 아래 수치는 경기 결과가 아니라 저장 데이터다.

## 변경 정책

- Cost를 연도별 백분위와 출전량 상한의 최솟값에서 **역할별 종합 능력치의 고정 구간**으로 바꿨다.
  같은 종합 능력치는 같은 가격이다. Source와 Replacement는 공용 가격 함수를 사용한다.
- 성과의 소표본 사전 Z는 -1, 수비·송구 근거 부족의 사전 Z는 0이다. 관측 Z는 ±3으로 제한한다.
  극소표본 선수가 자동으로 평균 전력에 가까워지는 문제를 줄이되, 충분한 성과 증거가 있는 부분
  출전 선수가 성적이 낮은 풀타임 선수보다 좋은 평가를 받는 것은 허용한다.
- 신뢰도 기준의 표본 상수는 당시 구단 시즌 경기 수 / 144로 조정한다. 44개 연도 모두 실제
  구단 경기 수를 사용했고 fallback은 없었다. 1982년은 80경기 기준이다.
- 공격·투구 효율의 비교 집단을 연도 전체 타자/투수로 통일했다. 수비와 투수 Stamina는
  포지션·역할군 비교를 유지한다. 주요 Rating 변환 폭을 확대하고 공격의 역할 가중치를 조정했다.
- DH 중심 기용을 타격 출전과 실제 수비 이닝 비율로 추론한다. 실제 주수비 위치는 Trace에
  보존한다. 공식 DH 출전 기록을 복원하거나 Runtime 복수 포지션 기능을 추가한 것은 아니다.
- 훈련 여유는 최종 Runtime Bake에서 Cost와 무관하게 모든 능력치 +3(상한 99)이다.
  저Cost에 더 큰 성장 여유를 주던 가격·전력 역전 요인을 제거했다.
- Editor 상세창은 실제 비교 집단, 관측/제한/사전/보정 Z와 고정 Cost 구간을 표시하도록 수정했다.
  출전량·백분위는 가격 상한이 아니라 참고 진단임을 명시했다.

계수와 역할별 가중치, Cost 구간은 `Tools/KBOImporter/derivation_balance.json`에 있다.
Ability v5 / Cost v7 / PositionRole v5 / DerivationBalance v9를 사용한다.

## 선수 사례

타격 능력치는 Contact / Power 순서다. Cost의 의미와 변환 척도가 바뀌었으므로 전후 Cost 숫자만으로
선수의 능력 상승률을 해석하지 않는다.

| 2024 최형우 | 3→8 | 50/57→51/67 | LF→DH 중심 시즌 추론, 공격 성과 반영 |

각 위치의 manifest·player_persons·44개 Years JSON만 교체했다. 기존 .meta와 Catalog GUID는
유지했으며 파일 삭제는 없었다. 생성 Archive는 저장소 ignore 대상이므로 코드 diff만 전달해서는
다른 환경의 데이터가 자동으로 바뀌지 않는다. 해당 환경에서도 같은 Normalized 입력으로 재Bake하고
실제 Runtime 경로를 동기화해야 한다.

## 별도 검증이 필요한 부분

1. 사전 Z=-1, Rating 폭, 역할 가중치와 Cost 구간은 밸런스 초안이다. 실제 경기의 Cost별
   기대 성적·승률, 리그 평균, AI 기용과 선발/구원 성능을 별도로 확인해야 한다.
2. Cost 분포가 달라졌으므로 로스터 예산, 영입·판매·계약 경제, 훈련 소요와 최종 전력도 확인해야 한다.
3. DH 판정은 수비 기록의 완전성과 대타·부상 복귀 기용의 영향을 받는다. 712개 변경 시즌에 대한
   포지션 표본 검수는 경기 검증과 별도로 필요하다.
4. 구속·구종의 실측 데이터가 없으므로 Velocity·Breaking 등은 결과 지표 기반 대용치다.
   이번 작업이 실제 선수의 모든 플레이 스타일을 복원하지는 않는다.
5. 기존 ContentHash로 생성한 WorldHistory/캐시가 있다면 새 정본 기준으로 별도 재생성이 필요하다.
   기존 Save의 호환성·이어하기는 확인하지 않았다. 이번 작업에서 WorldHistory Bake는 실행하지 않았다.
