# 구단주·선수 모드 독립성 검토

검토 대상은 2026-09-06 현재 작업 폴더의 미커밋 변경을 포함한 코드다. 게임 코드는 수정하지 않았다.

## 판정

모드별 상태·경제·UI 진입 분리의 기본 구조는 갖춰져 있다. 그러나 장기 진행과 저장까지 포함해
두 모드가 필요한 기능을 독립적으로 완비했다고 판정할 수는 없다.

`BaseballManager_PROJECT.md` 서두의 2026-08-31 결정에 따라 구단주 모드는 정식 두 번째 진입점이다.
AGENTS.md의 선수 모드 전용 설명만 근거로 구단주 구현을 규약 위반으로 판단하지 않았다.
최신 41.12절과 43.1절의 명시적 범위 결정을 과거 계획·완료 기록보다 우선했다.

## 확인된 결함

### 높음 — 구단주 경기에서 전술 카드 소모 실패가 경기 확정 뒤 발생한다

`ManagerModeMatchService.cs:350`의 프리셋 검증은 실제 보유 카드가 아닌 전술 정의 전체 ID를
유효 목록으로 전달한다. 이후 190~193행에서 경기 완료·선수 상태·기록을 반영한 다음에야
전술 카드를 소모한다. 보유량이 부족하면 842행에서 예외가 발생하므로 실패한 명령이 이미
일정과 기록을 변경한 상태로 남는다. 두 슬롯 중 뒤쪽 소모가 실패하면 앞쪽 소모도 되돌리지 않는다.

`ManagerOwnerProductionE2ETests.OwnerLoop_OperationStaffPregameMatchFinanceAndLoad_RemainsOneTransactionChain`
이 `tactic.owner.contact` 미보유 예외로 실패했고 단독 재실행에서도 재현됐다.
테스트 fixture의 보유량·장착 갱신을 최신 규칙에 맞추는 일과 별도로, Production 서비스는
실제 보유량을 경기 전 재검증하고 실패 시 상태를 변경하지 않아야 한다.
Unity Manager는 경기 후 장착을 비우는 처리가 있으므로 이 재현을 모든 정상 UI 경기에서
발생하는 오류로 확대 해석하지 않는다. 서비스 경계의 원자성과 기존 통합 검증이 깨진 것은 확인됐다.

### 높음 — 구단주 시즌 전환에서 이전 시즌 기록이 영속 상태에서 빠진다

- `Assets/02.Scripts/Game/Historical/ManagerModeRuntimeState.cs:442`의 `CreateNextSeason`은
  통계 인자를 전달하지 않고 다음 `ManagerLiveSeasonState`를 생성한다.
- 같은 파일 57행에서 새 빈 `LeagueSeasonStatisticsState`가 만들어지고, 232행에서
  `LiveSeason`을 교체한다. 완료 시즌을 별도 이력 컬렉션에 넣는 처리가 없다.
- `ManagerHistoricalSaveAdapter.cs:300`은 현재 `LiveSeason`만 저장한다. `WorldHistory`는
  새 게임의 과거 시뮬레이션 기록이며 운영 중 끝난 시즌을 여기에 추가하는 경로도 없다.

따라서 첫 시즌 경기를 진행한 뒤 시즌을 넘기고 저장하면, 그 시즌의 개인 기록과 일정별 결과를
저장 상태에서 다시 조회할 수 없다. 새 시즌 집계를 초기화하는 것은 맞지만 완료 시즌을 먼저
보존해야 한다. 이는 모든 데이터 구조를 여러 시즌 누적으로 설계한다는 규약과 충돌한다.

현재 `OwnerSeasonRecordsTests`는 한 시즌 안의 BoxScore 집계·결정론·저장 왕복을 검증한다.
`ManagerOwnerProductionE2ETests`의 시즌 전환 검증은 급여·계약·다음 일정에 집중하며,
완료 시즌 기록 보존을 확인하지 않는다. 완료 시즌 스냅샷과 Save 매핑을 추가하고
두 시즌 진행 → 저장 → 복원 후 양쪽 시즌 기록을 비교하는 회귀가 필요하다.

## 문서에 명시된 미완료·제한

- **선수 커리어 디스크 저장 미지원:** PROJECT 41.12절에 명시되어 있다.
  `UI_Popup_CareerSettings.cs:314`도 저장 미지원과 타이틀 복귀 시 진행 소멸을 안내하고,
  432행에서 `EndCareer()`를 호출한다. 문서와 다른 구현은 아니지만, 플레이 세션을 나누어
  커리어를 이어가거나 선수 → 구단주 → 기존 선수 커리어로 복귀하는 완전한 흐름은 제공하지 못한다.
- **구단주 승강은 같은 참가팀의 등급 변경:** PROJECT 43.1절의 현재 결정과 일치한다.
  `ManagerHistoricalRuntimeState.cs:97`은 참가팀을 유지하고 Grade만 바꾸며,
  `ManagerModeRuntimeState.cs:442`도 같은 팀으로 다음 일정을 만든다.
  선수 모드의 다중 리그 소속 이동과 동등한 기능으로 해석하면 안 된다.
- **최신 규약 문서 불일치:** AGENTS.md의 구단주 범위 제외 설명, 이전 로드맵의 승강 미구현·
  Save schema 4 설명과 최신 PROJECT 43.1절·현재 SaveVersion 9가 공존한다.
  과거 기록과 현재 완료 조건을 분리해 정리할 필요가 있다.
