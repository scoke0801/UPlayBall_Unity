# 프야매 팀덱 자료를 이용한 Cost·기록 평가 역설계 검토

작성일: 2026-09-06. 범위는 자료 수집·현행 분석·적용 가능성 검토다. Production 평가식, 밸런스, Bake 데이터는 변경하지 않았다.

추가 자료: 사용자 제공 `docs/ref` 복원 엑셀의 실제 집계·중복 후보·능력치 대응 검토는 [엑셀 추가 검토](엑셀_추가검토.md)에 기록했다. 초기 서비스 관측값의 모델 비교를 시작할 근거가 늘었으며, 아래 후기 Normal 유효 표본 수는 기존 Corpus 기준으로 읽는다.

## 결론

**선수별 예외 없이 원작에 가까운 Cost·능력치 배분을 추정하는 것은 가능하다. 다만 현재 자료로 원작 산식 복원이나 높은 일치율을 보장할 수는 없다.** 가장 먼저 해결할 것은 모델 복잡도가 아니라 카드 종류·재평가 시점·육성 상태가 확인된 정답 표본의 부족이다.

권장 목표는 재평가 이후 일반 카드의 기본 능력치와 Cost다. 이는 이번 검토의 제안이며 새 TargetPolicy 확정이나 구현 승인으로 기록하지 않는다. 최초 출시 카드와 후기 카드는 별도 평가 집단으로 유지한다. 현재 프야매 후기 Normal 유효 표본은 기존 연구 집계상 1장뿐이다.

Cost·기본 능력치·육성 후 덱 성능을 각각 평가해야 한다. 같은 Cost에서도 장단점이 다른 선수가 남아야 기용과 수집 선택이 의미가 있다. 원작에서 특정 덱이 강하다는 서술만으로 그 팀 선수의 기본 능력치를 일괄 가산하는 방식은 권하지 않는다.

[동일 제목 미러의 상위 문서](https://www.namu.moe/w/프로야구%20매니저/주요%20팀덱)는 본문을 읽었다. 아래 14개 하위 문서 링크를 확인하고 접근했으나 하위 페이지 직접 열기는 모두 Cache miss였다. 따라서 **하위 문서 전체·이미지 전체 수집 완료가 아니다.** 검색에 노출된 미러·과거 복제본의 본문 발췌로 대표 사례를 수집했다. 원문과 미러가 같은 최신판이라는 보장도 없다.

## 기존 연구 자산과 이번 재집계

`Tools/PMReference/corpus/`에 기존 수집본과 검수 기록이 있다. 기존 `PM_REFERENCE_CORPUS_SUMMARY.json`은 관측 651건, 중복 제거 카드 628장, 23시즌·26 TeamSeason을 기록한다. 타입은 Unknown 612장, EX 13장, Rare 2장, Normal 1장이다. 595장은 Cost를 별도 검수했다고 기록되어 있지만 이는 **후기 Normal 정답 595장**을 뜻하지 않는다. 기존 검수 이미지를 이번에 모두 다시 판독한 것은 아니다.

기존 보고서는 Ability v5 / Cost v8 / Balance v11 기준이었다. 현행은 Ability v6 / Cost v9 / Balance v12다. 아래는 기존 CSV의 `OriginalObserved2011` 중 숫자 Cost가 있고 현재 Runtime ID로 연결되는 같은 491개 표본을 현재 배포 JSON과 다시 대조한 결과다.

| 지표 | 기존 v8 보고서 | 이번 현재 v9 재집계 |
|---|---:|---:|
| 표본 수 | 491 | 491 |
| Cost 정확 일치 | 30.75% | 29.12% |
| 오차 ±1 이내 | 69.25% | 66.40% |
| 평균 절대 오차(MAE) | 1.134 | 1.200 |
| 현재 Cost - 참조 Cost 평균 | — | +0.935 |
| 연도 Holdout 98장 정확 일치 | 24.49% | 23.47% |
| 연도 Holdout ±1 이내 | 72.45% | 64.29% |

**이 표본에서는 v9가 v8보다 원작 관측값에 더 가까워지지 않았다.** 단, 2011 관측·종류 미확정 자료와 후기 정책 간 버전 차이가 있으므로 후기 원작 재현도나 게임 밸런스 악화로 일반화할 수 없다. Holdout 이름은 기존 분할을 보존한 것이며, 과거 개발 중 결과 열람·조정 여부를 통제한 새로운 독립 시험은 아니다. 이번에는 모델 학습을 실행하지 않았다.

재현: 프로젝트 루트에서 `& docs/reports/pm_reference_review_20260906/compare_current_cost.ps1` 실행. 출력 `current_cost_comparison.csv`는 선수별 대조, `current_cost_metrics.json`은 지표·현재 SourceManifest·입력 44개 연도 파일 및 참조 CSV hash를 보존한다. 미연결 ID는 조용히 버리지 않고 오류로 종료한다. 기존 연구 보고서를 덮어쓰지 않는다.

## 현행 평가 구조

기준 코드: `Tools/KBOImporter/derivation_balance.json`, `synthetic_bake.py`의 `cost_metric_evidence`, `elite_cost_ceiling`, `assign_origin_year_costs`, `derivation_cost.py`.

```text
실제 시즌 기록 → 표본 신뢰도·시즌 비교 집단 보정 → 기본 능력치
실제 시즌 기록 → quality + 출전량 + 수비 기여 + 역할 보정 → 연속 가치 → Cost 구간/9·10 자격
PlayerSeason.Cost → RosterCostResolver → 주전 야수 9명 + 투수 11명 합산
```

Cost는 능력치 평균 하나로 정하지 않는다. 주요 계수와 구간은 JSON에 있으며, 정본을 Offline Bake해 Runtime에 전달하는 구조는 이번 방향에 적합하다. 커리어의 `PlayerValueEvaluator`는 포지션별 능력치 가치와 팀 선호를 평가하는 별도 경로이며, 카드 Cost 역설계 대상으로 혼동하면 안 된다.

현재 Cost quality는 표본 보정 지표의 가중합이다. 타자는 AVG 45%, SLG 25%, HR 25%, SB 5%, 투수는 ERA 역방향 75%, BB/9 역방향 25%다. 원시 AVG 등에 이 비율을 바로 곱하는 식은 아니다. 결측 지표는 제외 후 재정규화한다.

연속 가치의 기본점은 2.5, quality 배수는 2다. 타자 출전량은 시즌 길이 보정 PA 목표 500과 곡선을 사용하고, 투수는 IP·선발 비율·역할별 목표를 사용한다. 역할 보정은 최대 ±0.5다. Cost 9/10은 quality·출전량·신뢰도 자격을 추가 검사한다.

| 평가 항목 | 현재 입력 | 역설계 관점의 제한 |
|---|---|---|
| 교타 / 타자 멘탈 | 모두 AVG, 변환 scale 차이 | 같은 타율에서 선구·멘탈 차이를 복원하기 어려움 |
| 장타 | HR 50% + SLG 50% | 출전량이 HR와 Cost workload 양쪽에 영향. 중복 효과를 검증할 필요 |
| 주력 | 도루 수 | 도루 시도 성향과 실제 달리기 능력의 구분이 부족 |
| 체력 | 시즌 IP를 427⅓이닝=100으로 선형 변환 | 현대 선발과 과거 혹사 투수의 사용 가능 이닝을 원작처럼 평가하는지는 미확인 |
| 구속 | 실측 구속, 결측 55 | 자료가 없는 선수 간 구속 개성은 재현할 수 없음 |
| 구위 / 변화구 / 투수 멘탈 | 모두 ERA 역방향 | 서로 다른 강점의 투수를 표현할 독립 근거가 부족 |
| 수비 / 송구 | 수비율·실책, 보살·도루저지 등 가용 지표 | 수비 범위·포지션별 기회와 기록 결측을 별도로 고려해야 함 |

보완 후보는 K%, BB%, ISO, HR/PA, SB 시도·성공률, GS/G, IP/GS, 구속·구종 자료다. **이 항목이 원작의 실제 입력이었다는 주장은 아니다.** 원작 라벨에 대한 추가 설명력을 검증할 후보이며, 기존 정규화 Source가 실제로 제공하는 항목부터 사용한다. 정신력·구종별 등급을 시즌 합계 기록만으로 정확히 복원하는 것은 식별 정보가 부족하다.

추가로 Cost9의 연속 가치 구간은 9.4~9.5로 매우 좁고 9·10 자격 상한이 결과를 다시 바꾼다. 따라서 구간 폭만 조절하면 해결된다고 볼 수 없다. 고평가/저평가를 quality, workload, roleAdjustment, elite gate 기여로 나눠 검수해야 한다.

하드코딩이 완전히 제거된 구조는 아니다. 예를 들어 수비 기여의 Defense/Arm 혼합 0.75/0.25, 중심 55, 폭 20 등이 Python 본문에 남아 있다. 재보정 대상으로 채택한다면 먼저 명명된 설정으로 옮기고 설명 Trace를 유지하는 편이 좋다. 이번에는 수정하지 않았다.

## 권장 역설계 절차

1. **정답 정책을 고정한다.** 후기 일반 카드의 미육성 기본값을 1차 목표로 권장한다. 최초 출시, 재평가 이후, 개별 수정 불명은 별도 버전이다. EX·Rare·Classic·Legend·Franchise는 별도 집단으로 보관한다. Edition 차이는 관측 근거로 확인하며 Normal로 간주하지 않는다.
2. **관측 자료를 정규화한다.** 원문 URL, 이미지 URL/hash, 확인일, 시즌, 원작 표시 이름, SourcePlayerId, 구단, 투타/포지션, 종류, 버전, Cost, 기본 능력치, 육성·팀컬러 여부, 검수 상태를 저장한다. 값 미상은 null로 두고 팀 합계·육성 후 수치를 기본 능력치 칸에 넣지 않는다. 가명·동명이인 매핑은 연구용 Source 연결에서만 사용한다.
3. **자료의 편향을 보완한다.** 강덱 문서의 주전만 모으면 스타 중심 편향이 생긴다. 약팀·저 Cost·벤치·중간계투와 시대를 함께 채운다. 기존 연구 기준인 유효 250장·10시즌·20 TeamSeason은 최소 작업 시작선으로 쓸 수 있으나 충분한 통계 검증을 보장하는 숫자는 아니다. Cost 라벨과 능력치 라벨의 Coverage를 따로 센다.
4. **현재 모델을 기준으로 작은 후보를 비교한다.** 먼저 quality 가중치·표본 보정·출전량 곡선·Cost 경계를 제한된 범위에서 추정한다. 다음으로 역할별 절편/기울기 또는 순서형 회귀를 비교한다. 유효 데이터가 적을 때 복잡한 모델과 선수별 보정은 피한다. 능력치는 항목별 단조 곡선으로 검증하고 Cost와 공동으로 강제하지 않는다.
5. **이름 없이 일반화되는지 확인한다.** 시즌·구단 계보·선수 단위 분할을 각각 수행한다. 같은 선수의 다른 시즌과 같은 카드의 다른 버전이 학습/검증에 걸쳐 들어가는 누출을 검사한다. 후보 탐색이 끝나면 새 미사용 검증 표본을 확보한다. 2016년 이후 KBO는 원작 정답이 없는 확장 구간이므로 원작 일치율을 주장하지 않는다.
6. **채택은 개별 오차와 게임 검증을 함께 본다.** Cost exact/±1/MAE, 역할별 signed error, 9·10 정밀도·재현율, 기본 능력치별 MAE·순위 상관, 동일 선수 구성 덱 합계를 보고한다. 덱 합계만 맞추면 선수별 과대·과소가 상쇄되므로 충분하지 않다.

초기 합격선 제안은 확인된 목표 버전의 독립 표본에서 Cost exact 60% 이상, ±1 90% 이상, MAE 0.6 이하이며, 현행보다 개선되어야 한다. 이는 실현 가능성을 검증한 약속이나 원작 기준이 아니라 프로젝트의 제안 목표다. 역할·시대별 오차와 능력치 표본의 판독 오차도 함께 판단한다.

채택 계수는 버전이 있는 JSON/Balance 데이터로 저장하고 순수 C# 구조와 Offline Bake 계약을 유지한다. 원작 선수명→Cost 조회표를 Production에 연결하거나 특정 팀 이름으로 능력치를 가산하지 않는다. 결정론·입력 ID 계약·능력치 범위 검증 이후 실제 DetailedMatchEngine 경로의 대량 시뮬레이션으로 AVG, ERA, HR/G, R/G, BB/K, 강약 전력 차이를 확인해야 한다. Cost만 변경하더라도 스카우트 분포·로스터 제약·성장/카드 경제 소비처에 미치는 영향은 별도 검증한다.

- 코드·JSON·기존 연구 자료 정적 검토 완료.
