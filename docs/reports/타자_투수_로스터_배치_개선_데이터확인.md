# 타자·투수 대표 로스터 배치 개선 — 데이터 확인

## 적용 범위

Canonical Core25의 오프라인 배치 로직을 개선하고 1982~2025년 44개 연도 JSON을 재생성했다.
버전은 RosterBuilder `ability-fit-core25-v3`, DerivationBalance `historical-derivation-balance-v10`이다.
BaseAttributes·Cost·TrainingCeiling·Natural Position/Role은 변경하지 않았다.

사용자 요청에 따라 테스트·컴파일·Unity 실행·경기 시뮬레이션은 수행하지 않았다.
회귀 테스트 소스는 추가했으나 실행하지 않았다. 아래 확인은 실제 저장 JSON에 대한 대조다.

## 타자

- 주포지션 +100 / 부포지션 +20을 제거하고 주포지션 0 / 적격 부포지션 -4로 바꿨다.
  포지션 이름만으로 능력치 차이를 압도하지 않는다.
- 수비 8명 확정 후 남은 타자에서 DH를 고르는 대신, 수비 8자리와 DH의 합산 점수를 동시에
  최대화한다. 특정 선수를 수비로 쓰는 경우 잃는 DH 공격력까지 비교한다.
- 수비 근거가 있는 실제 주수비 위치를 인정하고, 부포지션은 5경기 또는 45아웃 이상의 기록을
  요구한다. 무경험 배치는 적격 매칭 불가능 시에만 경고와 함께 fallback한다.
- 벤치는 남은 적격 포수 한 명을 우선 확보한다. 이후 교체 능력치와 아직 확보하지 않은 백업
  수비 포지션당 +6을 합산해 순차 선정한다. 14명 전체의 전역 최적화는 아니다.

## 투수

- 선발 역할 점수(선발 등판 비율·이닝 지표)를 전력 가산점으로 사용하지 않는다.
  Natural Starter 자격을 충족한 후보끼리는 선발용 능력치 가중평균으로 5명을 선정한다.
- 전문 마무리·셋업 후보는 각각 확보한다. 이 두 보직을 모든 투수와 무제한 경쟁시키는 정책은 아니다.
- 일반 불펜은 남은 선발·셋업·마무리까지 포함한 잔여 투수 전체에서 구원용 능력치로 선정한다.
  선발에서 탈락했다는 이유로 대표 로스터 후보에서도 자동 제외하지 않는다.
- Cost는 선발·타자 배치의 직접 입력이 아니다. 보직·포지션별 실제 능력치 조합을 비교한다.
- 원본 역할은 보존하고 Assigned Role만 변경한다. 동점은 Stable ID로 결정하도록 구현했다.
  입력 순서 변경에 대한 별도 결정론 테스트는 이번에 실행하지 않았다.

| 일반 불펜 | 전유수·문승원·김준·신정익 | 박정배·엄정욱·최영필·이재영 |

| 벤치 | 안치용·박재홍·김성현·조인성·최윤석 | 조인성·임훈·김성현·안치용·최윤석 |

채병용은 선발용 능력치 47.30으로 로페즈 43.90보다 높다. 기존 역할 점수의 80 대 98 차이가
배치 점수에 가산되지 않아 선발에 포함된다. 선발 순서는 능력치 순위이며 요청한 다섯 명과 일치한다.

박재홍은 시즌 주역할이 DH로 추론되지만 실제 우익수 29경기·584아웃 기록이 있어 우익수 적격이다.
이호준을 DH로 유지하면서 박재홍을 우익수로 쓰는 배치를 선택했다. 백업 포수는 조인성이다.
이는 원본 Natural Position을 변경하거나 Runtime 복수 포지션 모델을 새로 추가한 것이 아니다.

### 남아 있는 원본 제약

- 백업 포수 적격 근거가 없는 139개 구단 시즌에는 경고를 남겼다.
- Source 수비 OffPosition fallback은 기존·변경 모두 1,112슬롯이다. 원본 수비 기록 부족을
  이번 변경으로 복원했다고 주장하지 않는다.
- Source 투수 역할 fallback 경고는 211→216슬롯이다. 선발·전문 보직 확보 순서와 일반 불펜
  후보 정책이 달라졌기 때문이며 원본 총원 부족 3개 시즌은 그대로다. 실제 Runtime 정원 위반은 없다.
- 수비 적합성 감점·벤치 보완 가중치가 실제 경기 수비와 교체 가치에 맞는지, 원래 선발인 투수의
  불펜 활용이 Runtime 보직 페널티·피로와 어떻게 상호작용하는지는 별도 경기 검증이 필요하다.
- 이번 변경은 대표 로스터 생성이다. 실제 경기의 타순 최적화·감독 AI 교체 전략·구단 경제는 수정하지 않았다.

## 반영 및 확인

Editor 원본 Archive와 그 Runtime 복사본, 실제 Catalog가 참조하는
`Assets/10.Datas/HistoricalSimulation/1982-2025/`에 모두 반영했다.
이전 JSON은 `.tmp/roster-before-v3/Editor/`, `.tmp/roster-before-v3/Runtime/`에 보존했다.
기존 .meta와 Catalog GUID는 변경하지 않았고 파일 삭제는 없다.

재생성 후 Archive 검증 및 반영 후 기존 Archive 로더의 파일 해시·스키마·연결 확인을 완료했다.
`git diff --check`의 공백 오류는 없었다. 이는 Unity 컴파일이나 테스트 통과를 의미하지 않는다.

`ab801107938f19d3fb598e5582a4a5e277fcc7b194ec051e5d11fd9c5129fb05`

기존 Hash를 참조하는 WorldHistory/캐시가 있다면 별도 재생성이 필요하다.
기존 Save의 이어하기 호환성은 확인하지 않았다. 생성 JSON은 Git ignore 대상이므로 다른 환경에서는
동일 입력으로 재Bake하고 Runtime 경로를 동기화해야 한다.
