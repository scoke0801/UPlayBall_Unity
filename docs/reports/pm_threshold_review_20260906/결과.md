# 수비·투수 기사 정밀 검토와 평가 개선

**Ability v8 / Cost v11 / DerivationBalance v14**를 실제 데이터에 반영했다.
이번 비교의 변경 전 기준은 앞선 작업의 v7/v10/v13이다. 선수별 정답표를 게임에 넣지 않고
공통 기록 평가의 기준점·변환 폭을 보정했다. 역사 캐시 Bake는 수행하지 않았다.

## 원문에서 추가로 복원한 자료

[수비 기사, 2010-10-06](https://m.inven.co.kr/webzine/wznews.php?idx=86864&site=bm)의
HTML에는 텍스트 추출에서 빠졌던 등급 아이콘, 카드 판본 CSS, 선수 DB ID가 남아 있었다.
이를 복원하니 **593행: Normal 400·All Star 185·EX 7·Rare 1**이었다.
기존 엑셀의 수비 82행은 전체 원문 중 일부다. 원문은 B 이상 수비 선수를 대상으로 하므로
전체 야수 모집단의 빈도 분포로 사용할 수는 없다.

[투수 기사, 2010-10-20](https://www.inven.co.kr/webzine/news/?news=86866&site=bm)에는
9/10 Cost 외에 변화구가 낮은 추가 선발 목록도 있다. 전체를 읽으면 **52장의 앞뒷면 카드 링크와
구종별 목표 등급 445건**이 나온다. 이는 같은 구종의 1·2단계 목표를 별도 행으로 센 수치로,
기존 엑셀의 구종 136행과 집계 단위가 다르다. 같은 시즌의 카드 판본 간 변화구 값이 같다는
기사 설명을 구속·제구 등 다른 능력치까지 일반화하지 않았다.

일반 야수 400장과 투수 52장, 총 **452장의 앞면 6능력치**를 읽었다.
투수 52장은 표시 숫자를 직접 전사했다. 카드의 흰 막대가 1점당 1픽셀임을 이용한 판독기가
그 312개 숫자와 전부 일치했으며, 야수 카드도 고정 해시로 표집한 20장의 숫자·이름을 시각 확인했다.
각 막대의 세 주사선 길이가 같을 때만 받아들이도록 했고 야수 400장 모두 통과했다.
이는 야수 400장을 모두 사람이 숫자별로 전사했다는 뜻은 아니다.

원문과 이미지 URL, 원본 HTML SHA256, 판독 이미지 SHA256을 보존했다.
**현재 연결된 이미지가 2010년 게시 당시와 같은 바이트였다는 증거는 없다.** 기사 시점과 이미지
관측을 구분하며, 원작 최종판·재평가 전후를 확정한 자료로 간주하지 않는다.

## `+N`의 의미를 다시 확인한 결과

수비 일반 카드에서 일대일 비교 가능한 연속 목표 303쌍, 투수의 연속 목표 209쌍은 모두
추가 필요치가 10 차이였다. 그러나 이것이 기본 Defense/Breaking의 공통 등급 경계는 아니다.

| 카드 | 표시 수비 | A까지 추가 | A 도달 시 합 |
|---|---:|---:|---:|
| 08 최정 | 75 | 1 | 76 |
| 08 박재홍 | 76 | 5 | 81 |

전체 관측에서 `표시 수비 + A까지 필요치`는 68~87, S는 78~97로 달랐다.
투수도 같은 목표 등급의 `표시 변화구 + 필요치`가 구종·선수에 따라 달랐다.
따라서 `기본 수비 = 80 - 필요치` 같은 역산을 적용하지 않았다. 기사와 이미지 시점 차이도 가능한
교란 요인이므로 이 값만으로 숨은 적성의 정확한 공식까지 복원했다고 주장하지 않는다.
정밀 집계는 [threshold_audit.json](threshold_audit.json)에 있다.

원작 야수의 네 번째 능력은 **번트**다. 판독 자료에 보존하되 현 프로젝트의 Arm 평가에는 넣지 않았다.
원작의 구종별 등급을 현재 Synthetic Arsenal의 기본 숙련도로 직접 대입하지도 않았다.
이번 범위는 Cost·기록 기반 능력치 보정이다.

## 연결과 후보 선택

452장 중 연도·표시 이름·유형이 현재 Source에서 유일한 **438장(야수 388·투수 50)**을 연결했다.
동명이인 또는 개명 등으로 14장을 연결하지 못했다. 유사 이름이나 같은 연도만으로 강제 매칭하지
않고 [expanded_study.json](expanded_study.json)의 rejected에 남겼다.

같은 인물의 여러 시즌이 학습·검증에 섞이지 않도록 `playerPersonId`의 고정 해시로 분할했다.
학습 295장, Validation 88장, Holdout 55장이다. 야수는 257/85/46장, 투수는 38/3/9장이다.
투수 Validation이 3장뿐인 점은 큰 한계다. Holdout 결과도 함께 공개하며, 같은 기사에서 나온
표본이라는 출처 편향까지 제거된 독립 외부 검증으로 해석하지 않는다.

지표 조합은 v7 그대로 유지했다. 후보는 기준점 55~79(2점 간격 및 기존 값), 변환 폭
8/12/16/20/24 및 기존 값만 비교했다. 학습 MAE에 기존 설정으로부터의 이동량당 0.04의 벌점을
더했다. 아래는 실제 재Bake 후의 값이며, 후보의 예상값만 보고 채택한 결과가 아니다.

| 능력 | 기준점 / 변환 폭 | 표본 | 전체 MAE 이전→이후 | Holdout MAE 이전→이후 |
|---|---:|---:|---:|---:|
| 교타 | 67 / 16 | 388 | 14.482 → **2.528** | 14.413 → 2.522 |
| 장타 | 67 / 16 | 388 | 13.974 → **4.010** | 15.261 → 4.022 |
| 주력 | 69 / 12 | 388 | 6.879 → **4.278** | 7.087 → 4.978 |
| 수비 | 73 / 8 | 388 | 18.101 → **5.454** | 18.587 → 5.348 |
| 타자 정신 | 65 / 8 | 388 | 9.255 → **6.577** | 8.935 → 6.435 |
| 구위 | 69 / 24 | 50 | 13.160 → **5.080** | 13.778 → 5.556 |
| 변화구 | 71 / 20 | 50 | 15.160 → **4.320** | 16.222 → 4.000 |
| 제구 | 77 / 8 | 50 | 14.160 → **3.740** | 11.778 → 4.889 |
| 투수 정신 | 67 / 20 | 50 | 11.320 → **2.640** | 11.111 → 4.222 |

각 능력치는 기존 신뢰도 보정 Z에 대해 `round(기준점 + 변환 폭 × Z)`를 적용하고 25~100으로
제한한다. 근거가 전부 결측이면 기준점과 관계없이 55다. 단순한 전원 능력치 상승이 아니라
원작보다 크게 벌어져 있던 차이를 줄인 조정이다. 이름·팀·특정 시즌으로 분기하지 않는다.

체력과 실측 구속의 기존 절대 기준은 유지했다. 새 50장에서도 체력 MAE 24.280,
구속 11.380은 남는다. 이 둘까지 원작 카드 숫자와 맞췄다고 할 수 없다.
또한 기존 엑셀의 Normal 소표본에서는 타자 정신 MAE가 **5.500→7.250으로 악화**됐고,
구위는 10.750으로 그대로다. 개선된 항목만 골라 전체 일치를 주장하지 않았다.
나머지 기존 표본의 결과는 [이전 참조 비교](previous_reference/bake_comparison.json)에 있다.

## Cost 변경과 한계

기준점을 이동하는 단순 Cost 후보는 채택하지 않았다. 새 야수 표본만 보면 -1.0이 유리하지만,
이전 연구에서는 야수 하향이 다른 시점 자료를 악화시켰다. 새 투수 표본의 +0.75 후보도
Holdout MAE를 1.333→1.444로 악화시켰다. 서로 다른 시점 자료를 하나의 확정 가격표로 취급하지 않는다.

대신 **수비 가격이 표시 Defense/Arm에 의존하던 문제를 수정**했다. 표시 수비를 원작 척도에 맞추면
원기록은 같은데 Cost의 수비 가산까지 오르는 구조였다. v11은 가격 전용 원기록 근거에서 계산한다.
수비율·실책 그룹 가중치 0.525, 보살·도루저지 그룹 가중치 0.125는 이전 식의
`14 × 0.75 / 20`, `10 × 0.25 / 20`에 해당한다. 그룹 안에서는 가용 지표 가중치를 재정규화하며,
근거가 없는 그룹 기여는 0이다. 합산 신호를 -1~1로 제한한 뒤 기존 출전량·최대 가산을 적용한다.
원기록 Z를 직접 사용하므로 표시 능력치의 중간 반올림과 제한에 가격이 종속되지 않는다.

| Cost 비교 집합 | 건수 | MAE 이전→이후 |
|---|---:|---:|
| 새 연결 카드 | 438 | 1.034 → **1.032** |
| 기존 2011 관측 | 491 | 0.996 → **0.996** |
| 기존 엑셀 2011 기사 | 104 | 0.510 → **0.510** |
| 기존 엑셀 2013 투수 기사 | 62 | 1.032 → **1.032** |

Source 17,333개 중 Cost 변경은 야수 20개다. 투수 기본점·품질·출전량·elite 자격은 유지했다.
이번 작업의 큰 개선은 능력치 정합성이고, Cost 정확도가 크게 좋아졌다고 보고하지 않는다.
다음 Cost 보정에는 스냅샷 충돌 해소와 저Cost·낮은 수비등급 자료의 확장이 필요하다.

## 반영 및 검증

- 1982~2025 Source 17,333개와 Replacement 54개를 재생성했다. 다른 Seed로 생성한 JSON
  93개가 모두 바이트 단위로 일치했다. Editor 93개와 Runtime 46개를 복사 후 다시 비교했다.
- 원기록·기사·카드 이름을 Production 산식에 넣지 않는다. `costMetricEvidence`는 Editor 전용이며
  Runtime에서 제거된다. 원본 엑셀은 수정하지 않았다. WorldHistory 캐시는 사용자가 별도로 Bake한다.
- Importer 전체 테스트 **88/88** 통과. 판본·목표 등급 파싱, 카드 앞뒷면 누락 거부, 선수 단위 분할,
  결측 중립값, 수비 표시 척도와 가격의 독립성, 잘못된 가격 가중치 거부를 확인했다.
- 최신 소스 빌드는 별도 변경 중인 `TeamColorDefinitions.cs`의 미정의
  `CreateReferenceInspiredProfiles` 및 `_baseAttributes` 초기화 오류로 실패했다. 관련 코드를
  임의 수정하지 않았다. 이번에 Unity Test Runner/Play Mode를 실행하지 않았다.
- 아래 경기 비교는 **이전에 빌드한 동일 러너**에 전후 데이터를 넣은 결과다. 최신 소스 전체가
  컴파일·통과했다는 의미가 아니다. 사용한 DLL 해시는 [여기](simulation_runner_hashes.json)에 보존했다.

DetailedMatchEngine에서 전후 각각 10,000경기를 실행했다. 연도 균등 표집·고정 Seed·
각 Bake의 Core25·매 경기 피로 초기화·우투우타·중립 전술·팀컬러 없음 조건이다.
각 실행의 44개 연도에서 이벤트 결정론 비교도 통과했다. 커리어 전체 시즌·스카우트 경제·
원작 경기 통계의 재현 합격과는 구분한다.

| 지표 | v7 기준 | v8 반영 |
|---|---:|---:|
| 타율 | .273 | .272 |
| ERA | 3.496 | 3.330 |
| 구단 경기당 득점 | 3.616 | 3.434 |
| 구단 경기당 홈런 | .624 | .682 |
| BB/K | .504 | .464 |
| 구단 경기당 도루 | 1.167 | .807 |
| 사구 비율 | .93% | .53% |

주력 변환 폭을 줄이면서 앞선 보정에서 늘었던 도루가 감소했다. 제구 척도 변화와 함께 볼넷·사구도
줄었다. 이 영향은 공개하되 원작의 경기 성적까지 재현했다고 결론 내리지 않는다.
전체 지표는 [변경 전](simulation_before.txt)·[변경 후](simulation_after.txt)에 있다.
