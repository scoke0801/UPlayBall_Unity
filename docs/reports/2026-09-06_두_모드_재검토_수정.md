## 1. 전술 카드와 경기 진행

`ManagerModeMatchService.PlayNextGame`은 AI 경기·선수 상태·재무·일정·통계를 변경하기 전에
`TacticCollectionState.CanConsume`으로 전체 슬롯의 보유량을 확인한다. 프리셋 검증의 허용
목록도 전술 정의 전체가 아니라 등록된 정의와 실제 보유 카드의 교집합을 사용한다.

`TryConsumeAll`은 중복 지정 수량을 포함한 전체 수량을 먼저 검사하고 모두 충분할 때만
차감한다. 앞 슬롯만 소모된 채 뒷 슬롯에서 거절되는 경로를 없앴다. 경기 후 장착 해제는
`ManagerModeRuntimeState.ClearSelectedTactics`를 경기 서비스가 호출하며 Unity Manager의
중복 처리는 제거했다. 다음 경기에는 사용자가 다시 전술을 지정해야 한다.

SaveVersion 증가에 따라 초기 카드가 다시 지급되던 Load 조건도 함께 제한했다.
전술 수집 도입 전인 v1~v4에만 초기 전술을 보충하며 v5 이상은 저장된 수량을 그대로 따른다.

## 2. 완료 시즌 기록과 저장

`ManagerModeRuntimeState.CompletedSeasons`는 완료 시즌의 당시 리그 등급과
`ManagerLiveSeasonState`를 보관한다. 일정, 경기 Seed, 점수, 선수 누적은 이전 시즌에 남기고
새 시즌만 빈 기록으로 시작한다. 플레이어 경기뿐 아니라 모든 AI 경기의 완료를 시즌 마감
조건으로 삼아 마지막 휴식 라운드의 미완료 대진을 잃지 않게 했다.

구단주 SaveVersion은 9에서 10으로 올렸다. 완료 시즌 배열을 저장하고 로드시 시즌 번호
중복·역전, 기준 연도와 참가 구단 불일치, 미완료 대진을 거부한다. v1~v9는 완료 이력이
저장되지 않았으므로 빈 이력으로 이행한다. 이미 잃어버린 기록은 복원했다고 가장하지 않는다.
현재 시즌의 통계와 기존 저장 필드는 기존 매핑으로 복원한다.

`OwnerSeasonRecordsService`에 시즌 번호 조회를 추가하고 기존 기록 화면에 이전/다음 시즌
선택을 연결했다. 과거 시즌의 리더보드는 당시 일정의 경기 수와 당시 리그 등급을 사용한다.
새 게임 생성 당시 `WorldHistory`와 운영 중 완료 시즌의 구분도 유지한다.

## 3. AI 은퇴와 승격

기존 순서는 상위 리그 은퇴 → 하위 리그에서 승격 → 그 하위 리그 은퇴였다.
먼저 승격한 선수는 상위 리그에서도 원래 하위 리그에서도 은퇴 평가를 받지 않는 문제가 있었다.

현재는 모든 AI 선수의 은퇴를 먼저 확정한 뒤 생긴 공석을 처리한다. 구단 승강 배치로 소속이
바뀌는 상황에서도 직전 출전·순위는 `player.CurrentLeagueId`의 시즌에서 읽는다.
아래 리그부터 정원을 복원하고 승격으로 발생한 공석을 Rookie까지 내려 보내므로 대규모 은퇴에도
이미 비어 있는 하위 후보군에서 선수를 찾다가 실패하는 경로를 피한다. 신인 생성은 Rookie에서만 한다.
선수별 Seed, 능력치·은퇴 확률 계수와 연령 기준은 변경하지 않았다. 실행 순서 수정으로 시즌 결과는
이전 버전과 달라질 수 있으며, 변경 후 통계·결정론은 이번 작업에서 실행 검증하지 않았다.

## 검증 범위 및 별도 문제

- 테스트·대량 시뮬레이션은 실행하지 않았고 테스트 코드는 변경하지 않았다.
- 기존 Owner E2E fixture는 전술을 보유하지 않고 장착하거나 플레이어 경기만 완료시키는 입력을
  사용한다. 재실행 시에는 실제 보유·경기별 재장착·AI 대진 완료라는 현재 계약에 맞춰야 한다.
  NewsFactKey/스킬 블록/SeasonId 중복에 대한 과거 기대값도 위 판정과 구분해서 읽어야 한다.
- 변경한 소스의 호출부·타입·저장 버전 분기를 읽어 점검했고 해당 변경 범위의 diff 공백 오류는 없다.
- 컴파일만 시도했다. 전체 성공을 확인하지는 못했다.
  - Unity 생성 프로젝트는 새 팀컬러 정의 파일들이 현재 csproj에 누락되어 CS0246/CS0234로 중단됐다.
  - 실제 소스를 직접 포함하는 Headless Game 컴파일은
    `Assets/02.Scripts/Core/Historical/TeamColorDefinitions.cs:84`의 CS0171에서 중단됐다.
    `TeamColorRosterCard` 생성자가 `baseAttributes == null`일 때 readonly `_baseAttributes`를
    할당하지 않는다. 현재 C# 9 프로젝트에서는 모든 정상 반환 경로의 필드 초기화가 필요하다.
    별도로 진행 중인 팀컬러 변경이므로 해당 파일은 수정하지 않았다.
- 원시 컴파일 로그는 `.tmp/mode-fix-compile.log`와 `.tmp/mode-fix-headless-compile.log`다.

판정은 **요청 범위의 유효한 결함 3건에 대한 코드 수정 완료, 실행 테스트 미실시, 전체 컴파일 미확정**이다.
