# 한시 잔여 작업 S1~S6 구현 보고

기준 문서: `docs/todo/00_작업명세_지침_한시.md`

판정 어휘는 기준 문서 §4를 따른다. 사용자가 UI 화면 검증과 시뮬레이션 테스트를 직접 진행하기로 했으므로,
이번 작업에서 테스트가 생략된 항목은 **완료**가 아니라 **코드 연결**로 기록한다.

## S1. Scout·카드 강화·판매

### 대상 모드
구단주.

### 소비자 경로 (필수)
`OwnerModeShellCoordinator.HandleShopPurchaseRequested` → `OwnerModeManager.PurchaseShopProduct`
→ `OwnerShopComposer.Create` → `ShopService.Purchase` → Player/Tactic fulfillment
→ `ManagerHistoricalRuntimeState.AcquireCard` 또는 `TacticCollectionState.Acquire`.

강화·판매는 `UI_Scene_OwnerCollection` → `OwnerExpansionWorkspaceCoordinator`
→ `OwnerModeShellCoordinator` → `OwnerModeManager` → `ManagerModeCoordinator`
→ `CardEnhancementResolver`/`CardSaleResolver` → `OwnedPlayerCardState`/`ManagerEconomyState`로 이어진다.

### 콘텐츠 수량
상점 상품은 `ShopDefaultCatalog`의 선수 카드팩·스킬 블록팩·전술 연구 상품을 사용한다. 별도 임시 상품은 없다.

### 선행 설계 결정
상점 구매 횟수와 전술 보유 수량은 화면 로컬 상태가 아니라 구단주 Save Aggregate가 소유한다.
강화는 중복 한 장, 판매는 중복 한 장을 기본 명령 단위로 삼는다.

### 완료 게이트
Production 소비자와 저장 경로, Scout 첫 진입/신규 카드 Fact 생산자를 연결했다. UI 및 실제 구매 실행 검증은 미실행이다.

### 검증 근거
`Baseball.Core`, `Baseball.Simulation`, `Baseball.Game`, `Baseball.Game.Unity`, `Baseball.Presentation`
컴파일 성공. 사용자 지시에 따라 UI·시뮬레이션 테스트는 실행하지 않았다.

### 제거/정리 대상
`OwnerModeShellCoordinator`의 화면 로컬 `ShopPurchaseHistoryState`와 `TacticCollectionState`를 제거했다.

판정: **코드 연결**.

## S2. 작전카드 44장·연구·TacticLab·AI

### 대상 모드
구단주.

### 소비자 경로 (필수)
전술 연구는 S1 상점 경로 → `TacticResearchRoller` → `TacticCollectionState`로 이어진다.
`FacilityType.TacticLab` → `ClubFacilityEffectProfile.TacticResearchEfficiencyModifier`
→ `OwnerShopComposer` → `ShopDefaultPools.CreateTacticResearchPools`가 연구 등급 가중치를 조정한다.

경기는 `ManagerModeMatchService.PlayNextGame` → `TacticLoadoutState.ConfirmGame`
→ `DetailedMatchEngine`의 `TacticCardResolver`로 이어지며, 확정 뒤 보유 카드 한 장을 소비한다.
AI 구단은 `AiTacticSelectionResolver`가 `LeagueGrade + GameSeed + TeamId`로 두 장을 결정론적으로 고른다.

### 콘텐츠 수량
`Assets/10.Datas/Resources/NewGame/NewGameDefinition.asset`에 Normal~Signature 44장을 저작했다.
구성은 타자 16장, 투수 16장, 분석 6장, 공용 6장이다. 기존
`CompleteGame ↔ ToughAtBat`, `AllBullpen ↔ BullpenCrack` 조합과 함께
`야수 작전 무효`, `투수 작전 무효`가 명시된 핵심 카드 ID를 실제로 Counter한다.
레퍼런스의 순위·연령·직전 타석처럼 현재 `TacticGameState`에 없는 조건은 카드별 특수 코드를 만들지 않고
이닝·점수 차·타순·주자·투수 역할 조건으로 보수적으로 치환했다.

### 선행 설계 결정
Signature는 연구 풀에서 제외하고, 플레이어 구단이 3연패를 직접 끊었을 때
`OWNER-TACTIC-BREAK-LOSING-STREAK`를 업적 보상으로 한 번 지급한다.
AI는 Signature를 사용하지 않으며 상위 리그일수록 선택 가능한 최고 Tier가 높아진다.

### 완료 게이트
44장 콘텐츠, 연구/Inventory 저장, TacticLab 소비자, 경기 소비, Signature 해금, AI 선택 경로를 연결했다.
상점 연구는 보유 카드 목록이 아니라 전체 카탈로그를 소비하도록 분리해 미보유 카드도 획득할 수 있다.
경기 선택 후보에는 보유 수량을 표시하고 경기 종료 뒤 사용한 카드는 수량에서 한 장씩 사라진다.
확률·경기 영향의 대량 통계 검증은 미실행이다.

### 검증 근거
관련 5개 Assembly 컴파일 성공. 사용자 지시에 따라 결정론·통계·경기 시뮬레이션 테스트는 실행하지 않았다.
TacticLab 가중치 변화는 대량 통계 근거가 없으므로 밸런스 확정값으로 간주하지 않는다.

### 제거/정리 대상
전술 2장 고정 검증을 44장 Catalog 최소 검증으로 교체했다.

판정: **코드 연결**.

## S3. 승강·다음 시즌 로스터 이월

### 대상 모드
구단주. 선수 커리어의 다중 리그 승강과는 별도 Aggregate다.

### 소비자 경로 (필수)
시즌 종료 UI → `OwnerModeManager.AdvanceSeason` → `ManagerModeCoordinator.AdvanceSeason`
→ 시즌 승패 집계 → `LeaguePromotionResolver.ResolveNextGrade`
→ `ManagerHistoricalRuntimeState.MoveLeagueTo` → 기존 `CurrentRosterState`를 유지한
`ManagerModeRuntimeFactory.CreateNextSeason` 적용.

### 콘텐츠 수량
`Assets/10.Datas/Resources/NewGame/OwnerExpansionBalance.json` schema v2에
Rookie~Galaxy 10단계 전부의 승강 규칙을 둔다. 80경기 시즌에서 최소 40경기,
승률 60% 이상 승격·40% 이하 강등이며 양 끝 등급은 바깥 이동이 없다.

### 선행 설계 결정
구단 단위 승강으로 정의하고 참가 구단·선수 카드·로스터 객체는 그대로 이월한다.
새 시즌에는 상품별 구매 한도만 초기화하고 전체 구매 순번은 결정론 Seed를 위해 유지한다.

### 완료 게이트
시즌 종료 트랜잭션에 등급 판정·등급 교체·로스터 이월·구매 한도 초기화를 연결했다.
다년 시즌 실제 실행 검증은 미실행이다.

### 검증 근거
Core/Simulation/Game 컴파일 성공. 사용자 지시에 따라 시즌 시뮬레이션과 회귀 테스트는 실행하지 않았다.

### 제거/정리 대상
소비자 없이 존재하던 `LeaguePromotionResolver` 상태를 해소했다.

판정: **코드 연결**.

## S4. 부상/컨디션 이중 트랙

### 대상 모드
선수 커리어와 구단주 공통.

### 소비자 경로 (필수)
현행 컨디션은 `TeamSeasonPlayerStatusState.StoredBaseCondition` → 궁합 Resolver
→ `EffectiveMatchCondition` → `ManagerModeMatchService.BuildTeam`
→ `DetailedMatchEngine` 능력 보정으로 이어진다. 주간 회복은 `ManagerModeCoordinator.AdvanceWeek`가 담당한다.

### 콘텐츠 수량
0~100 단일 원본에서 파생되는 10단계 표시 Band를 사용한다.

### 선행 설계 결정
사용자 승인에 따라 기간 결장은 완전히 제거하고, 기존 출장 소모·주간 회복 곡선을 유지한다.
0~100 Condition을 단일 원본으로 두며 10단계 표시는 `ConditionPresentationTable`이 파생한다.
사용자는 구세이브 호환성보다 현재 구조 정리를 우선하도록 명시했다.

### 완료 게이트
`InjuryResolver`·`InjuryState`·`InjuryBalanceTable`과 부상 이력, 기간 결장 기반 강제 재활,
복귀 역할 보호, 시장·뉴스·은퇴 회고 생산 경로를 제거했다. 훈련 확률 리스크는 기간 결장이 아닌
`GrowthConditionSetbackResult`로 바꿔 0~100 Condition만 차감한다.

### 검증 근거
Core/Simulation/Game/Game.Unity/Presentation 및 관련 Game/Simulation 테스트 어셈블리 컴파일 성공.
UI·시뮬레이션 테스트 실행은 사용자 지시에 따라 생략했다.

### 제거/정리 대상
경기 엔진의 호출자 없는 `PitcherChangeReason.Injury`·`SubstitutionType.InjuryReplacement`와 예약 RNG
슬롯은 경기 이벤트/결정론 계약 변경 범위라 활성 부상 시스템 제거와 분리해 보존했다.

판정: **코드 연결**.

## S5. 상점/뽑기 UI

### 대상 모드
구단주.

### 소비자 경로 (필수)
공용 Shell의 `PowerUpScout` → `OwnerExpansionWorkspaceCoordinator.ShopRouteId`
→ `UI_Scene_Shop` 탭/상품 → S1 구매 Command → `ShopPurchaseResult`
→ `UI_Scene_Shop.ShowReveal` 획득 공개 패널.

### 콘텐츠 수량
선수·스킬·전술 세 탭과 상품별 2열 타일, 신규/중복을 구분하는 결과 공개 패널 한 종을 사용한다.

### 선행 설계 결정
`docs/디자인/ref`의 단순 실루엣 작전카드 문법을 따라 ImageGen으로 타자·투수·공용 3종만 만들었다.
분석 카드는 별도 네 번째 계열을 늘리지 않고 공용 이미지를 사용한다. 상점 타일·획득 공개 패널·경기별
작전 슬롯이 같은 `TacticCardArtwork` 경로를 소비한다. 뽑기 결과는 Simulation에서 다시 Roll하지 않고
확정 결과만 표현한다.

### 완료 게이트
Production 구매와 결과 공개 UI, 3종 ImageGen Asset을 연결했다. 실제 화면 배치·입력 검증은 미실행이다.

### 검증 근거
`Baseball.Presentation` 컴파일 성공. 사용자 지시에 따라 UI 테스트와 Play Mode 검증은 실행하지 않았다.

### 제거/정리 대상
없음.

판정: **코드 연결**.

## S6. 프런트 매니저 첫 진입·반복 상태

### 대상 모드
구단주.

### 소비자 경로 (필수)
새 Runtime 관찰 → `GuideManager.HandleOwnerRuntimeChanged` → `OwnerModeFirstEntry` Fact.
Scout 화면 진입 → `GuideManager.PublishOwnerFact("ScoutFirstEntry")`.
저장은 `OwnerModeManager.Save` → `GuideManager.CaptureRepeatState`
→ `ManagerHistoricalSaveAdapter` v5, 로드는 역방향 `RestoreRepeatState`로 이어진다.

### 콘텐츠 수량
기존 Front Manager Dataset의 `TUTORIAL_OWNER_FIRST_ENTRY`, `TUTORIAL_OWNER_SCOUT_FIRST`,
`SCOUT_NEW_CARD` Cue를 재사용한다.

### 선행 설계 결정
첫 진입은 새 `ManagerHistoricalRuntimeState` 인스턴스를 Guide가 처음 관찰한 순간이다.
Save 범위 반복 상태는 구단주 Aggregate가 소유하며 새 게임에서는 빈 상태로 초기화한다.

### 완료 게이트
Fact 생산자와 Save v5 직렬화·v4 마이그레이션 경로를 연결했다. 실제 Cue 표시·Save 재진입 검증은 미실행이다.

### 검증 근거
Game.Unity/Presentation 컴파일 성공. 사용자 지시에 따라 UI와 Save 실행 테스트는 하지 않았다.

### 제거/정리 대상
호출처가 없던 `CaptureRepeatState`/`RestoreRepeatState` 상태를 해소했다.

판정: **코드 연결**.

## 종합 판정

S1~S6 모두 Production 경로와 컴파일이 연결됐다. 사용자가 직접 수행하기로 한 UI·시뮬레이션 검증이 남았으므로 이 보고는 전체를
**완료**로 과장하지 않는다. 기준 TODO와 하위 TODO는 완료 게이트 통과 전까지 삭제하지 않는다.
