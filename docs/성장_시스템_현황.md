# 성장 시스템 구현 현황

2026-08-30 코드 기준 투영 문서다. 성장 규칙의 정본은
`BaseballManager_CAREER_ECONOMY.md`, 프로젝트 우선순위는 `BaseballManager_PROJECT.md`다.
이 문서는 실제 구현과 검증 상태만 기록한다.

## 1. 현재 결론

성장 시스템은 캐릭터 생성, 자연 성장, 노쇠, 오프시즌 12주 계획, 부상·재활, Skill Board,
감독 역할 평가, 계약 시장까지 연결되어 있다. 이번 안정화에서 다음 정합성 문제를 해소했다.

- 실행 캐릭터 생성 규칙을 `CareerCreationRules` 하나로 통합했다.
- `Base Ability`, `Potential`, `Skill Bonus`, `Peak Bonus`, 경기 보정을 분리했다.
- 출장 0인 선수도 소수점 성장 진행도를 다음 시즌으로 이월한다.
- Rookie~Galaxy 성장 접근을 7개 티어로 확장했다.
- Skill Bonus 중첩 체감과 상한, 리그별 상품 제한, 개막일 보드 스냅샷을 적용했다.
- 경기·역할·계약·UI가 공통 능력치 분해값을 사용할 수 있게 `EffectiveAbilityResolver`를 추가했다.
- 성장·경기 기록에 `SimulationVersionStamp`를 저장하고 시즌 중 버전을 고정한다.

## 2. 캐릭터 생성과 Potential

실행 경로는 다음 하나다.

```text
UI_Scene_NewGame
→ NewGameFlow.SubmitCreationAttributes
→ CareerCreationRules
→ PlayerGrowthFactory
```

규칙은 기본 50, 타자 자유 배분 60, 투수 자유 배분 40, 항목 상한 75다.
`CharacterCreationBalance`와 `AttributeAllocation`은 삭제했다. 기존 테스트용 간편 입력 메서드는
별도 밸런스를 갖지 않고 실제 규칙으로 정규화하는 호환 어댑터다.

초기 Potential은 숨은 RNG 없이 부분 분리 공식을 사용한다.

```text
Potential = min(88, max(BaseAbility + 5,
                66 + round((BaseAbility - 50) × 0.6) + PositionBonus))
```

포지션 핵심 능력은 +3, 보조 능력은 +1이다. 생성 배분이 현재 성능과 미래 상한을 동시에 완전히
독점하던 `Base + 12` 결합을 완화했다.

## 3. 능력치 계층

```text
Base Ability
→ Effective Skill Bonus
→ Peak Bonus
→ Condition / Injury / Tactics
```

`PlayerGrowthState`는 `Base Ability ≤ Potential`을 보장한다. Potential을 넘는 영구 Base는 만들지
않고 능력치별 0~3 `Peak Bonus`로 분리한다. 기존 세이브의 초과분은 유효 능력이 사라지지 않도록
필요한 Potential과 Peak로 마이그레이션한다.

`EffectiveAbilityResolver`의 출력은 다음과 같다.

| 값 | 용도 |
|---|---|
| `RosterAbility` | 계약 안정 전력 |
| `CurrentAbility` | 감독 역할 평가 |
| `MatchAbility` | 실제 경기 판정 |
| `AbilityBreakdown` | 선수·성장 UI와 진단 |

계약은 Peak를 안정 전력에 직접 중복 합산하지 않고 최근 실제 성과로 간접 평가한다.

## 4. 자연 성장과 역할 복귀 기반

자연 성장의 출장 배율은 다음과 같다.

```text
ExposureMultiplier = 0.55 + 0.45 × sqrt(clamp(UsageRatio, 0, 1))
```

- 출장 0에도 팀 훈련 성장 55%가 남는다.
- 높은 출장 구간은 체감 감소하므로 주전의 성장 독점이 완화된다.
- 능력치별 `DevelopmentProgress`를 정수 0~999로 누적하고 1,000마다 Base +1로 전환한다.
- 잔여 진행도는 다음 시즌으로 이월하므로 백업의 작은 성장량이 사라지지 않는다.
- 30세 이하 비주전이 같은 역할군 경쟁자와 8점 이내이면 핵심·보조 능력에 최대 20% 따라잡기
  보정을 받을 수 있다.

`ManagerRoleEvaluator`는 현재 기량, 포지션 적합도, 최근 성과, 컨디션, 신뢰, 성장 전망과 제한된
기존 주전 보정을 합산한다. 결과에는 경쟁자 점수와 개선 권고가 포함된 `DecisionExplanation`이 붙는다.

현재 구현은 개막 전 역할 평가를 지원한다. 정규시즌 20/40경기, 부상 복귀, 장기 활약을 트리거로 한
시즌 중 역할 재평가와 10경기 쿨다운은 아직 완전 연결되지 않았다.

## 5. Rookie~Galaxy 성장 접근

| 리그 | 접근 티어 |
|---|---|
| Rookie | Foundation |
| Minor | Advanced |
| Major | Professional |
| World·AllStar | International |
| Classic·Winners | Elite |
| Champion·Master | Championship |
| Galaxy | Legacy |

상위 티어는 성장 총량만 계속 높이지 않는다. International 이후에는 Potential 기회, Peak,
반복 페널티 관리, 정밀 조정, 노쇠 대응, Trait 쪽으로 가치가 이동한다.

접근 상태는 커리어 최고 도달 리그의 `TrainingKnowledgeTier`와 현재 리그의
`FacilitySupportTier`로 나뉜다. 강등 후에도 학습한 프로그램은 유지하지만 낮은 시설에서는 비용 +25%,
최소 보장 성장 감소, Potential 돌파 배율 감소가 적용된다.

## 6. 오프시즌 12주

기존 주차 겹침, 유학·보드 재설계 횟수, 강제 재활 규칙을 유지한다.

- 훈련 강도는 Safe/Standard/Intensive 데이터 변환 규칙을 사용한다.
- 같은 계통 반복 배율은 100%/90%/75%/60%다.
- 무료 `recovery_break` 2주는 반복 스택 하나를 줄인다.
- 휴식·재활·저강도 기본 선택이 있어 자금 부족이나 12주 재활로 진행이 막히지 않는다.
- 활동 결과는 Seed와 `SimulationVersionStamp`를 저장한다.

프로그램별 예상 성장, 비용, 주당 효율, 컨디션과 위험을 한 화면에서 비교하는 완전한 지배 전략
진단 보고서는 후속 대량 코호트 도구에서 계속 보강해야 한다.

## 7. Skill Board

| 등급 | 블록 기본 보너스 | 최소 구매 리그 |
|---|---:|---|
| Normal | +1 | Rookie |
| Rare | +2 | Minor |
| Elite | +3 | Major |
| Unique | +4 | Classic |
| Legendary | +5 | Champion + 개인 수상 1회 |

같은 능력치 블록은 100%/60%/30%/0%로 적용한다. 능력치 하나의 유효 보너스 상한은 +9,
보드 전체 상한은 +18이다. Raw와 Effective Bonus를 UI에서 분리해 표시한다.

Unique·Legendary는 Trait을 가진다. 현재 실제 경기 경로에 연결된 Trait은 2스트라이크 대응,
득점권 집중, 후반 구위, 위기 관리, 긴 이닝 적응, 적극 주루, 수비 집중이다.

개막일에 `ActiveSkillBoardSnapshot`을 고정하고 경기·역할 평가가 같은 스냅샷을 사용한다.
시즌 중에도 보드를 교체할 수 있다. 편집 자체는 자유롭지만 활성 스냅샷은 확정 명령
(`SkillBoardService.CommitInSeason`)으로만 갱신되며 확정 비용 `InSeasonBoardCommitCost`
(기본 2,000만원)를 받는다. 횟수 제한과 적응 페널티는 없다. 확정 전까지 경기와 역할 평가는
이전 스냅샷을 계속 쓰므로 경기 도중 능력치가 흔들리지 않고, 시즌 중 회수한 블록은
파괴되지 않고 보관함으로 돌아온다. 활성 스냅샷에 남아 있는 블록은 확정 전까지 판매할 수 없다. Unique 이상 뽑기에는 과도한 동일 카테고리 중복을 한 번 재추첨하는 보호가 있다.

## 8. 설명과 재현성

`DecisionExplanation`은 판정 종류, 요약 Reason Code, 가중치와 기여도, 임계값, 추천 행동,
RulesVersion을 가진다. 현재 역할, 자연 성장, 부상 위험, 계약 시장, 은퇴 판정이 이 구조를 반환한다.
Presentation은 한국어 문장을 만들고 Simulation은 Reason Code와 수치만 제공한다.

`SimulationVersionStamp`는 다음 값을 묶는다.

```text
BalanceVersion
EngineVersion
ContentHash
RngAlgorithmVersion
RulesVersion
```

경기 입력, 성장 기록과 시즌 상태에 저장하며 정규시즌 시작 후 해당 시즌의 스탬프를 바꿀 수 없다.
결정론의 정확한 계약은 “같은 Seed + 같은 입력 + 같은 버전 스탬프 = 같은 결과”다.

## 9. 콘텐츠 검증

`GrowthContentValidator`와 통합 `Baseball/툴 런처`의 “성장 콘텐츠 정합성 검증” 도구가 다음을 검사한다.

- 프로그램·블록 ID 중복
- 12주 초과 또는 0주 프로그램
- 선수 유형별 7개 접근 티어의 성장 프로그램 누락
- Potential 프로그램의 도달 불가능한 설정
- 등급별 빈 뽑기 풀, 등급과 보너스 불일치
- Unique 이상 Trait 누락
- 판매가와 구매가의 역전

기본 콘텐츠는 Core 테스트에서 오류 0건을 요구한다.

## 10. 검증 기준선

순수 C# 회귀와 대량 시뮬레이션에서 확인한 현재 기준선은 다음과 같다.

| 항목 | 결과 |
|---|---:|
| Core 회귀 | 10/10 |
| Simulation 회귀 | 140/140 |
| Detailed 경기 10,000경기 AVG/OBP/SLG | .275/.350/.426 |
| 경기당 득점 | 3.79 |
| BB/SO/HR/HBP | 9.2%/17.4%/1.54%/1.10% |
| 강팀 승률 | 73.2% |
| Elite 상한 구간 평균 성장/무성장 | +1.100 / 0건 |
| 5,000커리어×2 전략 Age22 | 개인 51.73 / 유학 52.83 |
| Safe/Standard/Intensive 평균 성장 | 1.381/1.502/1.771 |
| 성장·역할 코호트 백업 2시즌 내 복귀 | 429/444 (96.6%) |
| 성장·역할 코호트 단일 프로그램 최대 선택 | 33.3% |

`MatchSimulator.Simulate`는 `DetailedMatchEngine`에 위임된다. 현재 공개 실행 경로에 별도의 경량
경기 공식이 없으므로 엔진 간 차이 지표를 만들지 않는다. 빠른 고정 매치업과 실제 커리어 경로 모두
같은 엔진의 통계와 민감도를 검증해야 한다.

## 11. 남은 검증·표현 작업

핵심 계산 기반은 구현됐지만 다음 항목은 아직 완료로 보지 않는다.

- 실제 월드 진행을 사용하는 1,000명×20시즌 리그·역할·계약·경제 코호트 정기 실행
- 백업 격차 5 이하의 2시즌 내 주전 복귀율과 부상 복귀율 수치화
- 오프시즌 프로그램 선택 집중도와 포지션·연령별 지배 전략 보고서
- 역할·부상·계약·은퇴 설명의 모든 Presentation 화면 노출
- 성장 계획 3패널, 활동 미리보기, Locked 사유, 게임패드 포커스의 PlayMode 매트릭스
- ScriptableObject 성장 카탈로그 전체 전환과 ContentHash 생성 파이프라인

이 항목은 신규 게임 기능보다 우선하는 안정화 잔여 작업이다.
