# 상점 구단·연도 필터와 구매 지연 수정

구단·연도 선택 시 상품은 정밀 일치 → 단일 조건 일치 → 공통 상품 순서로 표시한다.
같은 단계에서는 카탈로그 순서를 유지해 단품과 10회 묶음을 나란히 배치한다.
전체 선택 시 정밀 조합을 숨기는 기존 정책과 재바인딩 시 필터 보존은 유지한다.

Play Mode의 `Destroy` 대기 중인 이전 탭·필터·상품은 즉시 비활성화해 새 레이아웃에
포함되지 않도록 했다. 목록 갱신 시 스크롤 관성을 멈추고 상위 레이아웃을 확정한 뒤
스크롤 위치를 복원한다.

구매용 상점 생성과 구매 후 재바인딩에서 모든 상품의 공개 확률을 미리 계산하던 경로를
선택 상품의 상세 조회 시 계산하는 방식으로 변경했다. 결과는 상점 서비스 수명 안에서만
캐시하며 구매 가능 여부는 계속 최신 재화와 구매 이력을 읽는다. 추첨 RNG·확률·가격은
변경하지 않았다.

## 검증

- 순수 C# 콘솔에서 Game 상점 NUnit 테스트 23개 통과.
- Presentation, Presentation EditMode/PlayMode 테스트 보조 컴파일 통과(경고·오류 0).
- 10구단 × 40연도 × 25명 = 10,000장, Scout 풀 451개, 상품 913개로 측정한
  확률 상세 준비 시간: 전체 사전 계산 390.378ms, 선택 정밀 상품 조회 0.668ms.
  이 수치는 콘솔 계산 구간이며 Unity 전체 구매 시간이나 실제 저장 월드의 실측이 아니다.
- 전체 상품 913개의 공개 확률·후보 수·설명 일치 확인.
- 정렬·필터 재바인딩 EditMode 검증 및 같은 프레임의 연속 필터 변경·첫행 위치
  PlayMode 회귀 테스트 추가. Unity 배치 에디터는 시작 단계에서 종료 코드 1로 종료해
  UI 테스트 실행과 실제 화면 검증은 미완료.
- 재현 러너: `tmp/shop-filter-validation/Validation.csproj`.

## 별도 확인이 필요한 기존 문제

상세 안내는 Pity 임계치에서 높은 Cost 보장을 설명하지만 `PlayerCardPackFulfillment`는
일반 `ScoutRoller.Roll`과 게이지 증가만 호출한다. Simulation의 `RollFocused`로
이어지는 Game/Presentation 소비자는 확인되지 않았다. 보장 안내와 실제 소비 경로의
불일치는 이번 필터·성능 수정 범위를 벗어나므로 변경하지 않았다.
