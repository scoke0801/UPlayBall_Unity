# 07. 선수 커리어 모드 연동 — 공통 Canonical World와 Career Player Wildcard

## 0. 목적

선수 커리어 모드와 구단주 모드가 같은 Canonical 선수·구단, World Identity, Simulation History를
소비하도록 경계를 정의한다. 플레이어가 직접 생성한 Career Player의 정체성은 Historical 일반 선수의
World Alias와 구분한다.

## 1. 두 모드가 공유하는 것

같은 World Save 안에서는 다음을 공유한다.

- `PlayerPersonDefinition` / `PlayerSeasonDefinition`
- `TeamSeasonDefinition`과 Canonical Core25
- `WorldIdentityRegistry`
- Schedule과 Detailed Match/Season Simulation
- Historical 개인·팀 Statistics, Standings, Postseason
- `WorldHistorySnapshot` / `WorldAwardRecord`
- `WorldCardCatalog`와 Special Composite Team
- Stable ID 기반 Origin, Edition, TeamColor 자격

일반 Historical 선수의 이름을 모드별로 따로 생성하지 않는다. 구단주 모드 화면과 선수 커리어 화면은
동일한 `PlayerPersonId → WorldPlayerIdentity.DisplayName`과
`FranchiseId → WorldFranchiseIdentity.DisplayName`을 조회한다.

## 2. Career Player 주인공

Career Player는 사용자가 입력하거나 캐릭터 생성 규칙으로 만드는 별도 Runtime State다.

```text
CareerPlayerState
  PlayerPersonId 또는 전용 CareerPlayerId
  UserDisplayName
  CurrentAttributes
  Growth / Condition / Contract / Career Statistics
```

사용자가 정한 주인공 이름을 Historical Name Generator로 덮어쓰지 않는다. 반대로 일반 Historical
Player에 주인공 이름 생성 규칙을 적용하지 않는다. 두 종류 모두 경기·기록 참조에는 Stable ID를 쓰며
표시 이름 문자열로 동일 인물 여부를 판정하지 않는다.

Career Player는 새 게임 이후 실제 진행 시즌부터 World 기록에 참여한다. 과거 Historical Simulation,
과거 Award, 과거 특수 합성팀에 소급 삽입하지 않는다.

## 3. World 생성과 Load

정식 Career New Game도 같은 경로를 사용한다.

```text
Canonical Content
→ WorldIdentityRegistry 생성
→ Historical Detailed Match/Season Simulation
→ Statistics / Standings / Postseason / Awards
→ WorldCardCatalog / Special Composite Teams
→ Career Player 생성 및 계약
→ Save
```

`OriginalHistory`는 Legacy/Debug/Validation 전용이며 정식 Career New Game 선택지가 아니다. Production
`HistoricalCareerBakedContentProvider`는 `NewGameDefinition`에 명시된 2016~2025 연도 목록을
LeagueGrade 순서로 소비한다. 목록 누락·중복·10구단 미달이면 명시적으로 실패하며, Synthetic
Player/Team fallback이나 코드가 추론한 임의 최근 연도 배치를 사용하지 않는다.

Load는 저장된 World Identity와 History를 복원한다. Name Generator, Historical Simulation, Award
Resolver를 다시 실행하지 않는다.

## 4. TeamSeason과 감독 AI

모든 일반 구단은 Source TeamSeason 1:1 Canonical 구성과 공통 Roster Rule을 사용한다.

```text
ActiveRoster = 25
Hitter 14 / Pitcher 11
SP 5 / Bullpen 4 / Setup 1 / Closer 1
Foreign <= 3
```

선수 커리어 모드에서 라인업, 선발 로테이션, 교체, 전술, 출전 판단은 감독 AI가 소유한다. 플레이어가
자기 팀 전체 라인업·전술을 직접 편성하게 만들지 않는다. Position/Role/Condition/Ability/계약을
Stable ID 기반 데이터로 판단하며 DisplayName은 UI에만 쓴다.

비주포지션 기용은 하드 금지가 아니지만 `PositionAssignmentRule`의 수비·Condition 패널티를
의사결정과 실제 경기 판정에 반영한다.

## 5. 특수 합성팀

Historical Simulation에는 Canonical 정규 Franchise만 참가한다. Statistics/Standings/Postseason과
Award가 확정된 뒤 AllStar/GoldenGlove/YearSelect 특수 합성팀을 만든다.

- 기존 `PlayerSeasonId`를 참조하며 능력치를 합성하지 않는다.
- 세 특수팀 사이 동일 PlayerSeason 중복을 금지한다.
- 원 Franchise의 Core25/Origin을 변경하거나 선수를 이동시키지 않는다.
- Career Player를 과거 특수팀에 소급 삽입하지 않는다.

## 6. Career Player Wildcard

Wildcard는 Career Player의 성장형 State에 붙는 예외 자격이다. 일반 선수의 Edition과 구분한다.

### 정체성 계열

주인공의 계약·소속·커리어 사건을 바탕으로 특정 Origin/Franchise 계열 TeamColor 자격을 보완할 수
있다. 자격은 Stable `FranchiseId`, `OriginYear`, 명시적인 Wildcard ID로 기록하고 DisplayName을 키로
쓰지 않는다.

### 명예 계열

현재 World에서 실제로 획득한 수상과 커리어 업적을 통해 AllStar/GG/MVP 계열 자격을 얻을 수 있다.
Source Award나 BaseAttributes 순위로 부여하지 않는다. 유효 기간과 해제 조건을 State에 명시한다.

Wildcard는 일반 Historical Card의 `Edition`을 변조하지 않고 Career Player의 TeamColor eligibility
조립 단계에서만 적용한다.

## 7. 구단주 모드 Owned State 비유출

선수 커리어의 일반 구단과 선수에게 다음을 붙이지 않는다.

- `OwnedPlayerCardState`
- SP Scout Pity
- Duplicate Enhancement/Sale
- DP `CardTrainingState`

AI 구단은 Canonical Definition, World Award Edition, 계약·성장 State만 사용한다. 구단주 모드 플레이어
구단의 경제 규칙을 공유 월드 데이터와 혼합하지 않는다.

## 8. 능력치 레이어

일반 구단 선수:

```text
BaseAttributes
+ EditionBonus(WorldAwardRecord)
+ TeamColorBonus
+ Condition/Growth/PositionPenalty
→ EffectiveRating
```

Career Player:

```text
Career CurrentAttributes
+ Wildcard/TeamColorBonus
+ Condition/PositionPenalty
→ EffectiveRating
```

World DisplayName은 어느 계산에도 들어가지 않는다.

## 9. 필수 검증

- 같은 Save의 두 모드에서 동일 Person/Franchise DisplayName 표시
- 같은 Person 다년도 이름 일치와 모드 전환 시 재생성 호출 0회
- Career Player UserDisplayName과 일반 Historical Alias의 생성·저장 경계 분리
- DisplayName만 변경해도 감독 AI 라인업, 출전 판단, Match Event/Statistics 동일
- Career New Game이 정식 Historical Simulation 결과를 사용하고 Source 기록을 복사하지 않음
- Save/Load 전후 Identity, Statistics, Standings, Awards, Career State 동일
- Load에서 Historical/Identity/Award 생성기 호출 0회
- Production Content/배치 정책 부재 시 명시적 실패, Synthetic fallback 0건
- Career Player 과거 History/Award/특수 합성팀 소급 삽입 0건
- AI/일반 선수에 구단주 모드 Owned Economy State 유출 0건
