# 10. 경기 전 상대 분석과 라인업 프리셋

> 상태: 신규 정본 기획안 / Codex 구현 기준

## 0. 목적

06절은 감독의 `ManagerTacticProfile`, 벤치/불펜 판단, 경기당 전술카드 2장을 정의한다. 그러나 플레이어가 **무엇을 근거로 경기 전 라인업과 전술카드를 준비하는지**를 담당하는 정보 계층과 반복 편성 편의 기능이 없다.

이 문서는 다음 루프를 추가한다.

```text
다음 경기 확인
→ 상대 분석 리포트
→ 예상 선발/타선/불펜 상태 확인
→ 라인업 프리셋 선택
→ 필요 시 일부 수정
→ TeamColor 확인
→ 전술카드 2장 선택
→ 경기 확정
```

핵심 원칙:

1. 상대 분석은 **실제 Runtime State와 공개/관측 가능한 기록**에서 만든다.
2. AI의 미공개 결정이나 RNG를 치팅처럼 그대로 노출하지 않는다.
3. 정보에는 신뢰도/불확실성이 존재한다.
4. LineupPreset은 ActiveRoster 25인을 바꾸는 기능이 아니다.
5. 기존 `ActiveRosterCompositionRule`, `PositionAssignmentRule`, `BullpenUsagePolicy`, TeamColor, Tactic 계약을 재사용한다.
6. Presentation은 결과를 표시만 하고 판정하지 않는다.

## 1. 기존 문서와의 연결

### 1.1 02절

프리셋은 현재 등록된 25인 내에서 다음을 구성한다.

```text
주전 9
벤치 운용 순서
선발 로테이션
Bullpen1~4
Setup
Closer
```

비주포지션을 금지하지 않고 기존 Penalty Resolver를 사용한다.

### 1.2 04절

TeamColor 슬롯 2개를 프리셋과 함께 저장할 수 있다.

단 TeamColor의 발동/적용 판정은 기존 Resolver만 수행한다.

### 1.3 06절

경기당 전술카드 2장을 선택하는 PreGame 단계와 연결한다.

OpponentScoutingReport는 전술카드의 Trigger를 자동 충족시키거나 효과를 바꾸지 않는다.

### 1.4 09절

`DataAnalysisCenter`는 리포트의 Confidence만 보조한다.

### 1.5 11절

`ScoutingDirector`가 존재하면 리포트의 정보 품질을 보조할 수 있다.

### 1.6 12절

프리셋 화면에 Base Condition과 Match Effective Condition, Lineup/Battery Chemistry 예상치를 표시한다.

## 3. 정보 생성 원칙

### 3.1 허용 정보

- 현재 일정
- 공개된 ActiveRoster
- 최근 출장 기록
- 최근 선발 로테이션
- 시즌/최근 경기 Statistics
- 최근 불펜 사용량
- 공개된/추정 가능한 감독 성향
- 실제로 과거 경기에서 발동/관측된 전술 패턴

### 3.2 금지 정보

- 상대가 이번 경기용으로 실제 장착한 미공개 전술카드
- 아직 확정하지 않은 실제 선발 라인업 객체 직접 열람
- 미래 RNG 결과
- 숨겨진 AI 선택 점수 전체
- 코드 내부의 정확한 Random Roll

### 3.3 예상 선발

```text
ProbableStarterResolver
input:
  상대 Rotation
  최근 선발 기록
  RestDays
  부상/사용 가능 상태
  일정

output:
  후보 + Confidence
```

실제 감독 AI가 경기 직전 다른 선발을 선택할 수 있다.

### 3.4 예상 라인업

최근 N경기 출전/타순, 상대 선발 손잡이, Condition, ActiveRoster를 기반으로 예측한다.

실제 라인업 결정 Resolver와 동일 객체를 반환하거나 내부 점수를 그대로 노출하지 않는다.

### 3.5 불펜 상태

정확한 내부 Stamina 값을 그대로 표시하기보다 등급화한다.

```text
Fresh
Available
Tired
VeryTired
Unavailable
```

원본 수치는 Simulation에서 유지한다.

### 3.6 감독 성향

`ManagerTacticProfile`의 실제 0~8 값을 무조건 그대로 공개하지 않는다.

최근 경기 행동으로부터:

```text
선발 신뢰 높음
불펜 교체 빠름
도루 적극적
번트 적극적
장타 지향
```

등의 설명형 Estimate를 생성한다.

## 4. 정보 신뢰도

기본 Confidence는 데이터 가용성과 최근성으로 계산한다.

```text
Confidence
 = BaseEvidenceQuality
 × RecencyFactor
 × SampleSizeFactor
 × AnalysisFacilityModifier
 × ScoutingDirectorModifier
```

모든 Modifier는 데이터화하며 1.0 이상의 무제한 배율이 되지 않게 Clamp한다.

`DataAnalysisCenter`와 `ScoutingDirector`가 모두 있다고 해서 `Unknown` 정보를 강제로 `Confirmed`로 만들 수 없다.

## 5. LineupPreset

```text
LineupPreset
{
    PresetId
    Name

    StartingLineupSlots[9]
    BattingOrder[9]
    BenchPriority[5]

    StarterRotationOrder[5]
    BullpenAssignments[4]
    SetupPitcher
    CloserPitcher

    TeamColorSlot0?
    TeamColorSlot1?

    DefaultTacticCardIds[0..2]?
}
```

### 5.1 저장 식별자

현재 코드 계약을 조사한 뒤 가장 안정적인 ID를 사용한다.

권장:

- 구단주 모드 소유 카드 편성은 `CardId`
- Chemistry 연속성은 `PlayerPersonId`

프리셋은 Runtime 인스턴스 메모리 주소나 배열 인덱스를 저장하지 않는다.

### 5.2 ActiveRoster와 분리

```text
ActiveRoster25 = 등록 선수
LineupPreset   = 등록 선수의 경기 운용 방법
```

프리셋 적용 때문에 2군/Collection 선수를 자동 등록하지 않는다.

### 5.3 유효성

프리셋 적용 시:

```text
Valid
PartiallyValid
Invalid
```

예:

- 카드 판매/방출로 선수가 사라짐 → PartiallyValid
- 선발 슬롯 중복 → Invalid
- 비주포지션 → Valid + Warning/Penalty Preview
- 외국인 4명 등록 문제 → 프리셋 문제가 아니라 ActiveRoster Validator 문제

누락 슬롯은 플레이어가 직접 수정하거나 명시적 AutoFill을 선택한다. 조용히 임의 변경하지 않는다.

시스템 기본 템플릿 이름은 UI 편의 기능일 뿐 별도 능력치 효과가 없다.

```text
우완 상대
공격형
수비형
휴식/로테이션
```

사용자는 자유 이름으로 저장/복제/삭제 가능.

최대 슬롯 수는 Balance/UX Config로 관리한다. 초기 구현에서 과도하게 많은 슬롯을 만들 필요는 없다.

## 7. Matchup Preview

프리셋을 적용하면 경기 시작 전 다음을 계산해 표시한다.

```text
Position Assignment Warning
Base Condition / Match Condition
Lineup Chemistry
Battery Chemistry
TeamColor 활성 후보/장착 결과
상대 예상 선발과 좌우 Matchup
불펜 가용성
전술카드 Trigger 관련 참고 정보
```

주의:

- UI용 Preview와 실제 경기 Resolver는 같은 Core 함수를 사용해야 한다.
- Preview 전용 복제 공식을 만들지 않는다.
- Preview와 경기 결과가 달라질 수 있는 부분은 `예상`임을 표시한다.

## 8. 경기 확정 시점

```text
{
    ScheduledGameId
```

## 10. Save/Persistence

Save 대상:

```text
LineupPreset[]
LastSelectedPresetId?
사용자 프리셋 이름
```

OpponentScoutingReport는 원칙적으로 현재 월드 상태에서 재생성 가능한 파생 데이터다.

성능상 캐시할 경우:

- ScheduledGameId
- 생성 시점 버전
- 입력 상태 Hash

를 함께 저장하거나 런타임 캐시로만 둔다.

오래된 리포트를 Save 정본으로 취급하지 않는다.

## 11. 구현 단계

### Stage 0 — Audit

Agent A:
- TeamOverview / MatchPreview / Schedule / RecentGame Statistics 타입 조사.

Agent B:
- Lineup/Rotation/Bullpen/TeamColor/Tactic Loadout 저장 구조 조사.

Agent C:
- 현재 Manager Mode UI 진입/경기 시작 명령 경로 조사.

Gate:
- 재사용 API 및 PreGame Freeze 지점 확정.

### Stage 1 — Scouting Core

Agent Scouting:
- `ScoutedValue<T>`
- OpponentScoutingReport Builder
- ProbableStarterResolver
- ExpectedLineupEstimator
- BullpenReadinessSummary
- ManagerTendencyEstimator

Agent Test:
- 미래 정보 누출 방지 테스트.
- 동일 상태 → 동일 리포트 테스트.

### Stage 2 — Preset Core

Agent Preset:
- Preset Definition/State
- Apply/Validate/AutoFill(optional explicit)
- Stale preset handling

Agent Test:
- 중복/누락/비주포지션/판매된 카드 회귀.

Stage 1과 2는 공통 ID 계약 확정 후 병렬 가능.

### Stage 3 — Matchup Preview

- Condition/Chemistry Preview
- TeamColor Preview
- PositionPenalty Preview
- 상대 예상 선발 Matchup

실제 Resolver 호출을 재사용한다.

### Stage 4 — PreGame Snapshot

- 경기 시작 직전 구성 Freeze.
- Tactic loadout 소모 계약과 연결.
- 경기 엔진 입력 연결.

### Stage 5 — UI

Agent UI:
- UI Toolkit 화면/프리셋 관리/상대 분석 상세.
- 필요 시 ImageGen 아트 생성.

Agent UX Test:
- 정보 부족 상태
- 프리셋 불완전 상태
- 포지션 경고
- 모바일이 아닌 현재 타겟 해상도 기준 레이아웃 회귀

### Stage 6 — AI/Simulation Regression

- 리포트 시스템이 AI 결정을 바꾸지 않는지 기본 회귀.
- 프리셋은 플레이어 입력 편의 기능일 뿐 Simulation 판정을 우회하지 않는지 확인.

### Stage 7 — Final Gate

```text
일정에서 경기 선택
→ 상대 분석 생성
→ 프리셋 적용
→ 경고/TeamColor/Condition/Chemistry Preview
→ 전술카드 선택
→ 경기 시작
→ 실제 Starting Snapshot 일치
→ Save/Load 후 프리셋 보존
```

E2E 통과.

## 13. 완료 기준

- 예상 선발/타선/불펜/감독 성향이 Runtime 기록 기반으로 생성된다.
- 미공개 Tactic Loadout/RNG가 노출되지 않는다.
- 정보에 Confidence가 존재한다.
- DataAnalysisCenter/ScoutingDirector가 Confidence에만 제한적으로 관여한다.
- LineupPreset이 ActiveRoster를 임의 변경하지 않는다.
- 프리셋에서 비주포지션은 허용되고 경고/예상 패널티가 표시된다.
- Preview가 실제 Core Resolver와 같은 계산 경로를 사용한다.
- 경기 시작 Snapshot과 UI에서 확정한 구성이 일치한다.
- Save/Load 후 프리셋이 안정적으로 복원된다.

## 14. 2026-09-05 구현·검증 상태

### Core / Simulation

- `OpponentScoutingReport`, `ScoutedValue<T>`, 5단계 `IntelState`, `LineupPresetState`,
  `PreGamePlanSnapshot`과 Resolver/Validator를 구현했다.
- Intel Confidence 경계와 Facility/Staff modifier는 `OwnerExpansionBalance.json`의
  `scoutingConfidence` 표에서 저작하며, DataAnalysisCenter와 ScoutingDirector를 단일 Context에서
  한 번만 합성한다.
- Report는 공개 ActiveRoster, 최근 workload와 정적 선수 정보만 읽는다. 실제 AI Tactic, 확정되지
  않은 최종 Lineup, Utility/RNG와 숨은 Stamina는 내보내지 않으며 근거가 없으면 Unknown/정보
  부족으로 유지한다.
- 프리셋은 경기 직전 현재 ActiveRoster·availability·수비 위치 1~9·투수 역할·TeamColor 2슬롯·
  Tactic 2슬롯을 재검증한다. 저장된 과거 `IsValid` 값으로 Validator를 우회할 수 없다.

### Runtime / Persistence / UI

- `ManagerPregameService`가 다음 일정에서 예상 선발·타선·불펜 상태와 단일 Intel Context를 만들고,
  `ManagerModeMatchService`가 검증된 Snapshot만 `DetailedMatchEngine`에 전달한다.
- TeamColor 2슬롯은 현재 Production 콘텐츠 ID로 검증한 뒤 같은 경기 Snapshot에 주입된다.
  OffPosition Warning의 비용은 별도 Rating 분기 없이 `EffectiveMatchCondition` 한 경로에서 실제
  경기 효과로 합성된다.
- Save schema 4가 여러 LineupPreset과 선택 ID를 Stable PlayerPersonId로 복원한다. 파생 Report와
  Preview 점수는 저장하지 않는다.
- `UI_Scene_OwnerPregame`은 공용 uGUI Shell에서 Intel Confidence, 예상 선발·타선·불펜, 위협,
  Warning, Condition/Chemistry, TeamColor/Tactic을 표시한다. 선수단 화면은 모든 저장 프리셋을
