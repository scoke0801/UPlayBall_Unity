# 17. 프로야구 매니저 덕아웃 — 감독·수석코치 역기획

> 상태: 역기획 완료 / 실루엣·Save·Simulation·덕아웃 4개 상세 화면 연결 완료 / 테스트 미실행
>
> 조사 기준일: 2026-09-06
>
> 적용 범위: 역사 시뮬레이션 **구단주 모드 전용**. 선수 커리어 모드에서 플레이어가 감독의
> 라인업·교체 판단을 직접 편성하는 기능으로 확장하지 않는다.

## 0. 결론

엔트리브 `프로야구 매니저`의 덕아웃은 다음 세 층을 한 화면에 묶었다.

```text
구단주의 6개 작전 방침
        +
감독 카드의 운영 성향·고유 효과
        +
수석코치 카드의 조건부 컨디션 관리
```

원작의 장점은 카드 한 장이 단순 전력 수치가 아니라 **어떤 야구를 할지**를 빠르게 바꿨다는 점이다.
반면 직접 능력치 보너스, 공개되지 않은 고유 운용, 현실 자정 기준의 소모성 컨디션 카드 때문에
결과의 원인을 설명하기 어렵고 관리 피로가 커졌다.

UPlayBall은 외형과 선택 구조는 계승하되 효과 계약은 다음처럼 바꾼다.

```text
감독       = 경기 운영 판단의 기본 임계값과 허용 조정 범위
수석코치   = 특정 상황에서 감독 판단을 보완하는 조건부 Modifier
전문 코치  = 기존 11절의 훈련·회복·분석 효율 담당
```

- 감독·수석코치는 선수 `BaseStat`을 올리지 않는다.
- 동일한 `Seed + Roster + Manager/HeadCoach Loadout`은 같은 이벤트 스트림을 만든다.
- 모든 영향은 `DecisionTrace`와 경기 후 운영 리포트로 설명한다.
- 감독과 수석코치는 실존 이름·사진을 쓰지 않으며 선수 카드와 같은 익명 실루엣을 사용한다.
- 원작의 현실 시간 만료·1회성 소모 구조는 싱글 플레이 시즌 흐름에 맞지 않으므로 복제하지 않는다.

## 2. 원작 덕아웃 화면 역기획

## 2.1 정보 구조

```text
┌──────────────── 작전 방침 40% ────────────────┬─ Staff 15% ─┬──── Card 45% ────┐
│ 타격방침  단타 ←────────────→ 장타             │ 감독         │ 일반 코치/카드   │
│ 도루시도  소극적 ←──────────→ 적극적           │              │                  │
│ 번트시도  소극적 ←──────────→ 적극적           ├──────────────┤                  │
│ 대타기용  소극적 ←──────────→ 적극적           │ 수석코치     │                  │
│ 선발교체  느리게 ←──────────→ 빠르게           │              │                  │
│ 중간교체  느리게 ←──────────→ 빠르게           │              │                  │
└───────────────────────────────────────────────┴──────────────┴──────────────────┘
```

이 화면의 핵심은 `설정`과 `카드`를 별도 메뉴로 흩뜨리지 않고 같은 비교 공간에 둔 것이다.
플레이어는 방침을 직접 만들거나 감독 카드의 프리셋을 선택하고, 카드 상세에서 어떤 축이 바뀌는지
즉시 확인한다.

## 2.2 6개 방침

위키 정리에 따르면 개편 후 수치는 최소 0, 최대 8이었다. 타격방침은 높을수록 장타 중심이고,
다른 다섯 축은 높을수록 해당 작전 또는 교체 빈도가 높다.

| 축 | 낮은 방향 | 높은 방향 | 의도 |
|---|---|---|---|
| `BattingApproach` | 단타·정확성 | 장타 | 타선의 득점 생산 방식 |
| `StealAggression` | 소극적 | 적극적 | 주력 활용과 도루사 위험 교환 |
| `BuntAggression` | 소극적 | 적극적 | 아웃 하나와 주자 진루 교환 |
| `PinchHitAggression` | 소극적 | 적극적 | 선발 신뢰와 벤치 활용 교환 |
| `StarterHookSpeed` | 느리게 | 빠르게 | 선발 이닝과 실점 위험 교환 |
| `RelieverHookSpeed` | 느리게 | 빠르게 | 불펜 총동원과 소모 위험 교환 |

원작의 좋은 점은 모두 **행동 빈도**로 읽힌다는 것이다. 그러나 타격방침이 실제로 어떤 판정값을
어떻게 바꿨는지, 감독 고유 운용이 별도로 존재했는지는 투명하지 않았다.

## 2.3 감독 카드

### 구조

```text
ManagerCard
  Portrait
  Six Tendencies (0..8)
  Style Name
  Conditional Bonus
```

2011년 개편 후 감독은 무료 선택·영구 사용·자유 교체 방식으로 바뀌었다는 후대 기록이 있다.
카드는 6개 방침 프리셋과 고유 효과를 함께 제공했다. 당시 공개 사례에는 다음과 같은 유형이 있었다.

- 모든 야수 `Bunt` 증가
- Setup/Closer `Control` 증가
- 모든 야수 `Speed` 증가
- 선발 `Stamina` 증가
- 특정 Cost 이하 선수의 모든 능력 증가
- 특정 타순·연령·카드 등급 대상 능력 증가

즉, 원작 감독은 `AI 행동 성향`과 `선수 능력치 버프`를 한 카드에 묶었다.

### 신뢰도

후대 위키는 2014년 개편에서 다음을 기록한다.

- 감독 성향을 제한된 범위에서 조정 가능.
- 같은 감독을 계속 쓰면 신뢰도가 누적.
- 신뢰도 100%에서 감독 효과 변경 가능.

이 구조는 한 감독을 오래 쓰는 애착과 커스터마이징을 만들지만, 신뢰도가 전투력 해금 수단이 되면
새 감독을 시험하는 비용이 지나치게 커질 수 있다.

## 2.4 수석코치 카드

### 최초 확인 구조

```text
Shop Purchase (26,000 PT)
→ HeadCoach Card 1장 장착
→ 조건에 맞는 복수 선수의 Condition 1단계 상승
→ 익일 자정까지 유지
→ 카드 소멸
```

수석코치는 감독처럼 경기 운영 AI를 바꾸기보다 **조건부 집단 컨디션 관리**를 담당했다.
초기 예시는 `6 Cost 선수`, `중심 타선`, `내야수`처럼 로스터 일부를 대상으로 했다.

2011년 기사에서 확인되는 추가 대상 12종은 다음과 같다.

| 수석코치 유형 | 대상 조건 |
|---|---|
| 데이터 선호 | `Contact >= 70` |
| 근육 선호형 | `Power >= 70` |
| 육상 출신 | `Speed >= 70` |
| 작전 중시형 | `Bunt >= 70` |
| 기본 충실형 | `Defense >= 70` |
| 마인드 중시 | `Mental >= 70`, 투수·야수 공통 |
| 체력 강조형 | `Stamina >= 70` |
| 속구 조련형 | `Velocity >= 70` |
| 구위 강조형 | `Stuff >= 70` |
| 구질 조련형 | `Breaking >= 70` |
| 제구 중시형 | `Control >= 70` |
| 연말 단골손님 | GoldenGlove 출신 |

후기에는 Rookie of the Year와 MVP 선수를 대상으로 하는 수석코치도 추가됐다. 이 방식은
“내 로스터에서 이번 카드의 수혜자가 몇 명인가”를 계산하는 조합 재미를 만든다.

### 원작의 경제적 역할

- 반복 PT 소비처.
- 컨디션이 나쁜 선수 집단을 한 번에 복구하는 편의 기능.
- 좋은 선수만 모으는 것 외에 Cost·타순·포지션·능력치 문턱을 기준으로 로스터를 다시 보게 하는 장치.

### 원작의 문제

- 현실 자정 만료는 싱글 플레이 시즌 시간과 무관하다.
- 컨디션 정상화가 사실상 필수라면 선택이 아니라 유지비가 된다.
- 현금 수석코치 팩과 결합되면 승부 결과가 소비 빈도에 종속된다.
- 정확한 컨디션 보정이 보이지 않으면 패배 원인이 카드 부재인지 선수 구성인지 설명하기 어렵다.

## 2.5 일반 코치

2011년 패치 기사는 32세 이상 보유 선수를 PT로 2일간 코치로 기용하고, 선수의 Skill Block 모양과
능력치·나이에 따라 대상과 효과가 달라지는 구조를 설명한다. 보유 선수를 은퇴 전 다른 용도로 쓰게
한다는 점은 흥미롭지만 이번 감독·수석코치 범위에는 넣지 않는다.

현재 UPlayBall의 Hitting/Pitching/Development/Conditioning/Scouting 5개 전문 인력은
[11_코칭스태프_시스템.md](11_코칭스태프_시스템.md)가 소유한다. 덕아웃이 이 기능을 중복 구현하지 않는다.

## 3. 원작이 만든 플레이 경험

## 3.1 강점

### 팀의 강점을 운영 방식으로 번역

강한 선발진과 약한 불펜을 가진 팀은 느린 선발 교체를, 빠른 야수가 많은 팀은 적극 도루를 선택한다.
카드 수집이 곧바로 “어떤 야구를 할 것인가”라는 질문으로 이어진다.

### 프리셋과 수동 설정의 공존

감독 카드는 초보자에게 이해 가능한 프리셋을 주고, 방침 슬라이더는 숙련자에게 세밀한 조정 공간을 준다.

### 조건부 대상 찾기

수석코치가 모든 선수에게 같은 효과를 주지 않아 로스터 화면을 다시 살펴보게 한다.

### 카드에 인격 부여

여섯 축과 스타일 문구가 감독을 단순 +N 버프가 아니라 기억 가능한 운영 캐릭터로 만든다.

## 3.2 약점

### 원인을 감춘 효과

같은 방침 수치인데 교체 양상이 다르다는 체감은 개성을 만들 수 있지만, 패배를 설명할 수 없게 한다.

### 직접 능력치 버프의 지배

운영 성향보다 `Speed +3`, `Stamina +7` 같은 범용 보너스가 선택 기준이 되면 감독 선택은 전술이 아니라
최적 버프 찾기로 축소된다.

### 실시간 소모 압박

익일 자정 소멸은 접속 주기와 소비를 강제한다. 여러 시즌을 자기 속도로 진행하는 UPlayBall에는 맞지 않는다.

### 중첩 시스템의 책임 불명확

감독, 수석코치, 일반 코치, 서포트 카드, 팀컬러가 모두 선수 수치를 바꾸면 결과를 어느 시스템이
만들었는지 알기 어렵다.

## 4. UPlayBall 적용 원칙

## 4.1 역할 분리

| 시스템 | 소유 효과 | 금지 |
|---|---|---|
| 감독 | 경기 운영 판단의 기본 성향, 상황별 고유 판단 규칙 | 선수 `BaseStat` 직접 수정 |
| 수석코치 | 감독 성향의 조건부 보완, 벤치·불펜·주루 등 한 영역의 실행 보정 | Condition 회복, 훈련 효율, 영구 능력치 |
| 전문 코치 5종 | 훈련·회복·분석 효율 | 경기 운영 임계값 소유 |
| TacticCard | 한 경기의 명시적 전술 선택 | 감독 Profile 영구 변경 |
| TeamColor | 로스터 구성 보상 | AI 의사결정 변경 |

수석코치가 원작처럼 Condition을 올리면 기존 `ConditioningCoach`와 충돌한다. 따라서 원작의
“조건부 집단 지원” 패턴만 가져오고 효과 대상은 **경기 판단**으로 바꾼다.

## 4.2 좋은 선택의 조건

- 특정 감독이 항상 상위호환이면 실패다.
- 로스터와 상대에 따라 좋은 감독·수석코치 조합이 달라져야 한다.
- 같은 조합을 오래 쓰는 보상은 선택 폭과 정보 해금이어야지, 숨은 전력 증가여서는 안 된다.
- 플레이어는 경기 후 “왜 선발을 바꿨고 왜 도루를 시도했는지” 확인할 수 있어야 한다.
- 방침은 결과 확률을 직접 덮지 않고 행동 선택 임계값을 바꾼다.

## 5. 제안 시스템

## 5.1 감독: 기본 운영 철학

기존 `ManagerTacticalProfile`의 8개 축을 정본으로 사용하되 덕아웃 6개 UI와 정확히 매핑한다.

| UI 축 | Core Profile | 현재 Consumer | 작업 |
|---|---|---|---|
| 타격방침 | `BattingApproach` 신규 | 없음 | 공통 `HitterDecisionAi`가 생길 때 연결 |
| 도루시도 | `RunningAggression` | `TacticalAiResolver` | 기존 연결 유지 |
| 번트시도 | `SmallBallPreference` | `TacticalAiResolver` | 기존 연결 유지 |
| 대타기용 | `PinchHitAggression` 신규 | 대타 기준 하드코딩 | 기준 Gain/이닝/Leverage에 연결 |
| 선발교체 | `HookSpeed`, `StarTrust` | `PitcherManagementAi` | 기존 연결 유지 |
| 중간교체 | `BullpenAggression`, `BullpenRoleRigidity` | `PitcherManagementAi` | 기존 연결 유지 |

추가 상세 축은 감독 카드 상세에서 보조 정보로 노출한다.

- `MatchupPreference`: 좌우·구종·타구 성향 Matchup 반영 강도.
- `DefensiveAggression`: 수비 교체와 수비 위치 변경의 Gain 기준.
- `StarTrust`: 선발·주전에게 부진을 만회할 기회를 주는 정도.

### 감독 고유 특성

고유 특성은 선수 능력치가 아니라 조건이 공개된 판단 규칙이다.

```text
LateInningPlanner
조건: 7회 이후, 1점 차 이내, Leverage >= High
효과: PinchHit Gain Threshold -10%, MatchupPreference +8
대가: 다음 이닝에 남은 Bench 선택지가 감소할 수 있음
```

```text
StarterGuardian
조건: Starter FatigueRatio < 0.85, RunsAllowed <= 2
효과: PullThreshold +7
대가: 세 번째 타순 순환 위험을 더 오래 감수
```

조건·효과·대가를 카드에 모두 쓴다. 숨은 고유 운용은 만들지 않는다.

## 5.2 수석코치: 조건부 실행 보완

수석코치는 한 경기 Loadout에서 1명만 배치한다. 시즌 계약 인력이며 사용 후 소멸하지 않는다.

```text
HeadCoachDefinition
  HeadCoachId
  FictionalIdentityId
  Archetype
  ContextPredicate
  TacticalModifier
  TradeoffModifier
  DescriptionKey
```

초기 6종은 덕아웃 UI 축과 1:1로 맞춘다.

| Archetype | 발동 조건 | 보완 | 대가 |
|---|---|---|---|
| `ContactPlan` | 상대 선발 Control이 높고 우리 타선 Contact 우세 | 선택적 타격 쪽으로 `BattingApproach` 이동 | 장타 시도 감소 |
| `RunningCoordinator` | 주자 Speed 70 이상, 2사 미만 | `RunningAggression +12` | 도루사 위험 증가 |
| `SmallBallCoordinator` | 7회 이후, 동점 또는 1점 열세 | `SmallBallPreference +12` | 기대 다득점 감소 |
| `BenchCoordinator` | 6회 이후, `Leverage >= Medium` | 대타 Gain Threshold 감소 | Bench 조기 소모 |
| `StarterCoordinator` | 선발이 강하고 Bullpen Freshness가 낮음 | `HookSpeed -10`, `StarTrust +6` | TTO·피로 위험 증가 |
| `BullpenCoordinator` | 7회 이후, `Leverage >= High` | `BullpenAggression +10`, 역할 적합도 가중 | 다음 경기 가용성 감소 |

`70` 같은 문턱과 Modifier 값은 예시다. `OwnerExpansionBalance`에서 저작하고 대량 Simulation으로 확정한다.

## 5.3 신뢰도 재해석

```text
경기 완료
→ 해당 감독 TrustExperience 누적
→ 운영 리포트 상세 항목 해금
→ 허용 조정 범위 확대
→ 대체 고유 특성 선택지 해금
```

신뢰도는 경기 성능을 몰래 올리지 않는다.

| 단계 | 해금 |
|---|---|
| 0 | 기본 Profile과 고유 특성 1개 |
| 25 | 세부 8축·DecisionTrace 통계 공개 |
| 50 | 6개 방침 수동 조정 범위 ±1단계 |
| 75 | 조정 범위 ±2단계 |
| 100 | 고유 특성 후보 중 1개 교체 가능 |

감독을 바꾸면 누적 신뢰도는 감독별로 보존한다. 새 감독 실험이 영구 손실이 되지 않게 한다.

## 5.4 조합 계산 순서

```text
Balance Default
→ Manager Base Profile
→ Trust로 허용된 User Adjustment
→ HeadCoach Context Modifier
→ Club DNA의 작은 장기 성향 Modifier
→ 0..100 Clamp
→ MatchRosterSnapshot에 동결
→ DetailedMatchEngine Consumer
```

TacticCard는 이 Profile을 영구 수정하지 않는다. TacticCard가 같은 행동을 건드릴 경우 별도
`MatchTacticContext`에서 한 경기만 적용하고 `DecisionTrace`에 두 출처를 각각 남긴다.

## 10. 구현 순서

## Stage 0 — 계약 확정

- `ManagerTacticalProfile`에 `BattingApproach`, `PinchHitAggression` 추가 여부 확정.
- 기존 8축과 UI 6축의 변환표를 Balance에 정의.
- `ManagerDefinition`, `HeadCoachDefinition`, `OwnerDugoutState` 확정.

Gate: 선수 `BaseStat`, Condition, Training 효율을 변경하는 필드가 없어야 한다.

## Stage 1 — Content / Persistence

- 가상 Manager 5종, HeadCoach 6종 최소 Catalog.
- Stable ID와 Save migration.
- 감독별 Trust State.
- AI 구단은 계약 경제 없이 결정론적 Archetype을 배정.

Gate: Save/Load 뒤 선택·신뢰도·방침이 동일하다.

## Stage 2 — Match Snapshot

- `ManagerModeMatchService`의 `Balanced` 강제를 제거.
- Player/AI 양 팀의 `MatchManagementSnapshot`을 경기 시작 시 생성.
- HeadCoach Predicate는 경기 중 Context만 읽고 RNG를 새로 만들지 않는다.

Gate: 같은 Seed와 Snapshot의 이벤트 스트림 완전 일치.

## Stage 3 — Consumer 연결

- 도루·번트: 기존 `TacticalAiResolver` 회귀 확인.
- 선발·중간 교체: 기존 `PitcherManagementAi` 회귀 확인.
- 대타·대주자·수비 교체: 고정 Gain Threshold를 Balance + Profile 입력으로 교체.
- Matchup/Defense: 실제 Consumer가 생길 때만 UI 활성.
- 타격방침: 공통 `HitterDecisionAi` 없이 결과 분포에 직접 곱하지 않는다. Consumer 전까지 잠금 또는
  “준비 중”으로 표시한다.

Gate: 화면만 움직이고 소비되지 않는 슬라이더가 없어야 한다.

## Stage 4 — UI Command

- 현재 선택 Empty State를 실제 Catalog ViewModel로 교체.
- 변경 전후 Profile, 발동 조건, 대가, 현재 Lineup 대상 수 표시.
- Confirm에서 Command 실행 후 성공했을 때만 UI 갱신.
- 취소는 Runtime State를 바꾸지 않는다.

## Stage 5 — 설명 가능성

- `DecisionReasonCode` 확장.
- 도루·번트·대타·투수 교체에 `DecisionTrace` 기록.
- 경기 결과 화면에 “오늘의 감독 판단” 3건 표시.

## Stage 6 — Balance

- 10 / 100 / 1,000 / 10,000경기 자동 실행.
- 같은 Roster 쌍에서 Manager/HeadCoach만 바꾸는 교차 실험.
- 여러 Roster 유형과 양 팀 교대 적용으로 홈·선공 편향 제거.

## 11. 테스트와 대량 Simulation Gate

## 11.1 규칙 테스트

- Profile 0/50/100 Clamp.
- 수동 조정이 감독 허용 범위를 넘지 않음.
- HeadCoach Predicate 불충족 시 Modifier 0.
- Benefit과 Tradeoff가 모두 Trace에 기록됨.
- 진행 중 경기에서 덕아웃 변경이 Snapshot에 역반영되지 않음.
- 감독·수석코치 미배치 시 `Balanced` 결과와 동일.

## 11.2 결정론 테스트

```text
Seed / Roster / ManagerId / HeadCoachId / PolicyAdjustment 동일
→ MatchManagementSnapshot 동일
→ MatchEvent Stream 동일
→ BoxScore 동일
```

Catalog 순서와 `Dictionary` 순회 순서가 선택 결과에 영향을 주지 않게 Stable ID 정렬을 사용한다.

## 11.3 통계 Gate

밸런스 수치는 아래 측정 뒤에만 확정한다.

| 지표 | 확인 목적 |
|---|---|
| SB Attempt / Success | 도루 성향이 빈도만 바꾸고 성공률을 몰래 버프하지 않는지 |
| Sacrifice Bunt / Game | SmallBall 차이가 실제 행동으로 보이는지 |
| PinchHit Appearance / Game | Bench Coordinator 영향과 Bench 고갈 위험 |
| Starter IP / Game | HookSpeed 차이 |
| Bullpen Pitchers / Game | 중간 교체와 벌떼 운용 차이 |
| High Leverage Role Fit | Setup/Closer 투입 설명 가능성 |
| R/G, AVG, OBP, SLG, HR, BB/K, ERA, WHIP | 리그 전체 분포 훼손 여부 |
| Win% by Roster Fit | 적합 조합의 가치와 단일 최적 조합 여부 |
| Consecutive Game Fatigue | 한 경기 이득이 다음 경기 비용으로 이어지는지 |

제안 목표는 동일 전력에서 최적·비적합 조합의 승률 차이가 보이되 감독 한 장이 선수 전력 차이를
뒤집지 않는 수준이다. 정확 범위는 10,000경기 결과 전에는 문서에 고정하지 않는다.

## 11.4 회귀 Gate

- 감독 미배치 Baseline의 기존 대량 통계 허용 범위 유지.
- 선수 커리어 모드의 감독 AI 경로에 Owner 소유 카드·경제가 유출되지 않음.
- TacticCard와 Manager Modifier가 이중 적용되지 않음.
- 기존 Staff Training/Conditioning/Scouting 테스트 유지.

## 12. 완료 기준

- 감독과 수석코치가 가상 Stable ID와 익명 실루엣으로만 표시된다.
- 감독은 공개된 운영 성향과 조건부 특성만 가지며 선수 능력치를 직접 올리지 않는다.
- 수석코치는 공개된 Predicate, Benefit, Tradeoff를 가지며 사용 후 소멸하지 않는다.
- 6개 덕아웃 방침 중 활성화된 항목은 모두 실제 `DetailedMatchEngine` Consumer에 연결된다.
- `ManagerModeMatchService`가 더 이상 무조건 `Balanced` Profile을 주입하지 않는다.
- 경기 시작 Snapshot, Save/Load, AI 배정이 결정론적이다.
- 경기 후 도루·번트·대타·투수 교체 이유를 설명할 수 있다.
- 10,000경기에서 주요 리그 지표와 Manager 조합별 편향을 보고한다.
- 최신 Unity EditMode Test와 Player Build 결과를 구분해 보고한다.
