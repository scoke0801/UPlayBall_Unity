# 프런트 매니저(안내 캐릭터) 현황과 남은 작업

## 0. 이 문서의 범위

여기서 말하는 "매니저"는 **구단 감독(Manager)이나 구단주가 아니라, 플레이어에게 상황을 설명하는
안내 NPC "프런트 매니저"**다. 팀을 운영하는 감독 AI(`ManagerUsageAi`, `ManagerLineupAi`)나
구단주 모드 런타임(`OwnerModeManager`)과는 별개 시스템이다.

2026-09-05 기준 조사·배선 결과를 정리한다.

## 2. 2026-09-05에 확인한 문제와 처리

### 2.1 구단주 모드에서 가이드가 전혀 뜨지 않았다 → 배선 완료

`GuideManager`가 `CareerManager.CareerChanged`만 구독하고 있어서, **Fact를 발행하는 경로가
선수 모드밖에 없었다.** 구단주 모드용 `OwnerRosterGuideEventAdapter`는 구현·데이터가 모두
갖춰져 있었는데도 이를 호출하는 코드가 프로젝트 어디에도 없는 미배선 상태였다.

처리:

- `GuideManager`가 `OwnerModeManager.RuntimeChanged`를 구독하도록 추가.
- 로스터 규칙을 재판정하지 않고 `OwnerModeManager.BuildRosterStatus().Validation` 결과를 그대로
  어댑터에 넘긴다.
- `OwnerRosterRevision.Compute()` 신설. **Revision을 증가 순번이 아니라 로스터 내용의 FNV-1a
  해시로 정의**했다. dedupe key가 `ROSTER_*:{rosterRevision}`이고 반복 정책이 Revision당 1회라서,
  순번이면 시설 업그레이드·저장처럼 로스터와 무관한 `RuntimeChanged`에도 같은 경고가 재발하고
  세이브·로드 후 같은 구성인데 값이 달라진다.
- Runtime이 없어지거나 교체될 때 pending 큐를 비워 모드 전환 시 메시지가 새지 않게 했다.

이제 구단주 모드에서 1군 구성이 유효하면 `ROSTER_VALID` 토스트가, 어긋나면 인원/야수투수 비율/
외국인 한도/중복 선수/벤치 부족/투수 보직 공백 경고가 뜬다.

### 2.2 죽은 테스트 기대값 제거

`OwnerModeManagerIntegrationTests.ExpectKnownGuideValidationError()`가 기대하던 로그
(`[CTA_UNKNOWN] $.cueDefinitions[9].cta.action: '' CTA Adapter가 없습니다.`)는 **현재 검증기
코드로는 만들어질 수 없다.** `GuideDatasetValidator.cs:308-311`에서 action이 비어 있으면
`CTA_ACTION_REQUIRED` 분기로 가고, `CTA_UNKNOWN`은 action이 비어 있지 않을 때만 탄다.
`"cta": null`을 빈 DTO로 정규화하는 `GuideCtaData.IsEmpty`가 해당 테스트보다 나중 커밋
(`329b1fa` → `71cbe7c`)에 들어오면서 남은 잔재라 제거했다.

### 2.3 헤드리스 테스트 제외 범위 축소

`Baseball.Game.Tests.Headless.csproj`가 `Assets/Tests/EditMode/Game/Guide/**`를 통째로 제외하고
있었다. 실제로 Unity(JsonUtility·AssetDatabase)에 의존하는 것은 `FrontManagerGuideTests.cs`
하나뿐이라 그 파일만 제외하도록 좁혔다. 신규 `OwnerRosterGuideEventAdapterTests`는 에디터 없이
돈다.

## 4. 남은 작업 (TODO)

### 4.1 아직 도달 불가한 Owner Cue — 우선순위 중

데이터·UI는 있으나 Fact 생산자가 없어 절대 뜨지 않는다.

- `TUTORIAL_OWNER_FIRST_ENTRY` (`OwnerModeFirstEntry`) — 구단주 모드 첫 진입 튜토리얼 대사.
  선수 모드의 `CareerModeFirstEntry`와 대칭 구조라 생산자만 붙이면 된다. "첫 진입"의 정의
  (새 게임 한정인지, 세이브 없음 기준인지)를 먼저 확정해야 한다.
- `TUTORIAL_OWNER_SCOUT_FIRST` (`ScoutFirstEntry`) — 스카우트 화면 첫 진입. 스카우트 메뉴 자체가
  아직 비활성(`OwnerModeUiProfileFactory`)이라 그 기능 구현과 함께 진행한다.

### 4.2 `GuideRepeatState`가 저장되지 않는다 — 우선순위 중

`GuideManager.CaptureRepeatState()` / `RestoreRepeatState()`가 정의만 있고 **호출처가 없다.**
그래서 `cooldownScope: Save`인 Cue(튜토리얼 등)는 재실행마다 다시 뜬다. 구단주 세이브
(`ManagerHistoricalSaveAdapter`)에 포함할지 결정이 필요하다. 선수 모드는 아직 디스크 세이브가
없으므로(`BaseballManager_PROJECT.md` 41.12절) 구단주 세이브 쪽만 해당한다.

### 4.3 모드 간 큐 격리는 "비우기"로만 처리 중 — 우선순위 낮음

`GuideDisplayContext`에 모드 필드가 없어 표시 시점 필터가 없다. 현재는 Runtime/Career가 바뀔 때
큐를 통째로 비워서 누수를 막는다. 두 모드를 오가는 흐름이 늘어나면 표시 시점 모드 필터를 넣는
편이 낫다.

### 4.4 나머지 미배선 Fact 대량 존재 — 우선순위 낮음

`factTypeIndex` 100개 중 실제 생산자가 있는 것은 선수 모드 4종
(`CareerModeFirstEntry`, `CareerNotStarting`, `CareerStartingLineupSelected`, `CareerDHStart`)과
구단주 로스터 7종뿐이다. 경기 전/후, 연승·연패, 스카우트, 카드 육성, 팀컬러/전술, 수상 관련
Cue는 전부 데이터만 있고 발행되지 않는다. 각 기능 구현 시 해당 Fact 생산자를 함께 붙인다.
