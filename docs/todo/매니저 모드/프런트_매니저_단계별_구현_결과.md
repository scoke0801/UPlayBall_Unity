# 프런트 매니저 단계별 구현 결과

구조 대조 보완안의 선수단 검증·경기 준비·경기 후 점검 세 흐름을 구현했다. 대상은 **구단주 모드의 안내 캐릭터**다. 기존 감독 AI의 판단과 경기 확률 모델은 변경하지 않았다. 이 문서는 원안의 60개 조언 전체를 구현했다는 보고가 아니다.

## 1. 플레이 흐름

홈의 ‘구단 운영 안내’를 열면 현재 적용된 선수단·프리셋의 진행 조건부터 확인한다. ‘대상 확인’은 기존 화면과 실제 슬롯으로 이동한다. 화면을 방문했다는 이유로 등록·배치 문제가 해결되지는 않는다. 변경안을 적용하고 저장한 뒤 원본 Validator에서 문제가 사라져야 해결된다.

허용 경고는 ‘현재 구성 유지’를 선택할 수 있다. 필수 위반에는 이 선택을 제공하지 않는다. ‘다음 주에 보기’는 같은 시즌·같은 주의 다음 경기에도 유지되며 다음 주에 다시 표시한다. 보류한 안내는 수동으로 다시 열 수 있다. 새 시즌에는 이전 보류를 가져오지 않는다.

경기 준비 안내는 기존 공개 상대 분석으로 연결하고, 실제 경기 시작은 기존 준비 화면에서 확정한다. 관전을 마치고 홈으로 돌아온 뒤 공개 점수와 다음 경기 투수진 점검을 안내한다. 승패 원인이나 추천의 효과를 단정하지 않는다.

안내 패널은 홈에서만 표시한다. 선수단·준비 화면으로 이동하면 셸 예약 공간을 반환하고 실제 대상만 강조한다. 경기·시즌 진행·모달·상점 연출 중에는 억제한다. 기존 선수 모드 안내는 유지하며 구단 편성 CTA 권한은 제공하지 않는다.

## 2. 단계별 연결

### 대화 UI 시각 보완

사용자 실화면 검수에서 전체 폭의 회색 패널과 동등한 여섯 버튼이 더미 UI처럼 보이는 문제가 확인됐다. 안내를 최대 1120 폭의 대화 카드와 큰 기존 초상화로 재배치하고, 공용 graphite 표면·금색 제목·주 행동 버튼 하나를 사용한다. 유지·보류는 보조 선택, 다음 안내·운영 소식은 작은 메뉴로 분리했다. 버튼은 실제 목적지에 따라 ‘선수 배치 확인’, ‘상대 분석 보기’, ‘경기 준비하기’로 표시한다. 공용 버튼 스킨에 `Quiet` 역할을 추가해 보조 메뉴도 마우스·키보드 포커스 상태를 유지한다.

초상화 신규 생성이나 경기 로직 변경은 없다. 장문 안내·130% 글자·네 해상도 회귀와 실제 홈 합성은 기존 Guide 검증 도구로 확인하며, 홈 합성 이미지는 `GuideScreenshots/home-guide-1280x720.png`와 `home-guide-1920x1080.png`에 기록한다.

|---|---|---|
| 1. 이동 계약 | 행동별 지원 판정, 미지원 홈 대체 제거, 온보딩 자동 종료 제거, 요청·화면·대상 도착과 실패 분리 | `FrontManagerGuideCtaRouter.cs`, `OwnerModeShellCoordinator.Guide.cs` |

| 3. 경기 준비 | 실제 공개 분석과 준비 확정 화면 연결. 프리셋·카드 ID 재확인. 미적용 편집·미리보기 중 이동 차단 | `UI_Scene_OwnerRosterLineup.Guide.cs`, `OwnerExpansionWorkspaceCoordinator.cs` |

Game은 순수 C# 상태와 의미적 대상만 소유한다. RectTransform·포커스·강조·화면 대기는 Presentation에 있다. 기존 Fact/대사 큐는 ‘운영 소식’에서 재사용하며 별도 범용 큐·Flow DSL을 추가하지 않았다.

## 3. 저장 계약

Owner의 `ManagerHistoricalSaveAdapter.CurrentSaveVersion`은 **19 → 20**이다. 선수 커리어 저장 버전은 변경하지 않았다. `guideRepeatState`와 별개로 `guideProgress`에 경기 범위·시즌·회차·상태·보류 기한·추적·공개/확인한 최근 경기 식별과 점수를 저장한다. 문장·좌표·Unity 참조는 저장하지 않으며 신규 마이그레이션은 만들지 않았다.

경기가 바뀌면 지난 경기 상세 이력을 비우고, 같은 시즌에서 기한이 남은 현재 문제의 보류만 유지한다. 20시즌 × 144경기 범위 전환 테스트로 상세 이력의 누적을 방지하는 계약을 확인했다. 이는 실제 20시즌 경기를 돌린 성장·계약 검증과 다르다.

실제 Unity JSON 저장/복원 테스트에서 생성 전 포스트시즌의 null이 빈 DTO가 되어 로드가 실패하는 문제가 드러났다. 이번 저장 연결에 필요한 범위에서 **시즌 ID·시드·시리즈가 모두 빈 포스트시즌만 없음으로 복원**하도록 보완했다. 내용이 있는 잘못된 데이터의 검증은 유지한다.

## 4. 검증 기록

- 전체 Headless EditMode: **820 통과, 0 실패, 11 건너뜀**, 약 654초. 마지막 주간 보류 보완 이전의 전체 실행이다. 로그: `output/guide-validation/headless.log`.
- 최신 `GuideProgressTests`: **15 통과, 0 실패**. 주간 보류의 경기·시즌 경계와 유지 경고의 필수 위반 전환까지 포함한다.
- Unity 안내 통합 필터: **54 통과, 0 실패**. 결과: `output/guide-validation/editmode-results.xml`.
- 현재 소스를 직접 포함한 Presentation 및 Presentation.Tests 보조 컴파일: 오류 0, 경고 0.
- 실제 동일 명령으로 3경기를 실행해 안내 사용 유무의 전체 `MatchEvent` 배열과 점수가 일치했다. 경기 RNG를 안내가 소비하지 않는 경계를 확인한 것으로, 밸런스 조정 실험은 아니다.
- Unity EditMode에서 실제 슬롯 신원, 잘못된 카드 거부, 초안 보존, 파일 저장/전체 Runtime 복원, 저장 실패 이력 복구, 취소된 늦은 도착, 실제 분석 본문 도착, Owner/Career 권한을 확인했다.
- 1280×720, 1920×1080, 2560×1440, 3440×1440에서 안내 패널을 130% 글자로 렌더링하고 본문·버튼 영역과 공용 스킨을 검사했다. 1280·1920 실제 선수단 화면에서는 안내 숨김·공간 반환과 홈 복귀를 검사했다. 생성 이미지를 열어 배치도 확인했다.

재현 명령:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Tools/GuideValidation/Invoke-GuideValidation.ps1
dotnet run --project Tools/HeadlessRegression/EditModeTestRunner/EditModeTestRunner.csproj -c Release --no-restore -- GuideProgressTests
dotnet build Baseball.Presentation.Tests.csproj --no-restore -v quiet /p:CustomAfterMicrosoftCommonTargets=C:/UsingProject/UnityProject/UPlayBall_Unity/Tools/GuideValidation/CurrentSources.targets
```

Unity 검증 스크립트는 `output/guide-validation/UnityProject`를 사용하고 PID를 반환한다. 실행 완료는 `output/guide-validation/editmode-results.xml`과 `unity.log`로 확인한다. 메인 프로젝트 Library를 공유하지 않는다. 스크린샷은 격리 프로젝트의 `GuideScreenshots`에 있다.

## 5. 남은 검수와 범위 밖 문제

메인 프로젝트 Play Mode의 실제 키보드·게임패드 전 경로, 장시간 수동 플레이의 반복 피로도, 준비까지 클릭 수의 전후 비교는 수행하지 않았다. EditMode 포커스 검사와 정적 렌더를 이 검수의 완료로 대신하지 않는다. 본문 설명을 사용자가 이해했는지도 플레이 검수로 확인해야 한다.

현재 `ManagerHistoricalSaveJsonStore`는 직접 파일 쓰기를 사용한다. 프로젝트 문서의 원자 저장·Hash·백업 설명과 이 Owner 구현에는 차이가 있다. 안내 상태의 메모리 롤백은 검증했지만 쓰기 중 중단에 대한 디스크 원자성은 보장하지 않는다. 범위 밖 저장 인프라를 임의로 교체하지 않았으며 별도 개선이 필요하다.

팀컬러·전술의 기존 검증 대상 연결은 제공하지만 대안 효과 비교·재정/계약 추천 팩·60개 조언·다섯 탭 Drawer·Career 신규 과제 체계는 후속 범위다. 기존 공개 근거·실제 목적지·완료 판정이 갖춰진 항목부터 확장한다.
