# 구단주 매니저 리포트 개선 기획

상태: P0/P1/P2 구현·외부 컴파일·콘솔 회귀 적용. 사용자 지시로 에디터 테스트와 실제 화면 검수는 미실행이다.
대상은 구단주 모드다. 선수 커리어의 감독 권한은 변경하지 않는다.
[실제 적용 범위와 검증](../reports/owner-manager-report-cases.md)을 따른다.

## 1. 경험 목표

매니저는 점검 문구를 쌓는 알림함이 아니라 **구단의 변화를 기억하고, 지금 필요한 판단과 그 근거를 짚는 조력자**다.
플레이어가 목록만 보고 누구에게 무슨 일이 생겼으며 무엇을 할 수 있는지 알아야 한다.
할 말이 없는 날은 조용해도 된다. 생기는 실제 선수의 성장·기록·선택의 후속 결과에서 만든다.

## 2. 현재 문제와 확인 범위

제공 화면에는 같은 제목·시즌·주차의 읽은 리포트가 반복되며 총 48건이 표시된다.
화면만으로 48건 모두가 같은 사건인지, 서로 다른 슬롯인지, 과거 저장 이력인지 확정할 수 없다.
현재 소스에서 확인한 구조적 원인은 다음과 같다.

| 확인한 코드 | 경험에 미치는 영향 |
|---|---|
| `OwnerGuideGoalProvider`는 프리셋·문제 코드·그룹·슬롯별 키를 생성 | 여러 투수의 같은 종류 경고가 각각 생긴다. 개별 원본 보존은 필요하지만 목록은 묶어야 한다. |
| `FormatReportTitle`은 문제 코드에 대응하는 고정 제목만 사용 | 대상이 달라도 모두 ‘투수의 기용 역할을 살펴봐요’로 보인다. |
| `RenderReports`의 전체 필터는 만료·읽은 이력까지 포함 | 지금 할 일과 옛 기록이 섞인다. 읽음 처리가 목록의 소음을 줄이지 못한다. |
| `ReconcileReports`는 동일 활성 키를 갱신하고 시즌 변경·해결로 만료된 뒤 재발하면 새 항목 생성 | 단순 화면 갱신 중복 억제는 이미 있다. 안건의 연속성·재발 표현과 지난 기록 정리가 부족하다. |
| `ManagerReportData` 목록에 보존 상한이 없다 | 여러 시즌 누적 시 탐색과 저장 비용이 계속 증가한다. |
| 투수 역할 검증은 원래 역할→배치 역할과 컨디션 불이익을 생성하지만 안내 공급자는 코드만 근거로 전달 | 실제 조언에 필요한 역할·영향 설명이 전달 과정에서 축소된다. |

기존 [실용성 개선](../reports/owner-manager-actionable-guidance.md)의 재알림 억제·읽음과 해결 분리는 유지한다.
구현 첫 단계에서 문제 세이브의 키·슬롯·만료 여부별 집계를 개발용으로 확인한다. 실제 48건 원인은 아직 재현 검증하지 않았다.

## 3. 핵심 결정

### 3.1 알림 대신 안건을 유지한다

- 같은 운영 문제는 현재 목록에서 **안건 한 장**이다. 같은 오더의 투수 역할 경고 3건은 ‘익숙한 역할과 다른 투수 3명’으로 묶고 상세에서 각각의 선수와 자리로 이동한다.
- 그룹 기준은 같은 구단·적용 오더·문제 유형·행동 목적지다. 다른 오더의 경고나 다른 조치가 필요한 필수 오류를 억지로 합치지 않는다.
- 내부의 개별 검증 문제와 경기 시작 차단은 그대로 유지한다. 묶음은 원본을 누락시키는 장치가 아니다.
- 동일 근거로 경기·화면·저장을 반복해도 새 항목·새 배지·정렬 상승이 발생하지 않는다.
- 일부 대상 해결 시 ‘3명→2명’으로 같은 안건을 갱신한다. 감소는 새 경고가 아니다.
- 새 대상 추가, 실제 영향 단계 악화, 필수 오류 격상만 같은 안건의 ‘변경됨’으로 재알린다. 수치의 미세 변화와 문구 교체는 재알림 사유가 아니다.
- 시즌 번호 변경 자체는 새 소식이 아니다. 동일 안건은 이어가고, 새 시즌의 적용 편성이 달라지면 그 변경을 평가한다.
- 해결 후 재발은 ‘다시 확인’으로 구별한다. 발생 회차는 이력으로 남기되 현재 안건을 복제하지 않는다.
- 선수 제거·오더 폐기 등은 ‘대상 변경으로 종료’, 실제 검증 통과는 ‘해결’이다. 둘을 성공으로 혼동하지 않는다.

### 3.2 확인과 결정은 다르다

| 행동 | 의미 | 이후 동작 |
|---|---|---|
| 읽음 / 모두 읽음 | 내용을 확인함 | 미해결 안건은 남지만 새 배지는 제거 |
| 이번 기용 유지 | 선택 경고를 이해하고 현재 배치를 선택함 | 동일 대상·역할·영향에서는 홈 재추천 없음. 현재 탭의 ‘유지한 판단’에 접어서 남김 |
| 나중에 확인 | 지금 결정하지 않음 | 다음 게임 내 주차에 현재 안건으로 복귀. 근거가 같으면 새 알림으로 세지 않음 |
| 보관 | 나중에 다시 읽을 기록 | 알림 억제·해결과 독립. 변경되어도 보관을 임의 해제하지 않음 |
| 대상 화면에서 수정 | 실제 편성 변경 | 원본 재검증 후에만 해결 판정 |

필수 오류에는 ‘이번 기용 유지’를 제공하지 않는다. 읽거나 미뤄도 경기 준비 화면의 차단 사유는 항상 보인다.
묶음의 일부 선수만 유지할 수 있고 새로 추가된 선수까지 자동 동의하지 않는다.

## 4. 화면과 문구

기존 홈 우측 ManagerHost·Front Office V2·SharedGameShell을 유지한다. 새 전용 메뉴나 중앙 모달은 만들지 않는다.
기존 `전체 / 우선 확인 / 보관`은 `현재 / 구단 소식 / 기록`으로 바꾼다. 기록 안에 보관 필터를 둔다.

- **현재(기본):** 필수 확인 → 검토 제안 → 접힌 유지·보류 안건. 읽었는지와 해결됐는지를 별도로 표시한다.
- **구단 소식:** 성장 완료·기록 달성·주간 회고 등 실제 변화. 현재 경고를 복사해 넣지 않는다.
- **기록:** 종료된 안건과 지난 소식. 시즌별 탐색과 보관 필터. 오래된 기록에는 현재 실행 CTA를 제공하지 않는다.
- 홈 대표 추천은 한 장이며 ‘현재 안건 2건 · 새 소식 1건’처럼 뜻이 다른 수를 분리한다. 읽은 안건만 남으면 ‘새 알림 없음 · 유지 중인 안건 2건’으로 표현한다.
- 목록은 제목에 대상·문제, 두 번째 줄에 근거·변화를 표시한다. 날짜·읽음은 보조 정보로 내린다. 항목을 늘려 화면을 빽빽하게 만드는 해결은 하지 않는다.
- 일괄 읽음 버튼은 제목을 대체하지 않는 고정 보조 행동이다. 읽은 뒤에도 목록 위치와 선택 포커스를 보존한다.
- 빈 현재 목록: ‘지금 확인할 운영 문제는 없어요.’ 데이터 로딩·실패 상태는 별도로 표현한다. 실패를 정상 상태로 표시하지 않는다.

**화면 예시 — 아래 이름·인원은 설명용이며 실제 플레이 데이터가 아니다.**

```text
매니저 리포트                        모두 읽음
[현재 1]   [구단 소식]   [기록]

검토 제안 · 확인함
익숙한 역할과 다른 투수 2명
김민수: 선발 → 불펜 1번 · 박준호: 구원 → 선발 3번
현재 역할 배치에 따른 컨디션 불이익이 있어요.

[배치 비교]  [이번 기용 유지]
```

상세에서는 각 선수의 원래 역할·현재 자리·실제 적용 영향·선택지를 보여 준다.
‘선발로 옮기면 승리합니다’처럼 확인되지 않은 효용을 단정하지 않는다.
비교할 합법적인 대체 후보가 없으면 그 사실을 밝히고 현재 기용 유지도 유효한 선택으로 설명한다.
리포트는 편성을 자동 변경하지 않는다. 대상 선택 → 기존 비교·확정 화면으로 연결하고 돌아오면 원본을 재검증한다.
대상이 사라졌다면 오래된 슬롯의 다른 선수를 열지 말고 종료 사유를 보여 준다.

## 5. 생기를 만드는 콘텐츠

먼저 중복과 안건 신뢰를 해결한 후 기존 게임 기록을 소비하는 소식만 추가한다.

| 종류 | 발행 조건 | 예시와 제한 |
|---|---|---|
| 성장 완료 | 실제 훈련·유학 완료 이벤트 | ‘김민수가 유학을 마쳤어요’ + 실제 성장 항목 + 선수 보기. 같은 완료 사건은 한 번 |
| 기록 달성 | 기존 공식 누적 기록의 최초 기준 통과 | ‘박준호, 구단 통산 100홈런’ 등 실제 집계 범위 명시. 연습경기와 정규 기록 혼합 금지 |
| 주간 회고 | 게임 내 주차 종료, 실제 경기 기록 존재 | ‘이번 주 4승 2패, 불펜 볼넷이 줄었어요’처럼 집계 근거 표시. 비교 표본 부족 시 변화 해석 생략 |
| 판단 후속 | 저장된 기용 선택 이후 충분한 출전 표본 | ‘배치 변경 후 3경기 등판’ 등 관찰 사실. 배치 때문에 성적이 좋아졌다는 인과 단정 금지 |

1차 소식은 성장 완료·기존 기록 달성 중 데이터 출처가 확인된 항목부터 도입한다.
주간 분석·판단 후속은 정책의 최소 표본을 통과한 실제 기록으로 연결했다.
한 경기 부진을 장기 약점으로 해석하거나 점수만 보고 패인을 지어내지 않는다.
성장 완료 여러 건은 한 묶음으로 전달하고 개별 완료 정보는 보존한다.

발행 정책 적용값: 새 구단 소식의 홈 노출은 게임 내 주차당 최대 2묶음, 회고는 주차당 1건 이하.
기존 운영 안건은 별도의 현재 목록과 읽음·유지·보류 정책을 적용한다.
이는 검증 전 UX 가설이며 경기 밸런스 계수가 아니다. 제한을 넘은 소식은 해당 주차 요약에 합치고 홈 알림을 예약 적체하지 않는다.
필수 오류는 빈도 제한에서 제외하며 모두 현재 목록과 경기 준비 검증에 남긴다.
게임 내 진행 시점으로만 판단하고 시스템 시간이나 경기 RNG를 사용하지 않는다.
기분·친밀도·대화 선택·별도 보상·가짜 격려 이벤트는 이번 범위에 넣지 않는다.

## 6. 데이터와 구현 순서

### P0 — 반복 제거와 판단 가능성 회복

1. 재현 세이브 또는 동일 조건 fixture에서 48건의 구성과 실제 생성 경로를 확인한다.
2. 기존 검증 결과를 유지한 채 그룹 안건·개별 대상·최초 발생·마지막 의미 변화·종료 사유를 구분한다.
3. 원본 검증의 역할·영향 근거를 순수 데이터로 전달하고 목록/상세 표현을 개선한다.
4. 현재/기록 분리, 동적 제목, 읽음/유지/보류/보관의 독립 처리, 대상별 CTA를 연결한다.
5. 저장 복원·시즌 전환·재발과 장기 이력을 검증한다. P0만으로도 스팸 문제 개선을 납품할 수 있어야 한다.

### P1 — 실제 사건 기반 소식

성장 완료·기존 기록 달성 공급자를 연결하고 주차별 묶음·노출 정책을 추가한다.
연결되지 않은 자료는 문구로 보완하지 않는다. 소식이 없어도 정상적으로 조용한 화면이어야 한다.

### P2 — 근거 있는 회고

최근 경기 집계와 판단 이후 관찰을 연결한다. 최소 타석·이닝·경기 표본, 비교 기간, 재발행 기준을 데이터로 정의하고
소표본 오판·중복 회고 검증을 통과한 유형만 활성화한다. 임의 승리 원인 생성은 허용하지 않는다.

구현 경계:

- Game의 `GuideProgressState`와 순수 보고 모델이 상태·재알림·결정론적 정렬을 소유한다.
- Simulation의 기존 Validator/경기 결과를 읽으며 리포트가 경기 규칙·페널티를 다시 계산하지 않는다.
- Presentation은 한국어 이름·문구·대상 이동을 맡는다. 내부 키와 추적값은 UI에 노출하지 않는다.
- 기존 `GuideGoalStatus`·원본 딥링크를 활용하고 겹치는 상태 기계를 별도로 중복 구현하지 않는다.
- 발행 빈도·보존량·분석 표본 기준은 보고 정책 데이터에 둔다. 문구와 무관한 의미 키 및 근거 버전으로 중복을 판정한다.
- 저장 DTO 변경 시 해당 구단주 저장 버전을 실제 구현값에서 올린다. 미배포 과거 포맷 마이그레이션은 만들지 않는다.
- 보존 정책 초안: 활성 안건은 전부, 일반 종료 상세는 최근 2시즌, 오래된 내용은 시즌별 요약. 보관은 최대 100건이며 초과 시 기존 보관 해제 안내를 제공한다.
- 중요한 달성 사실은 기존 공식 커리어/구단 기록에 남긴다. 리포트 정리가 공식 기록을 삭제해서는 안 된다.
- 과거 중복은 표시 단계에서 의미 키로 묶을 수 있지만 근거가 없어 복원할 수 없는 옛 문구는 ‘지난 안내’에 둔다. 현재 소식으로 승격하지 않는다.

P0는 Headless/EditMode 상태 전이·저장 회귀와 실제 화면 검수로 확인한다.

경기 밸런스는 변경하지 않는다. 향후 역할 페널티까지 변경한다면 별도 대량 경기 통계 검증을 수행한다.
P0/P1/P2의 외부 컴파일·콘솔 38건과 실제 경기 쌍대 실행 결과는 적용 보고서에 기록했다.
사용자 지시로 에디터 테스트는 실행하지 않았으며 실제 48건 세이브 재현·Unity 화면 검수는 미실행이다.
