# 06. 감독 전술과 전술카드

## 0. 목적

감독모드의 경기 운영을 "슬라이더로 조절하는 상시 전술 성향"과 "경기당 2장, 조건부로
발동하는 승부수 카드"로 분리해 정의한다. 전술카드는 새 재화를 만들지 않고 기존 Money를
연구소 비용으로 재사용한다.

## 0.1 수치 출처 표기 규칙

04절 §0.1과 동일한 규칙을 쓴다.

```text
[Reference]        프야매 공개 자료로 확인되는 카드 이름·조건·개념(예: "8회 열세 강화",
                    "1~3회 공격 강화", "선발 1~5회 강화", "득점권 위기 강화")
[ProjectOriginal]  정확한 수치(Contact +6 등)는 프야매 원문에서 확인된 것이 아니라
                    이 프로젝트가 새로 설계한 밸런스값
```

카드의 **존재와 트리거 개념**은 `[Reference]`로 표시하고, **정확한 스탯 수치**는 별도 필드
`ReferenceBehavior`(개념 서술)와 `ProjectBalanceValue`(실제 적용 수치)로 나눠 기록한다 —
"프야매 동일 효과"라고 뭉뚱그려 적으면 이후 검증 시 출처를 혼동하게 된다.

```text
TacticCardDefinition.ReferenceBehavior      // 예: "8회 이후 열세 시 타격 강화" [Reference]
TacticCardDefinition.ProjectBalanceValue    // 예: "Contact +6 / Power +6 / Mental +8" [ProjectOriginal]
```

## 1. 감독 전술 성향 (소모되지 않음)

```text
ManagerTacticProfile
{
    BattingApproach     // 0(컨택) ~ 8(장타)
    StealAggression     // 0(억제) ~ 8(적극)
    BuntAggression       // 0(강공) ~ 8(희생번트)
    PinchHitAggression   // 0(주전신뢰) ~ 8(적극교체)
    StarterHook          // 0(빠른교체) ~ 8(선발신뢰)
    BullpenHook          // 0(롱릴리프) ~ 8(벌떼야구)
    PitchApproach        // 0(유인구) ~ 8(정면승부)
    DefenseAggression    // 0(안정) ~ 8(공격적수비)
}
```

각 축은 능력치를 직접 더하지 않고 AI 판단 로직의 **행동 확률/임계값**을 바꾼다(예:
BattingApproach 0은 PowerSwing 선택률을 낮추고 2스트라이크 컨택 보호 행동을 늘린다).
0/8 극단값에서도 능력치가 없는 선수를 억지로 잘하게 만들지 않는다 — "선수 능력 × 감독
철학"으로 결과가 나오게 한다.

이 구조는 감독모드 전용이 아니라 **선수 커리어 모드의 감독 AI에도 이미 존재해야 하는
개념**이다(`BaseballManager_PROJECT.md`가 감독 AI 소유로 규정한 라인업/기용/투수교체 판단의
내부 파라미터화). 감독모드에서는 이 파라미터를 플레이어가 직접 조절하고, 선수 커리어
모드에서는 AI 성격값으로만 존재한다.

## 2. 전술카드 (경기당 소모품)

```text
TacticCardDefinition
{
    CardId, Name, Category (Batting|Pitching|Analysis|Common)
    TacticTier (Normal|Rare|Special|Signature)   // 선수 카드 Edition(03절)과 이름 충돌 방지를
                                                   // 위해 "Rarity"가 아닌 TacticTier로 명명
    ReferenceBehavior         // 개념 서술, §0.1
    ProjectBalanceValue       // 실제 적용 수치, §0.1
    TriggerConditions[]       // 공통 조건 시스템, 문자열 하드코딩 금지
    TargetRule                 // 예: BatterOrder in 3..5
    StatModifiers[]
    BehaviorModifiers[]
    DurationRule               // 예: UntilInningEnd, UntilAtBatEnd, SingleAtBat
    CounterCardIds[]
    IsDisruption                // 상대 디버프 계열 여부
}
```

### 2.1 장착과 소모 규칙

- 경기당 슬롯 2개.
- 같은 카드 2장 중복 장착 불가.
- `IsDisruption` 카드는 경기당 최대 1장.
- 경기 시작이 확정되면 장착 카드는 조건 발생 여부와 무관하게 소모된다(결과를 보고 쓰는
  아이템이 아니라 상황을 예상하고 준비하는 베팅으로 만들기 위한 의도된 제약).

### 2.2 TriggerCondition — 공통 조건 시스템

카드마다 전용 Resolver를 만들지 않는다. 조건은 데이터로 표현한다.

```text
Inning == 8
ScoreState == Trailing
RunDifference <= 3
BatterOrder in 3..5
RunnerOnSecondOrThird == true
OpponentPitcherHand == Left
PitcherRole == Closer
```

`TacticTriggerEvaluator`가 이 조건 목록을 평가하고, `TacticCardResolver`가 통과한 카드의
`StatModifiers`/`BehaviorModifiers`를 `TacticEffectContext`에 적용한다.

### 2.3 발동 순서 (결정론 고정)

```text
1. 경기 조건 확인
2. 카드 봉쇄(무효화류) 판정
3. 직접 카운터 판정 (CounterCardIds 상쇄)
4. 상대 디버프 적용
5. 아군 버프 적용
6. 감독 기본 전술 적용
7. 실제 타석/투구/수비 판정
```

동일 Seed에서 이 순서가 항상 동일해야 결정론 계약(`CLAUDE.md` "결정론적 시뮬레이션")을
지킬 수 있다.

## 3. 1차 구현 카드 목록 (16장)

전체 카탈로그를 한 번에 만들지 않는다. 우선 아래 16장으로 조건 조합의 다양성을 검증한다.

```text
공격: 초반 총공세, 럭키 세븐, 약속의 8회, 마지막 반격, 클린업 폭발, 비장의 대타
투수: 강심장, 퀄리티 스타트, 완투의 각오, 불펜 총동원, 문을 닫아라, 주자를 묶어라
분석/공통: 선발 집중 분석, 끈질긴 승부, 불펜 균열, 연패 탈출
```

대표 카드 예 — **약속의 8회**: `ReferenceBehavior`(`[Reference]`) = "8회 공격 시작 시 열세면
타격 강화". 조건 `Inning == 8 AND ScoreState == Trailing`. `ProjectBalanceValue`
(`[ProjectOriginal]`, 정확한 수치는 프야매 원문 확인 대상 아님): 1~3점차 Contact +6 / Power
+6 / Mental +8, 2스트라이크 컨택 판정 +8%p. 4점차 이상 Contact +4 / Power +4 / Mental +6.
`DurationRule = UntilInningEnd`.

카운터 예: `끈질긴 승부`(상대 선발 피로 가속) ↔ `완투의 각오`(상쇄). `타선 침묵` ↔
`초반 총공세`(상쇄). `불펜 균열` ↔ `불펜 총동원`(상쇄). 모든 카드에 억지로 카운터를 붙이지
않는다.

## 4. 전술 연구소 (획득)

새 재화를 만들지 않고 Money를 쓴다.

```text
안정 연구  — 저비용, Normal Tier 위주 다수 획득
승부 연구  — 고비용, Rare/Special Tier 확률 상승, 소량 획득
전문 연구  — Category 지정(공격/투수/분석/공통) 편중 획득
```

중복 카드는 사용 횟수(재고)로만 쌓인다 — 선수 카드처럼 강화 대상이 아니다. 미사용 카드는
연구 비용보다 낮은 가격에 Money로 판매 가능.

## 5. Signature 카드 (감독 업적 전용)

일반 연구에서 나오지 않는다. 감독 커리어의 실제 플레이 기록(예: "8회 열세에서 시즌 10회
이상 역전승")으로 해금한다. 능력치 수치는 일반 Special과 비슷한 범위로 제한하고, 서사적
가치(감독 프로필, 뉴스)를 더 크게 둔다.

## 6. 밸런스 목표

```text
Normal 카드 발동 시 기대 승률 영향   약 +0.5~1.5%p
Rare                              약 +1~3%p
강력한 역전 카드(조건 정확히 발생)   +3~6%p, 단 조건 미충족 시 효과 0
```

전술카드가 능력치 격차를 뒤집는 자동 승리 수단이 되지 않도록, 위 목표를 대량 시뮬레이션으로
검증한다.

## 7. AI 감독의 전술카드 사용

AI는 플레이어와 동일한 `TacticCardDefinition`을 참조하되, 카드팩/인벤토리 뽑기 시뮬레이션은
만들지 않는다. `TacticalFacilityLevel`, `ManagerQuality`, `LeagueTier`로 `AvailableTacticPool`을
바로 구성하고, AI Personality(`AggressiveHitting`, `BullpenHeavy`, `StarterTrust`, `SmallBall`,
`DataDriven` 등)에 따라 상황에 맞는 카드를 선택하게 한다. 판정 규칙은 플레이어와 동일해야
공정하다.

## 8. 선수 커리어 모드와의 연결

선수 커리어 모드에서는 플레이어가 전술을 선택하지 않는다. 감독 AI가 전술/전술카드를
선택하고, 화면에는 "우리 감독이 [약속의 8회]를 발동했다"처럼 결과만 통지한다. 이는 `07_
선수모드_연동_와일드카드.md`에서 이어서 다룬다.

## 9. 검증 기준

- 카드 조건 평가가 데이터 기반이며 카드별 하드코딩 분기가 없는지(신규 카드 추가 시 Resolver
  코드 변경이 필요 없는지) 코드 리뷰 기준으로 확인.
- 카운터 관계가 있는 두 카드가 동시 장착되면 정확히 상쇄되는지 EditMode 테스트.
- 경기당 슬롯 2개, 디버프 최대 1장 제약이 위반되면 장착 자체가 거부되는지 테스트.
- 조건 미발동 카드도 경기 확정 시점에 소모되는지 테스트.
- 대량 시뮬레이션으로 §6 기대 승률 영향 범위를 실측하고 문서에 근거 수치를 남긴다.
- 모든 카드 정의에 `ReferenceBehavior`와 `ProjectBalanceValue`가 분리되어 기록돼 있고,
  `[Reference]`/`[ProjectOriginal]` 태그 없이 수치만 적힌 카드가 없는지 문서 리뷰로
  확인한다(밸런스 근거 출처 누락 방지).
