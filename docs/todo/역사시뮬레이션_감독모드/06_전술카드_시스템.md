# 06. 감독 전술과 전술카드

## 0. 목적

감독의 경기 운영을 다음 세 축으로 나눈다.

1. 소모되지 않는 `ManagerTacticProfile` — 장기적인 운영 성향.
2. 라인업/벤치/불펜의 상황별 실제 기용 판단.
3. 경기당 2장까지 준비하는 조건부 전술카드.

선수 커리어 모드에서는 감독 AI가 이 판단을 소유하고, 감독모드에서는 플레이어의 직접 입력과 자동 운영 AI가 같은 Simulation 규칙을 사용한다.

## 0.1 수치 출처 표기

```text
[Reference]        프야매 공개 자료로 확인되는 이름/트리거/개념
[ProjectOriginal]  이 프로젝트가 설계한 정확한 적용 수치
```

```text
TacticCardDefinition.ReferenceBehavior
TacticCardDefinition.ProjectBalanceValue
```

두 값을 분리해 기록한다.

## 1. ManagerTacticProfile

```text
ManagerTacticProfile
{
    BattingApproach      // 0 컨택 ~ 8 장타
    StealAggression      // 0 억제 ~ 8 적극
    BuntAggression       // 0 강공 ~ 8 희생번트
    PinchHitAggression   // 0 주전신뢰 ~ 8 적극교체
    StarterHook          // 0 빠른교체 ~ 8 선발신뢰
    BullpenHook          // 0 롱릴리프 ~ 8 적극 불펜
    PitchApproach        // 0 유인구 ~ 8 정면승부
    DefenseAggression    // 0 안정 ~ 8 공격적 수비
}
```

각 축은 능력치를 직접 더하지 않고 AI의 선택 확률/임계값을 바꾼다.

## 2. 라인업과 벤치 교체

감독은 경기 상황에 따라 벤치 5명을 주전 9명과 교체할 수 있다.

판단 요소 예:

```text
대타
대주자
컨디션/피로
좌우 상성
공격 강화
수비 강화
부상
점수차/이닝
```

교체 시 포지션 적합성을 반드시 평가하되 **비주포지션이라는 이유만으로 교체를 금지하지 않는다.**

### 2.1 야수 비주포지션

02절 `PositionAssignmentRule`을 그대로 사용한다.

```text
본래/적격 수비 포지션과 다른 슬롯
  → 실책 확률 증가
  → Condition 하락
```

감독 AI는 교체의 공격적 이득과 이 패널티를 함께 비교해야 한다.

### 2.2 DH

DH는 어떤 포지션의 타자도 자유롭게 맡을 수 있다. DH 배치 자체에는 비주포지션 수비 패널티를 적용하지 않는다.

### 2.3 선수 커리어 모드

선수 커리어 모드의 플레이어는 라인업/교체를 직접 결정하지 않는다. 감독 AI가 공통 규칙으로 결정하며 결과를 플레이어에게 보여준다.

## 3. 투수진 운영과 불펜 역할

투수진은 02절 공통 구성 규칙을 사용한다.

```text
선발 5
Bullpen 1
Bullpen 2
Bullpen 3
Bullpen 4
Setup 1
Closer 1
```

### 3.1 BullpenUsagePolicy

```text
Bullpen 1 / 2
  필승조 + 추격조
  접전 리드 또는 접전 열세에서 우선 고려

Bullpen 3
  애매한 상황 + 추격조
  중간 레버리지나 승패가 아직 열려 있는 열세 상황에서 우선 고려

Bullpen 4
  패전조 + 비상 대체
  크게 뒤지는 상황에서 우선
  Bullpen 1~3의 체력 부족/연투/사용 불가 시 대체
```

이닝, 점수차, 레버리지, 체력 임계값은 데이터화한다.

감독은 단순 슬롯 번호만 보지 않고 다음을 함께 평가한다.

```text
ScoreState
Inning
RunDifference
Leverage
PitcherCondition
RecentWorkload
RestDays
OpponentMatchup
ManagerTacticProfile
```

### 3.2 비본래 투수 역할 기용

Starter를 Bullpen으로, 일반 Bullpen을 Setup/Closer로 쓰는 등 본래 `PitcherRole`과 다른 역할 기용을 허용한다.

```text
AssignedPitcherRole != NaturalPitcherRole
  → Condition 하락
```

정확한 패널티는 02절 공통 Balance를 사용한다. 역할 불일치를 하드 금지하지 않는다.

## 4. 전술카드

```text
TacticCardDefinition
{
    CardId
    Name
    Category            // Batting | Pitching | Analysis | Common
    TacticTier          // Normal | Rare | Special | Signature
    ReferenceBehavior
    ProjectBalanceValue
    TriggerConditions[]
    TargetRule
    StatModifiers[]
    BehaviorModifiers[]
    DurationRule
    CounterCardIds[]
    IsDisruption
}
```

선수 카드 `Edition`과 혼동하지 않도록 `TacticTier`를 사용한다.

### 4.1 장착/소모

- 경기당 슬롯 2개.
- 같은 카드 2장 중복 장착 불가.
- `IsDisruption`은 경기당 최대 1장.
- 경기 시작이 확정되면 조건 미발동이어도 장착 카드가 소모된다.

### 4.2 공통 TriggerCondition

카드마다 전용 Resolver를 만들지 않는다.

```text
Inning == 8
ScoreState == Trailing
RunDifference <= 3
BatterOrder in 3..5
RunnerOnSecondOrThird == true
OpponentPitcherHand == Left
PitcherRole == Closer
```

`TacticTriggerEvaluator`가 데이터 조건을 평가하고 `TacticCardResolver`가 효과를 적용한다.

## 5. 발동 순서 — 결정론 고정

```text
1. 경기 조건 확인
2. 카드 봉쇄 판정
3. 직접 Counter 판정
4. 상대 Debuff
5. 아군 Buff
6. 감독 기본 전술/라인업·불펜 판단 Modifier
7. 포지션/역할 Assignment Penalty 반영
8. 실제 타석/투구/수비 판정
```

동일 Seed와 동일 Game State에서 항상 같은 평가 순서를 사용한다.

## 6. 1차 구현 전술카드 16장

```text
공격
  초반 총공세
  럭키 세븐
  약속의 8회
  마지막 반격
  클린업 폭발
  비장의 대타

투수
  강심장
  퀄리티 스타트
  완투의 각오
  불펜 총동원
  문을 닫아라
  주자를 묶어라

분석/공통
  선발 집중 분석
  끈질긴 승부
  불펜 균열
  연패 탈출
```

대표 예 — **약속의 8회**:

- `ReferenceBehavior [Reference]`: 8회 공격 시작 시 열세면 타격 강화.
- `Trigger`: `Inning == 8 AND ScoreState == Trailing`.
- `ProjectBalanceValue [ProjectOriginal]`: 1~3점차 Contact +6 / Power +6 / Mental +8, 2스트라이크 컨택 +8%p. 4점차 이상 Contact +4 / Power +4 / Mental +6.
- `DurationRule = UntilInningEnd`.

카운터 예:

```text
끈질긴 승부 ↔ 완투의 각오
타선 침묵 ↔ 초반 총공세
불펜 균열 ↔ 불펜 총동원
```

모든 카드에 억지로 Counter를 붙이지 않는다.

## 7. 전술 연구소

새 재화를 만들지 않고 Money를 사용한다.

```text
안정 연구  — 저비용, Normal 위주
승부 연구  — 고비용, Rare/Special 확률 상승
전문 연구  — Category 지정 편중
```

중복 전술카드는 재고 수량으로만 쌓이며 선수 카드처럼 강화하지 않는다. 판매가는 연구 비용보다 낮게 유지한다.

## 8. Signature 전술카드

일반 연구에서 나오지 않는다. 실제 감독 커리어 업적(예: 8회 열세에서 시즌 10회 이상 역전승)으로 해금한다.

능력치 효과는 일반 Special 범위를 크게 넘기지 않고 서사 가치(감독 프로필/뉴스)를 크게 둔다.

## 9. 밸런스 목표

```text
Normal 발동 기대 승률 영향  +0.5~1.5%p
Rare                         +1~3%p
강한 조건부 역전 카드        +3~6%p (조건 불충족 시 0)
```

전술카드가 능력치 격차를 자동으로 뒤집는 수단이 되지 않게 대량 Simulation으로 검증한다.

## 10. AI 감독

AI는 플레이어와 같은 `TacticCardDefinition`, `PositionAssignmentRule`, `BullpenUsagePolicy`를 사용한다.

AI 전술카드 Inventory 가챠는 만들지 않고 `TacticalFacilityLevel`, `ManagerQuality`, `LeagueTier`로 Available Pool을 구성한다.

Personality 예:

```text
AggressiveHitting
BullpenHeavy
StarterTrust
SmallBall
DataDriven
```

벤치 교체와 투수 교체도 Personality/ManagerTacticProfile의 영향을 받지만 공통 규칙을 위반하거나 비주포지션 패널티를 무시할 수 없다.

## 11. 선수 커리어 모드 연결

선수 커리어 모드에서는 감독 AI가:

- 선발 라인업,
- 벤치 교체,
- 비주포지션 기용 여부,
- 선발/불펜/셋업/마무리 교체,
- 전술/전술카드

를 결정한다.

플레이어에게는 "우리 감독이 [약속의 8회]를 발동했다", "대수비 교체로 비주포지션 배치가 발생했다" 등 결과를 Presentation에서 전달할 수 있다. 판정은 Presentation이 아니라 Simulation에서 수행한다.

## 11.1 특수 합성팀의 경기 운영

02절의 AllStar/GoldenGlove/YearSelect 특수 합성팀이 실제 리그 경기에 참가할 때도
일반 AI 구단과 동일한 `ManagerTacticProfile`, `BullpenUsagePolicy`, 교체/포지션 규칙을 사용한다.
특수팀 전용 경기 판정이나 전술 보정은 만들지 않는다.

이 규칙은 게임 시작 전 `SimulatedHistory`의 최초 기록 시뮬레이션에 특수팀을 참가시킨다는 뜻이 아니다.
초기 Historical Simulation은 02/08절대로 원래 정규 구단만 사용한다.

## 12. 검증 기준

- 신규 전술카드 추가 시 Resolver 코드 변경이 필요 없는 데이터 기반 구조인지 검증.
- Counter 카드 동시 발동 시 정확히 상쇄되는지 검증.
- 슬롯 2개/Disruption 최대 1장/동일 카드 중복 금지를 검증.
- 조건 미발동 카드도 경기 확정 시 소모되는지 검증.
- Bullpen1/2가 접전 리드·추격 상황의 우선 후보가 되는지 검증.
- Bullpen3가 애매한 중간 레버리지/추격 상황에서 활용되는지 검증.
- Bullpen4가 패전 상황 및 상위 불펜 체력 부족 시 대체되는지 검증.
- 벤치 교체가 비주포지션을 금지하지 않되 Condition/실책 패널티를 의사결정에 반영하는지 검증.
- DH에 모든 타자 포지션을 배치해도 OffPosition 수비 패널티가 없는지 검증.
- 비본래 PitcherRole 기용 시 Condition 패널티가 적용되는지 검증.
- 동일 Seed에서 교체/불펜/전술 발동 결과가 재현되는지 검증.
- 대량 Simulation에서 전술카드 기대 승률 영향이 §9 범위 안에 드는지 검증.

## 13. 2026-09-02 구현 현황

### 완료된 계약과 집중 검증

- 새 `ManagerTacticProfile` 타입을 중복 추가하지 않고 기존
  `Baseball.Core.Teams.ManagerTacticalProfile`을 재사용했다. 데이터 기반
  `TacticCardDefinition`, Loadout/소모 계약, `TacticTriggerEvaluator`,
  `TacticCardResolver`를 구현했다.
- 슬롯 2개, Disruption 1장, 중복 금지, 조건 미발동 시에도 경기 확정 시 소모, 동일 입력의
  결정론적 순서와 `봉쇄 → Counter → Debuff → Buff`를 테스트했다.
- 반복 타석 Hot Path는 정렬된 Loadout과 재사용 Buffer를 쓰는 `ResolveInto` 경로로 구성했다.
- `DetailedMatchEngine`에 전술 Runtime Modifier와 Assignment/Fielding/Bullpen 공통 규칙을
  연결하고 동일 Seed 결과와 지속 효과 중복 방지를 집중 테스트했다.

### 부분 완료 또는 미완료

- 모든 `BehaviorModifiers`, Stamina, BatterMental 효과가 실제 판정 축에 연결된 것은 아니다.
- 벤치 교체 전체, AI 전술 선택, 전술 연구소/Inventory, Signature 해금은 미완료다.
- 16장 전체 전술 데이터와 Counter 조합을 콘텐츠로 완성하지 않았다.
- 수천~수만 경기의 전술 기대 승률 영향 검증은 실행하지 않았다. 시뮬레이션 코드를 더 개선한
  뒤 §9 범위를 검증한다.

따라서 Phase 6 전술 Lane은 **공통 Resolver와 DetailedMatch 핵심 연결은 완료, 전체 카드 콘텐츠·
AI 운영·통계 밸런스는 부분 완료**다.
