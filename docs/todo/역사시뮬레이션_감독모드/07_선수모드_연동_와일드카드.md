# 07. 선수 커리어 모드와의 연동 — 공통 카드/월드와 Career Player Wildcard

## 0. 목적

선수 커리어 모드가 감독모드와 **같은 Baked 선수·카드·TeamSeason·World History 데이터**를 사용하면서도, 감독모드 전용 카드 소유 경제가 선수 커리어 모드에 유출되지 않도록 경계를 정의한다.

기존의 "선수 커리어 모드는 카드 시스템을 전혀 요구하지 않는다"는 표현은 폐기한다.
정확한 원칙은 다음과 같다.

```text
공통 콘텐츠/월드 데이터        → 두 모드 공용
카드 수집·강화·SP/DP 소유 경제 → 감독모드 플레이어 구단 전용
Career Player 성장 State        → 선수 커리어 주인공 전용
```

## 1. 선수 커리어 모드가 공통으로 사용하는 것

```text
PlayerPersonDefinition
PlayerSeasonDefinition
WorldCardCatalog
TeamSeasonDefinition
CurrentRosterState
WorldHistorySnapshot
WorldAwardRecord
TeamColor
ActiveRosterCompositionRule
PositionAssignmentRule
BullpenUsagePolicy
```

선수 커리어 모드의 일반 구단 선수를 별도 `PlayerDefinition` Pool로 복제하지 않는다.

일반 선수의 경기 경로는 개념적으로 다음과 같다.

```text
PlayerSeasonDefinition / WorldCard
    ↓
PlayerSeasonInstance
    ↓
ActiveRoster / Lineup
    ↓
Match Simulation
```

## 2. 선수 커리어 주인공은 별도 성장형 State

주인공은 고정 시즌 카드가 아니다.

```text
CareerPlayerState
  나이
  성장
  훈련
  노화
  계약
  이적
  컨디션
  실제 시즌 기록
  실제 수상 기록
```

일반 구단 선수의 카드 구조를 주인공에게 강제로 적용하지 않는다.

## 3. WorldRecordMode — 선수모드에도 동일 적용

새 게임에서 선수 커리어 모드도 공통 `WorldRecordMode`를 사용한다.

### SimulatedHistory

Baked 선수/구단을 이용해 게임 시작 이전 과거 기록을 재시뮬레이션하고 Statistics/Award를 만든다.

### OriginalHistory

Historical Simulation을 생략하고 Runtime-safe 고유 기록을 공통 `WorldHistorySnapshot`으로 로드한다.

두 경로 모두 일반 선수의 Edition/TeamColor/Award 기록은 같은 World Record Schema를 사용한다.

**게임 시작 이후 시즌은 두 옵션 모두 실제 게임 Simulation 결과로 진행한다.**
Career Player의 미래 성적과 수상을 고유 기록으로 미리 고정하지 않는다.

## 4. 모든 구단은 공통 TeamSeason/ActiveRoster 구조를 사용

선수 커리어 모드도 02절 규칙을 그대로 사용한다.

```text
TeamSeason = 연도별 고유 구단
ActiveRoster = 25

야수 14
  주전 9
  벤치 5

투수 11
  선발 5
  Bullpen 1~4
  Setup 1
  Closer 1

외국인 <= 3
```

일반 구단 선수 원본은 감독모드와 같은 Baked Definition이다.

모든 TeamSeason은 Rookie에서 시작하고 실제 Simulation 결과로 Rookie → Galaxy까지 승강한다.

### 4.1 리그 정규 10구단 + 특수 합성팀

선수 커리어 모드의 World도 02절 리그 생성 규칙을 그대로 사용한다.

- 한 LeagueInstance의 정규 Franchise 구단 슬롯은 정확히 10개.
- `SimulatedHistory` 최초 과거 기록 생성에는 원래 정규 구단만 참가.
- Award/WorldHistory 확정 뒤 같은 OriginYear 선수풀에서 AllStar/GoldenGlove/YearSelect 합성팀을 구성.
- 세 특수 합성팀 최종 로스터 사이의 동일 `PlayerSeasonId` 중복은 금지.
- 합성팀 생성이 원래 구단의 선수/Origin을 이동시키지 않음.

선수 커리어 주인공은 게임 시작 이후 실제 시즌부터 World 기록에 참여하므로 게임 시작 이전 과거 합성팀 생성을 위해 주인공을 소급 삽입하지 않는다.

## 5. 감독 AI의 라인업/교체 권한

선수 커리어 모드의 플레이어는 라인업, 벤치 교체, 투수 교체, TeamColor 장착, 전술카드를 직접 결정하지 않는다.

감독 AI가 다음을 소유한다.

```text
Starting Lineup
Bench Substitution
Rotation
Bullpen 1~4 Usage
Setup / Closer Usage
TeamColor Slots
Manager Tactic
Tactic Cards
```

### 5.1 비주포지션 교체

감독 AI는 상황에 따라 벤치 선수를 주전과 교체할 수 있다. 실제 등록 포지션과 다른 포지션 기용도 허용한다.

- 야수 비주포지션: 실책 확률 증가 + Condition 하락.
- DH: 어떤 타자도 자유롭게 배치, 수비 비주포지션 패널티 없음.
- 투수 비본래 PitcherRole: Condition 하락.

AI는 이 패널티를 고려해 교체 여부를 결정하며 비주포지션을 무조건 금지하지 않는다.

## 6. Career Player Wildcard — 정체성 계열

주인공은 공통 카드가 아니므로 TeamColor의 Origin을 직접 가지지 않는다. 현재 소속 TeamSeason을 정체성 Wildcard로 사용한다.

```text
if IsCareerPlayerWildcard(candidate):
    effectiveOriginTeamSeasonKey = candidate.CurrentTeam.TeamSeasonKey
    effectiveOriginFranchiseId   = candidate.CurrentTeam.FranchiseId
    effectiveOriginYear          = candidate.CurrentTeam.OriginYear
```

동시에 다음 세 Family에 적용한다.

```text
YearFranchise
Franchise
Year
```

이적하면 현재 소속 TeamSeason 기준으로 자동 변경된다.

## 7. Career Player Wildcard — 명예 계열

주인공의 AllStar/GoldenGlove/Mvp Wildcard는 **실제 World Award를 받았을 때만** 생긴다.

Award 판정은 일반 선수와 동일한 시즌 Statistics 기반 Resolver에 주인공도 함께 참가한다. 주인공 전용 MVP 공식을 만들지 않는다.

```text
AllStar       → 실제 전반기 성적/선정 결과
GoldenGlove   → 실제 시즌 성적/수비 결과
Mvp           → 실제 정규시즌/올스타전/포스트시즌 결과
```

### 7.1 유효 기간

All-Star는 시즌 중 발표되지만 Golden Glove/정규시즌 MVP는 시즌 후 발표되는 차이를 반영한다.

```text
AllStar:
  선정 발표 시점 → 해당 시즌 종료

GoldenGlove:
  수상 발표 시점 → 다음 시즌 종료

Mvp:
  수상 발표 시점 → 다음 시즌 종료
```

한 시즌에 정체성 Wildcard와 명예 Wildcard가 동시에 성립할 수 있다.

## 8. 일반 선수의 Edition은 Wildcard가 아니다

일반 구단 선수는 `WorldCardCatalog`가 제공하는 실제 Edition을 사용한다.

```text
Baked Origin
+ WorldAwardRecord
→ Normal/AllStar/GoldenGlove/Mvp World Card
```

Wildcard는 **Career Player 주인공만** 카드가 아닌 성장형 선수이기 때문에 필요한 예외다.

## 9. 감독모드 Owned State는 절대 유출하지 않는다

선수 커리어 모드에는 다음을 생성/저장하지 않는다.

```text
OwnedPlayerCardState
EnhancementLevel
DuplicateCount
CardTrainingState
SP
DP CardTraining
PityGauge
Card Sale
```

같은 PlayerSeason/Card Definition을 참조해도 감독모드에서 강화한 값이 선수 커리어 모드의 일반 선수 능력치에 영향을 주면 안 된다.

## 10. 능력치 레이어

### 일반 구단 선수

```text
Card BaseStat
+ Edition Modifier
+ TeamColor
+ Condition
+ AI Tactic
= EffectiveRating
```

### Career Player 주인공

```text
Career BaseStat
+ NaturalGrowth
+ Career Training
+ Wildcard TeamColor
+ Condition
= EffectiveRating
```

비주포지션/비본래 역할 기용 시 02절 Assignment Penalty를 추가 적용한다.

## 11. 시스템 필요 여부

| 시스템 | 선수 커리어 모드 |
| --- | --- |
| Offline Baked Player/Season/Card Base | 필요 |
| TeamSeason / Rookie~Galaxy | 필요 |
| ActiveRoster 25인/외국인/포지션 규칙 | 필요 |
| WorldRecordMode / WorldHistorySnapshot | 필요 |
| Runtime Statistics / Award Resolver | 필요 |
| WorldCardCatalog / Edition | 일반 구단 선수에 필요 |
| TeamColor | 필요 |
| CareerPlayerWildcard | 주인공에 필요 |
| ManagerTacticProfile / AI 운영 | 필요 |
| 감독모드 SP Scout | 불필요 |
| OwnedPlayerCardState / 중복 강화 / CardTraining | 불필요 |
| 전술카드 플레이어 직접 선택 | 불필요 — 감독 AI가 사용 |

## 12. 검증 기준

- 선수 커리어 모드 일반 구단 선수가 별도 선수 원본이 아니라 공통 Baked PlayerSeason/WorldCard에서 파생되는지 검증.
- `OriginalHistory`/`SimulatedHistory` 모두 같은 WorldHistory/WorldAward Schema로 선수모드가 초기화되는지 검증.
- 게임 시작 이후 Career Player의 기록/수상이 실제 Simulation으로 누적되는지 검증.
- 주인공의 정체성 Wildcard가 이적 시 현재 TeamSeason으로 자동 갱신되는지 검증.
- AllStar/GG/Mvp Wildcard가 실제 Award가 있을 때만 활성화되고 유효 기간이 정확한지 검증.
- 주인공과 일반 선수가 동일 Award 후보 평가 규칙에 들어가는지 검증.
- ActiveRoster가 25인/14:11/투수 역할/외국인 최대3/Person 중복 금지를 지키는지 검증.
- 선수모드 LeagueInstance의 정규 Franchise 구단 수가 10개인지 검증.
- SimulatedHistory 최초 기록 시뮬레이션에 특수 합성팀이 포함되지 않는지 검증.
- Award 확정 뒤 생성된 세 특수 합성팀끼리 PlayerSeasonId가 중복되지 않는지 검증.
- 감독 AI가 Bullpen1~4 역할과 체력을 고려하는지 검증.
- 비주포지션 야수/비본래 투수 역할을 허용하되 Condition/실책 패널티를 적용하는지 검증.
- 모든 타자가 DH에 배치 가능하고 DH 자체에는 비주포지션 수비 패널티가 없는지 검증.
- 선수 커리어 Save Schema에 OwnedPlayerCardState/Enhancement/Duplicate/CardTraining이 없는지 검증.
- 기존 성장/기용/계약/이적/시즌/저장 테스트가 회귀 없이 통과하는지 검증.

## 13. 2026-09-03 구현 현황

### 완료된 계약과 집중 검증

- `CareerPlayerWildcard`의 현재 소속 기반 YearFranchise/Franchise/Year 정체성과 실제
  `WorldAwardRecord` 기반 AllStar/GoldenGlove/Mvp 명예 자격을 구현했다.
- 이적 시 정체성 갱신, AllStar 당해 시즌 종료, GoldenGlove/Mvp 다음 시즌 종료, 다른 선수
  Award 비활성화를 테스트했다.
- `ICareerBakedContentProvider` 주입 Seam과 명시적 Baked 새 게임 설정을 만들고, Test Provider로
  Baked Core25가 Runtime `TeamGenerator`를 우회하며 같은 Seed에서 같은 일반 선수 ID를 만드는지
  집중 테스트했다.
- Career Save Root가 감독모드 `OwnedPlayerCardState`를 소유하지 않는 경계를 테스트했다.
- 공통 Runtime 정제본은 `UnityHistoricalContentProvider`가 실제 `PlayerPersonDefinition`,
  `PlayerSeasonDefinition`, `TeamSeasonDefinition`, `WorldHistorySnapshot`, `WorldCardCatalog`로
  복원한다. 실명 검수 필드는 Player Build payload에 포함되지 않는다.
- Production 새 게임의 암묵적 Synthetic fallback을 제거했다. Synthetic Career/Team 생성은
  `ExplicitSyntheticTestFixture`를 명시한 개발·테스트 설정에서만 실행된다.

### 부분 완료 또는 미완료

- Editor Bake 정제본을 읽는 공통 Runtime Provider는 있으나, 그 440개 TeamSeason을 기존 Career의
  10단계 동시 리그에 배치하는 Production `ICareerBakedContentProvider`는 아직 없다. 현재 테스트
  Provider는 각 등급에 팀을 미리 넣는데, 이는 “모든 TeamSeason Rookie 시작” 계약을 Production
  정책으로 정당화하지 못한다.
- 따라서 Production Career 새 게임은 잘못된 자동 배치나 Synthetic fallback 대신 명시적으로
  실패한다. `CareerWorldFactory`의 `TeamGenerator`는 테스트 fixture 경로에만 격리되어 있다.
- Career Save에 `WorldHistorySnapshot`, `WorldAwardRecord`, 일반 선수 `PlayerSeasonId`, Natural
  `PitcherRole`을 영속화하는 통합이 미완료다.
- 경기 후 `CurrentRosterState` 유지, 특수 합성팀 참가 Instance, 기존 성장/노화/계약/이적을
  포함한 전체 장기 Career 회귀는 미완료다.

따라서 선수모드 Lane은 **공통 Runtime 원본, Provider 주입 계약, Wildcard와 경제 비유출 경계는
구현됐지만 Career 리그 초기 배치와 디스크 Persistence가 없어 실제 공통 월드 전환은 부분 완료**다.
