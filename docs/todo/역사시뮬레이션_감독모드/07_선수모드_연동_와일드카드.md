# 07. 선수 커리어 모드와의 연동 — Wildcard 범위

## 0. 목적

감독모드 카드/팀컬러 시스템이 기존 선수 커리어 모드를 오염시키지 않도록 접점을 명확히
제한한다. **기본 원칙: 선수 커리어 모드는 이 폴더의 어떤 시스템도 필수로 요구하지 않는다.**
감독모드가 구현되지 않아도 선수 커리어 모드는 그대로 완결된 게임이어야 한다.

## 1. 접점은 정확히 두 곳뿐이다

1. 선수 커리어 모드의 소속 팀이 **감독모드에서 만들어진 TeamSeason**일 수 있다(02절 —
   가상 연도 구단 자체는 두 모드가 공유하는 세계관 데이터).
2. 선수 커리어 모드 주인공에게 **Career Player Wildcard** 판정을 적용해, 자신이 뛰는
   TeamSeason의 팀컬러 인원 수 계산에 자신을 포함시킬 수 있다.

이 두 가지 외에 감독모드의 카드 강화/스카우트/전술카드 경제는 선수 커리어 모드에 전혀
노출되지 않는다.

### 1.1 전제 — 선수 커리어 모드의 게임 세계도 02절의 TeamSeason 구조를 그대로 쓴다

**명시적으로 확정한다:** 02절의 다음 두 규칙은 감독모드 전용이 아니라 **게임 세계 전체에
적용되는 공통 전제**이며, 선수 커리어 모드의 세계도 예외 없이 이 위에서 돌아간다.

1. **모든 구단은 Rookie 리그에서 시작한다.** 선수 커리어 모드의 플레이어가 첫 계약을
   맺는 구단도 예외가 아니다 — `ReferenceStrength`가 높은 역사적 강팀이라도 게임 시작
   시점에는 Rookie이고, 실제 시뮬레이션 결과로만 Rookie → Galaxy까지 승격한다(02절 §4).
   플레이어가 어느 시점에 어느 구단과 계약하든, 그 구단은 그 시점까지 쌓은 실제 승강
   기록을 가진 TeamSeason이다.
2. **모든 구단은 "연도별로 고유한 TeamSeason"으로 구성된다.** `2008 Comets`, `2011 Comets`,
   `2019 Comets`는 같은 Franchise라도 서로 다른 TeamSeason이고, 각자 독립적인
   `TeamSeasonClubState`(02절 §5)와 독립적인 팀컬러 자격(04절, `TeamColorEligibilityKey`의
   `OriginYear`+`OriginFranchiseId`)을 가진다. 선수 커리어 모드에서 플레이어가 "2011
   Comets와 계약했다"는 것은 곧 `TeamSeasonKey = COMETS_2011`인 특정 TeamSeason과
   계약했다는 뜻이며, 같은 Comets라도 다른 연도의 Comets와는 별개 구단으로 취급된다.

이 두 규칙이 선수 커리어 모드에도 적용되기 때문에, §2의 Wildcard(YearFranchise/Franchise/
Year 정체성 계열)가 의미를 가진다 — 애초에 플레이어의 소속팀이 "연도별 고유 TeamSeason"이
아니라면 YearFranchise 조건 자체가 성립하지 않는다.

이 문서의 §2가 `BaseballManager_PROJECT.md` 39절이 예고한 "연도 팀 컬러" 로드맵 항목의
최종 구현 내용이다 — 04절의 실제 팀컬러 수치를 그대로 쓰며, 별도의 축소된 성장/컨디션
보너스 체계를 새로 만들지 않는다.

## 2. Wildcard 범위 — 정체성 계열은 자동, 명예 계열은 실제 수상 필요

Wildcard는 두 그룹으로 나눠 판정 기준을 다르게 둔다. 이유는 단순하다 — **소속(어느
구단·어느 연도에서 뛰는가)은 지금 사실 그대로 정할 수 있지만, 수상(올스타·골든글러브·MVP)은
실제로 그 성과를 낸 사실이 있어야 의미가 있기 때문**이다.

```text
정체성 계열 (자동 Wildcard)     — YearFranchise, Franchise, Year
명예 계열 (실제 수상 필요)       — AllStar, GoldenGlove, Mvp
```

### 2.1 정체성 계열 — 현재 소속팀 기준으로 항상 성립

```text
OriginTeamSeasonKey (선수 커리어 주인공 전용 값) = PLAYER_WILDCARD
```

TeamColorResolver(04절) 판정 시, 정체성 계열 3종(YearFranchise/Franchise/Year) 전부에 대해
동시에 다음을 적용한다.

```text
if IsCareerPlayerWildcard(candidate):
    effectiveOriginTeamSeasonKey = candidate.CurrentTeam.TeamSeasonKey
    effectiveOriginFranchiseId   = candidate.CurrentTeam.FranchiseId
    effectiveOriginYear          = candidate.CurrentTeam.OriginYear
```

- 플레이어가 이적하면 Wildcard가 가리키는 값도 자동으로 바뀐다 — 어느 팀에 가도 그 팀의
  YearFranchise/Franchise/Year 조건을 깨지 않는다.
- 정체성 계열 3종을 **동시에** 만족시킨다(초안에 있던 "한 번에 하나의 Family에만 작동"
  제한은 폐기한다 — 04절이 Family 간 자유 조합을 허용하는 구조로 바뀌었으므로, 셋 중 어느
  조합을 장착하든 플레이어가 그 조건을 깨는 일이 없어야 한다).
- 플레이어도 팀컬러 보너스를 그대로 받는다(팀의 일원으로 취급). 04절 §1.2의
  `TeamColorBonus`가 그대로 적용되며, "개인 성장/컨디션 보너스로 축소"하지 않는다 — 04절의
  실제 팀컬러 수치를 그대로 받는다. 이는 라인업/전술 편성 권한과는 무관하다(플레이어가
  팀을 편성하는 것이 아니라, 감독 AI가 짠 로스터·장착 팀컬러의 결과를 자동으로 공유받을
  뿐이다).

### 2.2 명예 계열 — 실제 수상 기록이 있어야 자격이 생긴다

AllStar/GoldenGlove/Mvp Wildcard는 자동으로 주지 않는다. 선수 커리어 모드 안에서 실제로
해당 수상을 했을 때만 해당 Edition Wildcard 자격을 얻는다. 다만 세 수상의 **발표 시점이
서로 다르므로**, "수상 시즌 한정"을 셋에 똑같이 적용하면 안 된다.

**시상 시점 문제:** All-Star는 시즌 도중(보통 시즌 중반) 선정되므로 "그 시즌 한정" 자격이
실제로 그 시즌 남은 경기에 적용될 기회가 있다. 반면 Golden Glove와 정규시즌 MVP는 보통
**그 시즌이 끝난 뒤** 발표된다 — 수상 시점에는 이미 그 시즌 경기가 없으므로 "그 시즌
한정" 자격을 주면 사실상 아무 경기에도 적용되지 못하고 사라진다. 따라서 시상 시점에 맞춰
적용 구간을 다르게 둔다.

```text
if PlayerCareerRecord.HasAward(AllStar, forSeason):
    선정 발표 시점부터 forSeason 종료까지 AllStar Wildcard 자격

if PlayerCareerRecord.HasAward(GoldenGlove, forSeason):
    forSeason 수상 발표 시점부터 (forSeason + 1) 시즌 종료까지 GoldenGlove Wildcard 자격

if PlayerCareerRecord.HasAward(Mvp, forSeason):
    forSeason 수상 발표 시점부터 (forSeason + 1) 시즌 종료까지 Mvp Wildcard 자격
```

즉 **All-Star는 수상한 그 시즌에만**, **Golden Glove·MVP는 수상 시즌 종료 후 다음 시즌
한 시즌을 더 포함해** 자격을 유지한다 — 이렇게 해야 시즌 후 발표되는 상이 실제 플레이에서
쓸모 있는 효과로 이어진다. 두 시즌이 지나면(즉 다음 시즌마저 끝나면) GG/MVP 자격도
소멸한다. 한 시즌에 여러 해의 수상 자격이 겹칠 수 있다(예: 작년 MVP + 올해 AllStar를
동시에 보유).

실제로 딴 상이 없다면 명예 계열 팀컬러 인원수 계산에 포함되지 않는다.

### 2.3 동시 반영 규칙

정체성 계열(2.1)과 명예 계열(2.2)은 서로 다른 조건이므로 **동시에 성립할 수 있다**. 예를
들어 특정 시즌에 MVP를 받은 플레이어는 그 시즌 한정으로 YearFranchise/Franchise/Year
Wildcard와 Mvp Wildcard를 모두 인정받는다. 다만 04절의 "2슬롯 자유 조합" 규칙 자체는
그대로 적용되므로, 실제로 어떤 팀컬러 2개를 장착할지는 감독 AI가 결정한다(플레이어가
팀컬러 슬롯을 선택하지 않는다 — 07절 §4).

## 3. 감독모드 전용 강화는 절대 유출되지 않는다

`OwnedPlayerCardState.EnhancementLevel`, `DuplicateCount`는 감독모드 세이브에만 존재하는
필드다. 선수 커리어 모드의 `PlayerState`/`PlayerGrowthState`에는 이 필드를 추가하지 않는다.
두 모드가 같은 `PlayerPersonId`/`PlayerSeasonDefinition`을 참조하더라도, 감독모드에서 어떤
카드를 얼마나 강화했는지는 선수 커리어 모드의 능력치 계산에 어떤 경로로도 영향을 주지
않는다.

## 4. 감독모드가 없어도 되는 부분과 있어야 하는 부분

| 시스템 | 선수 커리어 모드 필요 여부 |
| --- | --- |
| 02절 TeamSeason / Rookie~Galaxy 승강 | 필요 (기존 `LeagueGrade` 확장선상) |
| 01절 시대보정/Synthetic 선수 생성 | 필요 (구단·선수 원본 생성에 공용) |
| 04절 팀컬러(정체성 계열) | 필요 — §2.1 Wildcard로 실제 적용 |
| 04절 팀컬러(명예 계열) | 필요 — §2.2 실제 수상 시에만 |
| 03절/05절 카드 수집·강화·스카우트 경제 | 불필요, 감독모드 전용 |
| 06절 전술카드 | 불필요 — 감독 AI 내부 판단으로만 존재(플레이어 조작 없음) |

플레이어는 여전히 어떤 팀컬러 슬롯을 장착할지, 자신을 로스터의 몇 번 타순에 넣을지를
직접 정하지 않는다 — 그 권한은 계속 감독 AI 소유다(`CLAUDE.md` 절대 경계 3번). Wildcard는
"플레이어가 팀 편성에 관여한다"가 아니라 "감독 AI가 이미 짠 편성의 결과값을 플레이어도
동등하게 공유한다"는 의미로 한정한다.

## 5. 검증 기준

- Wildcard 미적용 상태에서 선수 커리어 모드의 기존 테스트(성장/기용/계약 등)가 회귀 없이
  통과하는지 확인 — 즉 이 문서의 변경이 기존 시스템에 사이드이펙트를 만들지 않는지가
  최우선 검증 대상이다.
- 정체성 계열 Wildcard가 이적 시 자동으로 새 TeamSeasonKey를 가리키고, 세 조건
  (YearFranchise/Franchise/Year) 모두에 동시에 반영되는지 테스트.
- 명예 계열 Wildcard 유효 구간이 시상 시점에 맞게 다른지 테스트한다 — AllStar는 수상 시즌
  종료까지만, GoldenGlove/Mvp는 수상 시즌 발표 시점부터 다음 시즌 종료까지 유지되고, 그
  이후에는 자동으로 해제되는지 확인한다.
- 정체성 계열과 명예 계열이 동시에 성립하는 케이스(해당 시즌 MVP 수상)에서 두 보너스가
  모두 올바르게 적용되는지 테스트.
- `OwnedPlayerCardState` 필드가 선수 커리어 모드 세이브 스키마에 전혀 존재하지 않는지
  (직렬화 스키마 검사) 테스트.
- 선수 커리어 모드 세계 생성 시 모든 구단이 Rookie에서 시작하고, 같은 Franchise의 서로
  다른 연도 구단이 서로 다른 `TeamSeasonKey`를 가진 별개 TeamSeason으로 존재하는지(§1.1)
  테스트.
