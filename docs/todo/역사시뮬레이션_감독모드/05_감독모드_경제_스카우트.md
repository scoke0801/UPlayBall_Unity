# 05. 감독모드 경제와 스카우트

## 0. 목적

감독모드 전용 3자원 경제(구단 자금/스카우트 포인트/육성 포인트)와, 선수 카드를 얻는 스카우트
(가챠) 시스템, 중복 카드의 강화/판매 순환을 정의한다. **이 문서의 모든 시스템은 감독모드
전용이며 AI 구단과 선수 커리어 모드에는 적용하지 않는다.**

이 문서는 `BaseballManager_PROJECT.md` 23절("가챠 금지, 카드=UI 표현")을 감독모드에 한해
뒤집는 2026-08-31 확정 결정을 전제로 한다(README.md 참고).

## 1. 3자원 구조

```text
Money (구단 자금)   — 계약, 연봉, FA, 트레이드, 시설, 코치
SP (Scouting Point) — 선수 스카우트 전용. 중복 카드 판매로 일부 회수
DP (Development Point) — 선수 훈련 전용
```

세 재화를 합치거나 상호 환전 가능한 통로를 만들지 않는다(합치면 결국 하나의 재화로 수렴해
경제적 선택이 사라진다).

## 2. 재화 획득

```text
Money  — 경기 수익, 리그 보상, 승격 보상
SP     — 스카우트 부서 시설(주간 생산 + 저장 한도), 감독 미션/업적, 승격 보상
DP     — 훈련 시설(주간 생산), 코치
```

Money로 SP/DP를 직접 구매하는 통로는 두지 않는다. Money는 오직 **SP/DP 생산 시설과 코치를
강화**하는 데만 쓴다. 상위 리그일수록 시설 상한이 높아지지만(Rookie Lv.3 → Galaxy Lv.10),
동시에 선수 연봉·계약 요구도 커져서 자원이 무한 눈덩이가 되지 않게 한다.

## 3. 스카우트(뽑기)

표현은 "카드 뽑기"가 아니라 **스카우팅**으로 통일한다. SP를 사용하면 즉시 카드 1장을 획득한다
(프야매식 즉시 획득 — "후보 발견 후 별도 계약금" 구조는 채택하지 않는다, 재화 역할이 이미
Money/SP로 분리되어 있어 이중 화폐 요구가 불필요하다).

### 3.1 Scout Pool 종류

```text
ScoutPoolDefinition
{
    ScoutType            // General | Franchise | Year | YearFranchise | Award
    FranchiseFilter?
    YearFilter?
    EditionFilter?        // Award 타입 전용: AllStar/GoldenGlove/Mvp만 등장
    CostWeights[]         // Cost 1~10 확률 분포
    EditionWeights[]      // Normal/AllStar/GoldenGlove/Mvp 확률 분포 (Award 제외 시 Normal 위주)
    PriceSP
}
```

| Scout | 필터 | 초기 비용(SP) |
| --- | --- | ---: |
| General | 없음 | 100 |
| Franchise | 구단 | 160 |
| Year | 연도 | 160 |
| YearFranchise | 구단+연도 | 240 |
| Award | Edition 한정(Normal 제외) | 500 |

### 3.2 ScoutRoller 알고리즘 — 필터·Cost·Edition을 하나의 Bucket 추첨으로 통일

**이전 초안의 서술 불일치를 정리한다.** 앞부분은 "Cost를 먼저 굴리고 → 그다음 Edition을
굴린다"는 순차 추첨으로 설명했지만, 후보가 0장인 경우를 처리하는 NoCandidatePolicy(§3.3)는
실제로는 "존재하는 (Cost, Edition) 조합에 `CostWeight × EditionWeight`를 곱해 통째로
재정규화"하는 **Joint Bucket 추첨**을 쓴다. 순차 추첨과 Joint Bucket 추첨은 후보가 모두
존재하는 일반적인 경우엔 같은 결과 분포를 내지만, 문서에 두 알고리즘이 동시에 존재하는
것처럼 보이면 구현자가 헷갈린다. 따라서 **Joint Bucket 추첨을 유일한 정식 알고리즘으로
확정**한다.

```text
ScoutRoller.Roll(pool: ScoutPoolDefinition, rng: IDeterministicRandom) → PlayerCardDefinition

1. 필터 적용        — pool의 FranchiseFilter/YearFilter/EditionFilter로 후보 카드 전체 집합을 구한다.
2. Bucket 구성      — 그 집합에 실제로 존재하는 (Cost, Edition) 조합만 Bucket으로 추출한다.
3. Bucket Weight    — 각 Bucket의 Weight = CostWeights[Cost] × EditionWeights[Edition].
4. 정규화           — 존재하는 Bucket의 Weight 합이 1이 되도록 비례 재정규화한다(§3.3).
5. Bucket 추첨      — 정규화된 Weight로 Bucket 하나를 뽑는다.
6. Bucket 내부 추첨 — 그 Bucket에 속한 카드들(같은 Cost+Edition, 필터를 만족하는 여러 선수) 중
                     균등 확률로 카드 1장을 최종 추첨한다.
```

특정 선수만 확률을 별도로 높이지 않는다 — 희소도는 Cost로, 등급은 Edition으로만 표현하고
Bucket 내부는 항상 균등이다.

```text
Cost 1~10 초기 확률(CostWeights): 12/13/15/15/14/12/8/6/3.5/1.5 (%)

Edition 확률(EditionWeights, General/Franchise/Year/YearFranchise 공통 초기값):
  Normal 97.0% / AllStar 2.0% / GoldenGlove 0.7% / Mvp 0.3%

Award 스카우트 전용 EditionWeights(Normal 미등장):
  AllStar 75% / GoldenGlove 20% / Mvp 5%
```

General/Franchise/Year/YearFranchise 네 Scout는 모두 같은 `EditionWeights`(위 표)를 기본값으로
공유한다 — Phase 5(08절)에서 실제 카드 분포를 관찰한 뒤 필요하면 Scout 종류별로 분리한다.

Franchise/Year/YearFranchise 필터는 **1단계(필터 적용)에서만** 후보를 좁히고, 3단계의
`CostWeights`/`EditionWeights` 자체는 건드리지 않는다 — 즉 "타깃 스카우트를 돌리면
고코스트가 잘 나온다"는 착시를 주지 않는다. 다만 필터링 후 특정 Cost/Edition 조합의 Bucket이
아예 비어 있을 수 있으므로, 그 경우의 정규화 규칙은 §3.3에서 정의한다.

### 3.3 NoCandidatePolicy — 후보 0장 Bucket 처리

Cost와 Edition을 조합하면, 필터링 후 그 Bucket이 비어 있는 경우가 반드시 발생한다(예:
`2011 Comets + Mvp + Cost 10` 카드가 애초에 존재하지 않을 수 있다). 이는 수학적으로
불가피하므로, §3.2의 4단계(정규화)는 다음을 뜻한다.

```text
비어있지 않은 Bucket만 남기고, 그 Bucket들의 Weight 합이 1이 되도록 비례 재정규화한다.
```

"필터를 걸어도 Cost 분포가 절대 변하지 않는다"는 §3.2 원칙은 **해당 필터 아래 실제로
존재하는 (Cost, Edition) Bucket 전체에 한해서**만 성립한다 — 애초에 존재하지 않는 Bucket
까지 확률을 보존할 수는 없다. UI에는 이 스카우트의 **재정규화된 실제 확률**을 표시해, 예를
들어 `YearFranchise` 스카우트에서 Cost 10 카드가 아예 없는 구단·연도 조합이면 "Cost 10:
0%"로 정직하게 보여준다.

### 3.4 Pity Gauge

```text
GaugeGainPerScout   // Scout 1회당 Gauge 증가량, 데이터화(초기값: Scout 종류 무관 10)
```

뽑기마다 `GaugeGainPerScout`만큼 Gauge가 누적되고(초기값 10이면 10회 스카우트마다 1회),
100 도달 시 1회 "집중 스카우트"를 쓸 수 있다. 플레이어가 구단 또는 연도(또는 둘 다) 조건을
선택하면 그 조건 내에서 **Cost 7 이상 확정** 카드를 1장 준다. 특정 선수나 MVP를 확정하지
않는다 — 위시 카드 획득은 여전히 어렵게 유지한다.

**Edge Case:** 플레이어가 선택하려는 필터(예: 특정 `YearFranchise`)에 애초에 Cost 7 이상
카드가 한 장도 없을 수 있다("Cost 7+ 확정"이 수학적으로 불가능한 조합). 따라서 집중
스카우트 UI는 §3.3의 필터-후보 계산을 먼저 돌려 **Cost 7 이상 후보가 최소 1장 존재하는
필터만 선택 가능하게 제한**한다. 후보가 없는 필터는 선택지 자체에 노출하지 않는다(선택
가능한데 결과가 실패하는 상태를 만들지 않는다).

## 4. 중복 카드

동일 카드(`PlayerPersonId` + `OriginYear` + `OriginFranchiseId` + `Edition` 전부 일치) 재획득 시
신규 선수로 등록하지 않고 `DuplicateCount`를 올린다. 플레이어는 다음 중 선택한다.

```text
강화 (동일 카드 1장 소비, 실패 없음, Money/DP 요구 없음)
판매 (SP로 환급)
보관 (즉시 결정하지 않음)
```

### 4.1 강화

```text
+0 → +1 → +2 → +3 → +4 → +5(MAX)
```

한 단계당 ALL +1 (타자 6항목/투수 6항목 전부). 최대 +5. **AI 구단에는 `EnhancementLevel`
필드 자체가 존재하지 않는다** — AI는 항상 Base Card + TeamColor만 사용한다.

### 4.2 판매

```text
기본 판매 SP (Cost 1~10): 3 / 4 / 6 / 8 / 10 / 14 / 20 / 28 / 40 / 55
Edition 보정 배율: Normal ×1.0, AllStar ×1.2, GoldenGlove ×1.4, Mvp ×1.8
```

판매가는 항상 동급 스카우트 비용보다 낮게 유지해 "판매 → 재뽑기"만으로 무한 순환하지
못하게 한다. `+5 MAX` 카드의 추가 중복은 강화 불가이므로 판매만 가능 — UI에서 이를 강하게
안내한다.

### 4.3 자동 판매

기본값 `MAX_DUPLICATE_ONLY`(+5 완료 카드의 추가 중복만 자동 판매). `OFF`/`ALL` 옵션도
제공하되 강화 가능한(미완성) 카드는 자동 판매 대상에서 절대 제외한다.

## 5. 훈련(DP)

**03절의 "카드는 나이를 먹지 않는다" 원칙 때문에, 감독모드 카드 훈련은 선수 커리어 모드의
`GrowthResolver`(나이·성장곡선·노화 기반)를 그대로 재사용하지 않는다.** 대신 시즌 카드마다
파생되는 능력치별 벡터 `PlayerSeasonDefinition.TrainingCeiling`(03절 §1.1 — Person 공통
`PersonPotentialTrait`이 아니라 **그 시즌의 BaseStat+Cost로 파생된 값**)만으로 성장 여지를
계산하는 별도의 축소 Resolver를 만든다.

```text
CardTrainingBonus[ability] = TrainingResolver.Resolve(
    currentEffectiveBase: BaseStat[ability] + CardTrainingBonus[ability],  // 훈련 전 누적치
    ceiling: TrainingCeiling[ability],  // 예: ContactCeiling — 이 시즌 카드 고유, 이후 불변
    programIntensity, dp)
```

DP는 능력치에 직접 `+N`을 붙이지 않고 훈련 프로그램(기간, 소모, 피로 부담, 성장 확률)을
실행하는 비용으로 쓴다. 훈련 효율은 능력치별로 `현재 누적치`와 그 능력치의 `*Ceiling`
사이의 거리로 체감한다(잠재치에 가까울수록 어려워진다) — 나이·성장곡선 입력은 없다.
`TrainingCeiling`이 시즌마다(Cost마다) 다르므로, 같은 인물이라도 저코스트 시즌 카드를 DP만으로
고코스트 시즌 카드 수준까지 키울 수 없다(03절 §1.1의 Headroom 스케일). Contact는 쉽게 크는데
Power는 거의 안 크는 카드처럼 능력치별로 다른 성장 여력도 표현된다.

`GrowthBalanceTable`의 체감 곡선 형태(수확체감 공식)는 참고해 재사용할 수 있지만, 입력
변수(나이 등)까지 그대로 가져오지 않는다.

## 6. 카드 컬렉션의 귀속

`OwnedPlayerCardState`와 그 강화 상태는 **구단(TeamSeason)에 귀속**된다. 감독이 다른
TeamSeason으로 이적하면 기존 컬렉션은 이전 구단에 남고, 새 구단에서는 새 컬렉션을
시작한다. 계정 귀속(감독이 카드를 들고 다니는 방식)은 만들지 않는다 — "구단을 키웠다"는
의미를 유지하기 위함이다.

## 7. AI 로스터 — Core25는 초기값일 뿐, AI도 로스터를 계속 바꾼다

**Core25(02절 §3)는 TeamSeason 생성 시점의 초기 1군일 뿐이다.** 시즌이 진행되면 AI 구단의
실제 1군은 `CurrentRosterState`(AI 전용, `OwnedPlayerCardState`와 무관한 별도 상태)로
관리하며, 다음은 AI에게 계속 허용한다.

```text
허용 — 트레이드, 방출/영입(스카우트가 아닌 일반 이적 시장), 특수 Edition 카드 활용,
       TeamColor를 고려한 로스터 최적화, Club DNA(02절)에 따른 영입 우선순위
금지 — 스카우트(SP 가챠), 중복 카드 강화(+0~+5), DP 소비 훈련
```

AI는 "가챠로 카드를 늘리지 않을 뿐" 로스터 편성 자체는 계속 살아 있게 움직인다 — 그렇지
않으면 시즌이 누적될수록 강화(+5)와 DP를 쌓는 플레이어만 강해지고 AI가 정적으로 고착돼
Galaxy 최상위 경쟁이 무너진다. AI의 로스터 최적화는 02절의 Club DNA 가중치와 04절
TeamColorResolver의 기대 보너스를 함께 평가해 결정한다(05절 §"영입 판단"과 04절
TeamColorResolver를 공유 — 새 AI 전용 판정 로직을 별도로 만들지 않는다).

이 비대칭(플레이어만 카드 강화/스카우트 가능) 때문에 장기적으로 플레이어 구단이 유리해지는
것은 감독모드의 의도된 성장 곡선이다 — 단 AI도 로스터 편성으로 계속 경쟁력을 조정하므로
Galaxy 최상위 AI가 무의미해지지 않는다.

### 7.1 AiEditionUnlockPolicy — AI의 특수 Edition 획득 규칙

AI는 스카우트도 `OwnedPlayerCardState`도 없으므로, "AI가 언제 Normal 대신 AllStar/GG/Mvp
Edition을 쓰는가"를 별도로 정의해야 한다.

```text
AiEditionUnlockPolicy
{
    // 해당 PlayerSeasonDefinition이 역사적으로 그 Edition을 실제로 획득했다면
    // (예: 그 시즌 실제로 올스타/골든글러브/MVP로 선정된 카드라면),
    // 해당 TeamSeason의 CurrentRosterState는 Normal 대신 그 Edition 카드를 기본 보유한다.
}
```

즉 AI는 "스카우트로 특수 카드를 뽑는" 것이 아니라, **자기 소속 선수가 실제로 그 시즌
수상자라면 그 Edition을 자동으로 쓴다.**

**정정:** 이전 초안은 "Edition을 쓰면 YearFranchise 조건 인원이 깨질 수 있다"고 썼는데,
이는 03절 §4("Origin은 Edition과 무관하게 유지된다")와 모순이다 — AllStar/GoldenGlove/Mvp
카드는 Normal 카드와 동일한 `OriginYear`/`FranchiseId`/`TeamSeasonKey`를 유지하므로, Edition을
바꿔도 YearFranchise/Franchise/Year 팀컬러 자격은 절대 깨지지 않는다. 실제 선택 문제는 다른
곳에 있다.

- 한 `PlayerPersonId`(그 시즌 카드)가 가질 수 있는 특수 Edition이 **하나뿐**이면 그 Edition은
  Normal보다 모든 면에서 우위이므로 AI가 Normal을 고를 이유가 없다 — 항상 그 Edition을 쓴다.
- 만약 04절 §7~§9의 특수 팀컬러(AllStar덱/GoldenGlove덱/MVP덱)까지 고려할 때 **같은 선수가
  이론상 여러 Edition을 동시에 만족할 수 있는 상황**(예: 그 시즌 AllStar이면서 동시에
  GoldenGlove인 선수 — 카드 자체는 Edition마다 별도 1장이므로 이 경우 실제 선택 문제가
  생긴다)이라면, `AiRosterOptimizer`는 "이 카드를 AllStar Edition으로 쓸 때"와 "GoldenGlove
  Edition으로 쓸 때" 각각의 개인 능력치 + 두 특수 팀컬러 기대 보너스를 비교해 더 유리한
  Edition을 로스터에 등록한다(둘 다 Normal보다는 항상 우위이므로 Normal은 후보에서 제외).

## 8. 데이터 모델

```text
Baseball.Core
  ScoutPoolDefinition
  OwnedPlayerCardState        // 플레이어 감독모드 전용
  CurrentRosterState          // AI 전용, 시즌별 로스터 변화 (§7)
  ManagerEconomyState (Money/SP/DP 잔고, 시설 레벨)

Baseball.Simulation
  ScoutRoller              // Cost → Edition → 카드 추첨, NoCandidatePolicy 재정규화 포함
  CardEnhancementResolver  // 중복 소비 → 강화 단계 갱신
  CardSaleResolver         // 판매가 계산
  CardTrainingResolver     // 시즌별 TrainingCeiling 기반 능력치별 고정 성장, GrowthResolver와 별개 (§5)
  AiRosterOptimizer        // Club DNA + TeamColorResolver 기대값 기반 AI 로스터 편성 (§7)
```

## 9. 검증 기준

- **필터 없는(General) Scout** 또는 **모든 Cost/Edition 조합이 실제로 존재하는 Pool**에서는
  결과 분포가 원본 `CostWeights`/`EditionWeights`와 대량 시행(예: 100만 회) 결과에서 허용
  오차 안에 들어오는지 통계 테스트.
- **일부 (Cost, Edition) 조합이 존재하지 않는 필터 Pool**(예: 특정 `YearFranchise`에 Cost
  10 카드가 없는 경우)에서는, §3.3의 재정규화 규칙으로 계산한 `ExpectedWeights`(존재하는
  조합만 남기고 비례 재정규화한 값)와 실측 분포가 일치하는지 통계 테스트. "필터 유무와
  무관하게 Cost 분포가 항상 동일하다"는 기준은 쓰지 않는다 — §3.3에서 확정했듯 이는
  후보가 실제로 존재하는 조합에 한해서만 성립한다.
- 동일 Seed 재현성(같은 시드 + 같은 SP 소비 순서 → 같은 카드 시퀀스) 테스트.
- 강화 최대 단계(+5) 도달 후 추가 중복이 강화되지 않고 판매만 가능한지 테스트.
- AI `OwnedPlayerCardState`가 항상 비어 있거나 존재하지 않는지(강화 로직이 AI 경로에서
  절대 호출되지 않는지) 회귀 테스트.
- 필터로 후보가 0장이 되는 (Cost, Edition) 조합에서 NoCandidatePolicy 재정규화가 정확히
  동작하고 확률 합이 항상 1이 되는지 테스트.
- `CardTrainingResolver`가 나이·성장곡선 입력 없이 시즌별 `TrainingCeiling`만으로 성장을
  계산하며, 기존 `GrowthResolver`(선수 커리어 모드)를 호출하지 않는지 회귀 테스트.
- 같은 인물의 저코스트 시즌 카드를 DP로 최대한 훈련해도 동일 인물의 고코스트 시즌 카드
  BaseStat 수준을 넘어서지 않는지 테스트(03절 §1.1 Headroom 스케일 검증).
- 여러 시즌을 시뮬레이션했을 때 `CurrentRosterState`가 Core25와 달라질 수 있는지(AI가
  실제로 로스터를 갱신하는지), 그러면서도 AI 경로에서 스카우트/강화/DP Resolver가 호출되지
  않는지 테스트.
- 집중 스카우트(Pity Gauge) UI가 Cost 7+ 후보 0장인 필터를 선택지에서 실제로 제외하는지
  테스트.
- `AiEditionUnlockPolicy`가 실제 수상 기록이 있는 `PlayerSeasonDefinition`에만 Edition 카드를
  부여하고, AI 경로에서 스카우트/뽑기 없이 이 카드가 등장하는지 테스트.
