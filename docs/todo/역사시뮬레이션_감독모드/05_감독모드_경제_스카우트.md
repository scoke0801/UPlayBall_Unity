# 05. 감독모드 경제와 스카우트

## 0. 목적

감독모드 플레이어 구단 전용 3자원 경제와 스카우트, 중복 강화/판매, 카드 훈련을 정의한다.

중요한 경계:

- `PlayerPersonDefinition`/`PlayerSeasonDefinition`/`WorldCardCatalog`는 선수 커리어 모드와 감독모드가 공통으로 사용한다.
- **이 문서의 소유 경제만 감독모드 플레이어 구단 전용**이다.
- AI 구단과 선수 커리어 모드 일반 선수에게 `OwnedPlayerCardState`, SP Scout, Enhancement, DP CardTraining을 붙이지 않는다.

## 1. 3자원 구조

```text
Money (구단 자금)       — 계약, 연봉, FA, 트레이드, 시설, 코치
SP (Scouting Point)     — 선수 스카우트 전용, 중복 카드 판매로 일부 회수
DP (Development Point)  — 감독모드 카드 훈련 전용
```

세 재화를 합치거나 직접 환전하는 통로를 만들지 않는다.

## 2. 재화 획득

```text
Money  — 경기 수익, 리그 보상, 승격 보상
SP     — 스카우트 시설 주간 생산/저장, 감독 미션·업적, 승격 보상
DP     — 훈련 시설 주간 생산, 코치
```

Money로 SP/DP를 직접 구매하지 않는다. Money는 SP/DP 생산 시설과 코치를 강화하는 데 사용할 수 있다.
상위 리그는 시설 상한을 늘리되 연봉/계약 요구도 함께 상승시킨다.

## 3. 스카우트

표현은 "카드 뽑기"보다 **스카우팅**으로 통일한다. SP를 사용하면 즉시 카드 1장을 획득한다.

스카우트의 후보 원본은 해당 Save의 **공통 `WorldCardCatalog`**다. `OriginalHistory`인지
`SimulatedHistory`인지 ScoutRoller가 직접 분기하지 않는다.

- Normal: Baked PlayerSeason에서 항상 존재.
- AllStar/GoldenGlove/Mvp: 현재 World의 `WorldAwardRecord` 때문에 활성화된 Edition만 후보가 된다.

### 3.1 Scout Pool

```text
ScoutPoolDefinition
{
    ScoutType            // General | Franchise | Year | YearFranchise | Award
    FranchiseFilter?
    YearFilter?
    EditionFilter?       // Award: AllStar/GoldenGlove/Mvp
    CostWeights[]
    EditionWeights[]
    PriceSP
}
```

| Scout | 필터 | 초기 비용(SP) |
| --- | --- | ---: |
| General | 없음 | 100 |
| Franchise | 구단 | 160 |
| Year | 연도 | 160 |
| YearFranchise | 구단+연도 | 240 |
| Award | 특수 Edition 한정 | 500 |

### 3.2 ScoutRoller — Joint Bucket 단일 알고리즘

```text
ScoutRoller.Roll(pool, worldCardCatalog, rng)

1. WorldCardCatalog에 Filter 적용
2. 실제 존재하는 (Cost, Edition) Bucket만 구성
3. Weight = CostWeights[Cost] × EditionWeights[Edition]
4. 빈 Bucket 제거 후 비례 재정규화
5. Bucket 추첨
6. Bucket 내부 카드는 균등 추첨
```

특정 선수만 별도 확률 가중치를 주지 않는다.

```text
Cost 1~10 초기 확률:
12 / 13 / 15 / 15 / 14 / 12 / 8 / 6 / 3.5 / 1.5 (%)

General/Franchise/Year/YearFranchise Edition 초기값:
Normal 97.0% / AllStar 2.0% / GoldenGlove 0.7% / Mvp 0.3%

Award Scout:
AllStar 75% / GoldenGlove 20% / Mvp 5%
```

Phase 4의 Normal-only 구현 기간에는 `EditionWeights = Normal 100%`로 고정하고 특수 Edition은 Phase 5 이후 활성화한다(08절).

### 3.3 NoCandidatePolicy

필터 후 존재하지 않는 (Cost, Edition) 조합은 Bucket에서 제거하고 남은 Weight를 합 1로 재정규화한다.

```text
ExpectedWeight(bucket) = RawWeight(bucket) / Σ RawWeight(non-empty buckets)
```

UI에는 재정규화된 실제 확률을 표시한다. 예를 들어 특정 YearFranchise에 Cost 10이 없으면 0%로 표시한다.

### 3.4 Pity Gauge

```text
GaugeGainPerScout = 10   // 초기값, 데이터화
```

100 도달 시 1회 집중 스카우트를 사용한다. 플레이어가 구단/연도/둘 다를 선택하고 해당 조건 내 **Cost 7 이상 확정** 카드 1장을 얻는다.

Cost 7+ 후보가 없는 필터는 선택지 자체에서 제외한다.

## 4. 중복 카드

동일 카드 재획득 기준은 Stable CardId 또는 동등한 `(PlayerSeasonId + Edition)` 식별자를 사용한다.

```text
강화
판매
보관
```

### 4.1 강화

```text
+0 → +1 → +2 → +3 → +4 → +5(MAX)
```

단계당 모든 주 능력치 +1, 실패 없음, 별도 Money/DP 요구 없음.
AI와 선수 커리어 모드에는 EnhancementLevel이 없다.

### 4.2 판매

```text
기본 판매 SP (Cost 1~10): 3 / 4 / 6 / 8 / 10 / 14 / 20 / 28 / 40 / 55
Edition 배율: Normal ×1.0, AllStar ×1.2, GoldenGlove ×1.4, Mvp ×1.8
```

판매가는 재스카우트 무한 순환이 되지 않도록 동급 Scout 기대 비용보다 낮게 유지한다.

### 4.3 자동 판매

기본값 `MAX_DUPLICATE_ONLY`. +5 완료 카드의 추가 중복만 자동 판매한다. 강화 가능한 카드는 자동 판매하지 않는다.

## 5. 카드 훈련(DP)

감독모드 카드는 나이를 먹지 않으므로 선수 커리어 `GrowthResolver`를 재사용하지 않는다.

```text
CardTrainingBonus[ability] = CardTrainingResolver.Resolve(
    current: BaseStat[ability] + accumulatedBonus,
    ceiling: TrainingCeiling[ability],
    program,
    dp)
```

나이/노화/GrowthCurve를 입력하지 않는다. 성장 여지는 03절의 시즌별 TrainingCeiling만 사용한다.

## 6. 카드 컬렉션 귀속과 외국인 카드

`OwnedPlayerCardState`는 감독모드에서 **구단(TeamSeason)에 귀속**된다. 감독이 다른 TeamSeason으로 이적하면 기존 Collection은 원 구단에 남는다.

외국인 카드는 Collection에 몇 장이든 보유할 수 있다. 제한은 02절 ActiveRoster의 외국인 최대 3명 등록에만 적용한다.

```text
Foreign Card 보유 10장 → 허용
ActiveRoster Foreign 3명 → 허용
ActiveRoster Foreign 4명 → 거부
```

Scout Pool도 외국인 보유 수를 이유로 후보를 제거하지 않는다.

## 7. 감독모드 플레이어 ActiveRoster

감독모드 플레이어의 실제 1군은 02절 공통 `ActiveRosterCompositionRule`을 반드시 만족해야 한다.

```text
25명
야수 14 = 주전 9 + 벤치 5
투수 11 = 선발 5 + Bullpen 1~4 + Setup 1 + Closer 1
외국인 <= 3
동일 PlayerPersonId 중복 금지
```

포지션 불일치는 등록 실패 사유가 아니다. 타자를 다른 수비 포지션에 배치하거나 투수를 다른 PitcherRole로 운용할 수 있지만 02절의 Condition/실책 패널티를 적용한다. DH는 어떤 타자도 자유롭게 맡을 수 있다.

## 8. AI 로스터 — 공통 카드, 별도 소유 경제 없음

AI의 실제 1군은 `CurrentRosterState`로 관리한다.

허용:

```text
트레이드
방출/일반 이적시장 영입
WorldCardCatalog의 특수 Edition 활용
TeamColor 고려
Club DNA 고려
공통 Roster/Position/Bullpen Rule 사용
```

금지:

```text
SP Scout
OwnedPlayerCardState
Duplicate Enhancement
DP CardTraining
```

AI는 Core25에서 출발하되 시즌이 진행되면 로스터를 계속 최적화한다.

### 8.1 AiRosterOptimizer의 강제 제약

AI가 전력이 높은 조합을 찾더라도 다음을 위반할 수 없다.

- 25인 / 14:11 / 투수 역할 수.
- 외국인 최대 3명.
- 동일 PlayerPersonId 중복 금지.

반면 포지션 불일치는 **금지 조건이 아니다.** AI는 비주포지션 기용으로 얻는 공격/투수 이득과 Condition/수비 실책 비용을 비교한다.

### 8.2 불펜 1~4 운용

AI의 Bullpen 배치 및 경기 중 선택은 02/06절 `BullpenUsagePolicy`를 사용한다.

```text
Bullpen 1 / 2 — 필승조 + 추격조
Bullpen 3     — 애매한 상황 + 추격조
Bullpen 4     — 패전조 + Bullpen 1~3 체력 부족 시 대체
```

정확한 상황 임계값은 데이터화한다.

### 8.3 AiEditionUnlockPolicy

AI는 `PlayerSeasonDefinition`에 Bake된 고정 수상 플래그를 읽지 않는다.

```text
WorldAwardRecord
    ↓
WorldCardCatalog
    ↓
AiEditionUnlockPolicy / AiRosterOptimizer
```

현재 World에서 수상 자격이 활성화된 Edition만 사용할 수 있다. OriginalHistory와 SimulatedHistory를 AI 내부에서 따로 분기하지 않는다.

한 PlayerSeason에 여러 특수 Edition이 활성화된 경우 개인 능력치 + TeamColor 기대값을 비교해 더 유리한 Edition을 선택할 수 있다.

## 8.4 특수 합성팀은 Scout/Owned Economy 대상이 아니다

02절의 AllStar/GoldenGlove/YearSelect 특수 합성팀은 `SpecialCompositeTeamBuilder`가
`WorldHistorySnapshot`/`WorldCardCatalog`와 해당 연도 전체 선수풀을 입력으로 구성한다.

- 합성팀을 만들기 위해 SP Scout를 돌리지 않는다.
- `OwnedPlayerCardState`를 생성하지 않는다.
- `AiRosterOptimizer`가 Award 확정 전에 합성팀을 임의 생성하지 않는다.
- 세 특수 합성팀끼리 동일 `PlayerSeasonId`가 겹치지 않는 규칙은 02절 Builder가 책임진다.
- 원래 Franchise 구단의 카드 보유/CurrentRosterState는 합성팀 생성 때문에 제거·이동되지 않는다.

## 10. 검증 기준

- General 또는 모든 Bucket이 존재하는 Pool에서 대량 Scout 결과가 원본 Weight 허용 오차 내인지 검증.
- 빈 Bucket이 있는 Pool에서 재정규화된 ExpectedWeight와 실측 분포가 일치하는지 검증.
- 같은 Scout Seed/SP 소비 순서에서 카드 시퀀스가 동일한지 검증.
- `OriginalHistory`와 `SimulatedHistory` 모두 ScoutRoller가 동일한 WorldCardCatalog API만 소비하는지 검증.
- Award 없는 PlayerSeason의 특수 Edition이 Scout Pool에 들어오지 않는지 검증.
- 강화 +5 상한/실패 없음/추가 중복 판매 동작 검증.
- AI/선수 커리어 경로에서 OwnedPlayerCardState, Enhancement, CardTraining이 호출되지 않는지 검증.
- CardTrainingResolver가 나이/노화 없이 TrainingCeiling만 사용하는지 검증.
- 외국인 카드 보유 수 무제한과 ActiveRoster 3명 제한이 분리되어 있는지 검증.
- AI와 플레이어 ActiveRoster가 02절 25인/역할/외국인/중복 규칙을 동일하게 통과하는지 검증.
- 비주포지션이 로스터 편성 단계에서 무조건 거부되지 않고 기대 패널티가 AiRosterOptimizer 평가에 포함되는지 검증.
- Bullpen4가 패전 상황 및 상위 불펜 체력 부족 시 실제 대체 후보가 되는지 검증.
- Pity 100과 Cost 7+ 후보 없는 필터 제외를 검증.

## 11. 2026-09-02 구현 현황

### 완료된 계약과 집중 검증

- `OwnedPlayerCardState`, `ManagerEconomyState`, `ScoutPoolDefinition`과 Scout/강화/판매/
  CardTraining/AI Roster Resolver를 구현했다.
- Phase 4의 Normal 100%, Award Scout 비활성 정책, Joint Bucket, 빈 Bucket 재정규화,
  결정론, Pity/Cost 7+, 강화 +5, MAX 이후 자동 판매, TrainingCeiling을 테스트했다.
- Joint Bucket 통계 테스트는 100,000회 표본으로 실행해 구성된 기대 Weight 허용 범위에
  수렴함을 확인했다. 이는 전체 콘텐츠의 최종 Scout 밸런스 확정이 아니라 Resolver 분포
  검증이다.
- 감독모드 Save Adapter는 플레이어 Franchise에만 Owned Economy를 노출하고 Career State가
  이를 소유하지 않는 경계를 집중 테스트했다.

### 부분 완료 또는 미완료

- 실제 Manager Mode 진입/주간 경제/시설/UI를 관통하는 전체 Runtime Flow는 아직 없다.
- `WorldCardCatalog` 기반 Award Edition 정책은 Resolver에 있으나 실제 시즌 월드 생성에서
  Award Scout/AiEditionUnlockPolicy를 끝까지 소비하는 통합은 부분 완료다.
- AI `CurrentRosterState`가 경기 후·시즌 후 계속 영속되는 전체 경로와 장기 전력 최적화 통계는
  미완료다.
- 1,000,000회 장기 Scout 및 경제 인플레이션 검증은 코드 개선 후 수행한다.

따라서 Phase 4는 **Normal-only 경제 규칙과 100,000회 Resolver 검증은 완료, 실제 감독모드 경제
루프는 부분 완료**다.
