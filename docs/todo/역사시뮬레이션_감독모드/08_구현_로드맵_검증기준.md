# 08. 구현 로드맵과 검증 기준

## 0. 전제

`README.md`의 2026-09-01 최신 확정을 전제로 한다.

핵심은 다음 순서를 지키는 것이다.

```text
Offline에서 선수/소속/Cost/TrainingCeiling/고유 기록 Bake
        ↓
공통 TeamSeason / ActiveRoster / Card Base
        ↓
Normal 경로 안정화
        ↓
WorldRecordMode + Statistics/Award + 특수 Edition
        ↓
감독모드/선수모드 공통 Runtime 연결
```

Runtime에서 Synthetic 선수/원소속을 생성하지 않는다.

## 1. Phase 순서

```text
Phase 1  Offline Reference Pipeline + Synthetic Player/Career/Season 생성 + Origin 배정
         + Cost/TrainingCeiling + Runtime-safe Original Record + Content Bake (01절)

Phase 2  TeamSeason + Core25 + 공통 ActiveRosterCompositionRule
         + 외국인 최대3 + 비주포지션/투수 역할 패널티
         + LeagueInstance 정규 Franchise 10구단 규칙
         + Rookie~Galaxy + Club DNA (02절)

Phase 3  공통 Player/Season/Card Base 모델 + Normal 카드
         + YearFranchise/Franchise/Year TeamColor
         + 공통 EffectiveRating 경로 (03·04절 일부)

Phase 4  Normal-only 감독모드 경제/Scout/중복강화/판매/CardTraining
         + AI CurrentRoster 최적화
         (EditionWeights = Normal 100%, Award Scout 미사용) (05절)

Phase 5  WorldRecordMode(New Game) + WorldHistorySnapshot
         + Historical Simulation / Original Record Loader
         + Season Statistics 기반 AllStar/GG/MVP Resolver
         + Award 확정 후 AllStar/GoldenGlove/YearSelect 특수 합성팀 생성
         + WorldCardCatalog 특수 Edition
         + 특수 TeamColor + Award Scout + AiEditionUnlockPolicy

Phase 6  감독 전술/벤치 교체/불펜 운용/전술카드 (06절)
         + 선수 커리어 공통 카드/월드 연동과 CareerPlayerWildcard (07절)
         + Golden Generation/Dynasty
```

Phase 3~4에서 Normal 경로를 먼저 안정화한 뒤 Phase 5에서 World Award와 특수 Edition을 얹는다.

## 2. 병렬화와 순차 의존

### 2.1 순서가 필요한 핵심 경로

```text
Reference/Generation Config
→ Offline Synthetic Player/Season
→ Origin/TeamSeason 배정
→ Cost/TrainingCeiling
→ Core25 Validation
→ Bake
→ Shared Card Base
→ World Record Provider
→ Statistics
→ Awards
→ SpecialCompositeTeamBuilder
→ Special Edition
→ Honor TeamColor / Award Scout / AI Edition
```

후행 단계가 선행 데이터에 의존하는 구간은 순서를 지킨다.

### 2.2 병렬 가능한 작업

- Offline 생성 단계에서 서로 독립적인 연도/검증 Job.
- Phase 2에서 League/DNA와 Roster Rule 구현.
- Phase 3에서 Card Model과 TeamColor 기본 Family.
- Phase 4에서 Economy/Scout와 CardTraining, AI Roster Test.
- Phase 5에서 OriginalHistory Loader와 Historical Simulation Harness는 공통 Output Schema를 먼저 확정한 뒤 병렬 구현 가능.
- Phase 2 이후 06절의 `ManagerTacticProfile`/BullpenUsagePolicy 기반 AI 작업 일부를 병렬 착수 가능.
- 선수 커리어의 공통 Card/Roster 연결은 Phase 3 이후 시작할 수 있으나 명예 Wildcard/Award 연결은 Phase 5를 기다린다.

## 3. Phase 1 완료 기준 — Offline Bake

- Synthetic 선수 분포가 Reference와 통계적으로 유사.
- 실존 선수 유사도 Reject 통과.
- 같은 Generation Seed/버전에서 동일 Stable ID/ContentHash.
- PlayerSeason의 BaseAttributes/Origin/Cost/TrainingCeiling이 최종 Bake에 존재.
- Runtime-safe Original Season/Award Record가 실제 식별자 없이 연결됨.
- Runtime Game Flow에서 SyntheticCareer/Player/Team Generator 호출 경로 없음.
- OriginFranchise/TeamSeason은 Bake 후 World Seed에 따라 바뀌지 않음.

## 4. Phase 2 완료 기준 — TeamSeason / Roster / League / DNA

### 4.1 Core25 / ActiveRoster

모든 Core25가 다음을 만족한다.

```text
25명
야수 14 = 주전9 + 벤치5
투수 11 = 선발5 + Bullpen4 + Setup1 + Closer1
외국인 <= 3
동일 PlayerPersonId 중복 없음
```

### 4.2 포지션

- 야수 비주포지션 기용 허용.
- 비주포지션 야수 실책 확률 증가 + Condition 하락.
- DH는 모든 타자가 패널티 없이 사용 가능.
- 비본래 PitcherRole 기용 허용 + Condition 하락.
- 포지션 불일치를 Roster Validation 하드 실패로 처리하지 않음.

### 4.3 불펜

```text
Bullpen1/2 = 필승조 + 추격조
Bullpen3   = 애매한 상황 + 추격조
Bullpen4   = 패전조 + 상위 불펜 체력 부족 시 대체
```

정확한 임계값은 데이터 기반.

### 4.4 League / DNA

- 한 `LeagueInstance`의 정규 Franchise 구단 슬롯이 정확히 10개.
- 특수 합성팀은 정규 10구단 슬롯에 산입하지 않고 Award/History 확정 후 별도 배치.
- 모든 TeamSeason Rookie 시작.
- 10,000 TeamSeason 승강 Simulation에서 ReferenceStrength와 승격 속도에 통계적 상관.
- League Grade 직접 능력치 보정 없음.
- TeamSeasonClubState 시즌 변화폭 ±5.
- 같은 Franchise의 다른 TeamSeason DNA 상호 간섭 없음.

## 5. Phase 3 완료 기준 — 공통 Card Base / 기본 TeamColor

- 선수 커리어 모드와 감독모드가 같은 PlayerPerson/PlayerSeason/Card Base를 참조.
- Cost 1~10 백분위 구간 정확.
- 이 Phase에서 활성 카드는 Normal만 사용 가능.
- `PlayerPersonId` 동일 카드 ActiveRoster 중복 금지.
- YearFranchise/Franchise/Year 단계 경계 정확.
- TeamColor 2슬롯 자유 조합 및 카드별 적용 대상 정확.
- 외국인/비주포지션 여부가 Origin TeamColor 자격을 임의로 제거하지 않음.
- 일반 구단 카드와 Career Player 주인공의 EffectiveRating 경로가 분리됨.
- HardCap 140, SoftCap 120 초기 구조 동작.

## 6. Phase 4 완료 기준 — Normal-only 감독모드 경제

- EditionWeights = Normal 100%.
- Award Scout 비활성.
- Joint Bucket / NoCandidate 재정규화 정확.
- Cost 분포 대량 시행 검증.
- Pity 100, Cost7+ 후보 없는 필터 제외.
- 강화 +5, 실패 없음.
- 판매 무한 순환 방지.
- CardTraining이 Career GrowthResolver를 호출하지 않음.
- 외국인 카드 보유 수 제한 없음.
- 플레이어/AI CurrentRoster는 공통 25인/외국인/역할 규칙 준수.
- AI에는 Scout/Enhancement/CardTraining 없음.

## 7. Phase 5 완료 기준 — World Record / Award / Special Edition

### 7.1 WorldRecordMode

```text
SimulatedHistory
  Baked Player/Team → Historical Simulation → Statistics → Awards

OriginalHistory
  Baked Original Record → WorldHistorySnapshot
```

두 경로는 같은 `WorldHistorySnapshot`/`WorldAwardRecord` Schema로 수렴한다.

- OriginalHistory에서 HistoricalSeasonSimulator 호출 0회.
- SimulatedHistory에서 고유 Award를 그대로 복사하지 않음.
- SimulatedHistory 결과는 최초 생성 후 Save되고 Load 때 재실행하지 않음.
- SimulatedHistory 최초 Historical Simulation 참가팀은 원래 정규 Franchise 구단뿐이며 특수 합성팀은 0개.
- WorldHistory/Award 확정 전에는 SpecialCompositeTeamBuilder를 실행하지 않음.
- OriginalHistory도 Original Record를 WorldHistorySnapshot으로 변환한 뒤 같은 Builder를 사용.

### 7.2 Award

- All-Star: 실제 전반기 Statistics + Position quota.
- Golden Glove: 실제 시즌 Statistics/수비 지표 기반, P/C/1B/2B/3B/SS 각1 + OF3 + DH1.
- Regular MVP: 실제 정규시즌 Statistics 기반.
- All-Star Game MVP: 실제 올스타전 Simulation 결과 기반.
- Postseason MVP: 실제 포스트시즌 출전/Statistics 기반.
- BaseAttributes만으로 수상자를 직접 뽑는 `SyntheticAwardResolver` 경로 없음.

### 7.3 특수 합성팀

- 같은 OriginYear의 정규 구단 전체 선수풀을 입력으로 AllStar/GoldenGlove/YearSelect 각 1팀 생성.
- 각 특수팀은 공통 25인 Roster Rule을 만족.
- 세 특수팀의 최종 25인 사이 동일 `PlayerSeasonId` 중복 0.
- 중복 해소는 `AllStar → GoldenGlove → YearSelect` 우선순위 + Stable Sort/결정론 RNG 사용.
- 특수팀 배정은 원래 TeamSeason의 Core25/Origin/CurrentRoster를 이동·변조하지 않음.
- 특수팀 카드의 TeamColor는 합성팀 이름이 아니라 원래 Origin/Edition으로 판정.

### 7.4 Edition / Consumer

- 특수 Edition은 WorldAwardRecord가 있을 때만 활성화.
- 같은 PlayerSeason의 Edition은 Cost/Origin 동일.
- Golden Glove TeamColor 기본 조건 8명.
- AllStar/GG HighestOnly StackPolicy 정확.
- MVP 10/20 등 의도된 Stackable 유지.
- Scout/AiEdition/TeamColor/Career 모두 `WorldRecordMode`를 직접 분기하지 않고 공통 WorldCard/Award를 소비.

## 8. Phase 6 완료 기준 — 전술 / 교체 / 선수모드 / Legacy

### 8.1 전술/교체

- 전술카드 조건/Counter가 데이터 기반.
- 경기당 슬롯2, Disruption1, 조건 미발동 카드도 소모.
- 벤치 교체가 비주포지션을 허용하면서 Condition/실책 리스크를 평가.
- Bullpen1~4 운영 우선순위와 체력 대체가 데이터 기반으로 작동.
- 비본래 PitcherRole Condition 패널티 적용.

### 8.2 선수 커리어

- 일반 구단 선수는 공통 WorldCard를 사용.
- Career Player는 성장형 State 유지.
- 선수모드에도 공통 25인/외국인/포지션/불펜 규칙 적용.
- 정체성 Wildcard는 현재 소속 TeamSeason으로 갱신.
- 명예 Wildcard는 실제 World Award에만 반응.
- AllStar는 해당 시즌 종료까지, GG/MVP는 다음 시즌 종료까지 유효.
- 선수 커리어 Save에 OwnedPlayerCardState/Enhancement/Duplicate/CardTraining 없음.
- 기존 성장/계약/기용/저장 Regression 전부 통과.

### 8.3 Legacy

Golden Generation/Dynasty는 실제 플레이/World 기록으로만 발생하며 사전 Ability만으로 부여하지 않는다.

### 미실행 또는 완료 판정 제외

- Tactic 수천~수만 경기, 승강 10,000 TeamSeason, Endgame EffectiveRating 분포는 이번 작업의
  미실행 장기 Gate다.
- Production Career Baked 리그 배치와 Career 디스크 Save가 없으므로 공통 Baked 원본을 사용한
  성장/노화/계약/이적 전체 장기 회귀는 아직 실행 대상 자체가 완성되지 않았다.
- Unity의 정확한 GC Allocation Counter를 현재 실행 환경에서 사용할 수 없어 Full World 보고값은
  0으로 표시하지 않고, 별도로 관측한 Unity 프로세스 Peak Working Set을 참고값으로 기록했다.
- 후속 순수 C# 변경은 `Baseball.Core`/`Baseball.Simulation`/`Baseball.Game` 컴파일과 targeted
  회귀로 재검증했다. 최종 Runtime Historical Content Provider Unity EditMode 테스트는 9/9 통과했다.

## 15. Editor Asset 생성 및 Runtime 경계

현재 Bake 에셋은 다음 공식 단일 Editor 경로에만 생성한다.

```text
Assets/Editor Default Resources/HistoricalSimulation/1982-2025/
  manifest.json
  player_persons.json
  Years/1982.json ~ Years/2025.json
  Runtime/manifest.json
  Runtime/player_persons.json
  Runtime/Years/1982.json ~ Runtime/Years/2025.json
```

루트 `manifest.json`의 `assetArchiveHash`는
`25ea34ebc305f0456fbbfd4c2c7686b40af07b48d6d0d1ecd90f5ae5ead45937`, Editor 원본 Bake
`ContentHash`는 `a68d07194dac5d06c67158287d01b1bf70bc3e830224828cf39b1e2eca744bed`다.
파일별 SHA-256, 재조립 결과, 동일 Seed 재생성 전후 46개 파일 바이트 일치를 확인했다.

`Runtime/` 정제본의 `assetArchiveHash`는
`400993aeeef23ec348df8cc078334e7ef0f7adac9bbfb8f03d32abb61d5676b4`, `ContentHash`는
`df7d4eab7596057b86cf6dfd822677026146aa097f4d1ccc7003f88ce3d37d09`다. Runtime Exporter는 이
정제본만 Player Build TextAsset으로 복사한다.

- `EditorGUIUtility.Load`/`LoadRequired`로 Editor Tool이 읽는 재생성 가능 Asset이다.
- Runtime Exporter는 `Assets/10.Datas/HistoricalSimulation/1982-2025/`에 정제본만 복사하고
  `HistoricalRuntimeContentCatalog.asset`에 연결한다.
- `Resources/NewGame/NewGameDefinition.asset`은 JSON을 경로로 재검색하지 않고 Catalog Asset을
  직렬화 참조한다. 이 의존성으로 Player Build에 payload가 포함된다.
- Runtime Provider는 같은 내용을 최초 1회 파싱·검증한 뒤 불변 `HistoricalBakedContent`를 캐시한다.
