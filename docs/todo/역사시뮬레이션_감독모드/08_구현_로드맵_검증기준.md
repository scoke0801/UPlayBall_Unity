# 08. 구현 로드맵과 검증 기준

## 0. 전제

`README.md`의 2026-08-31 확정(감독모드 신설, 가챠·강화 감독모드 전용, 선수 커리어 모드
기존 구조 유지)을 전제로 Phase 1부터 바로 착수한다.

## 1. Phase 순서

```text
Phase 1  KBO 시대보정 + SyntheticCareerGenerator/SyntheticPlayerGenerator + Synthetic Team 생성 (01절)
Phase 2  TeamSeason + Rookie~Galaxy 승강 + FranchiseIdentityProfile/TeamSeasonClubState (02절)
Phase 3  카드 데이터 모델 정의(Cost, Edition 타입 4종) + Normal 카드만 실제 생성,
         팀컬러 Family 6종 중 YearFranchise/Franchise/Year만 우선 구현 (03절, 04절 일부)
Phase 4  Normal 카드 한정 감독모드 경제 + 스카우트 + 중복강화/판매 (05절, EditionWeights는
         Normal 100%로 시작 — Award Scout는 Phase 5로 미룬다)
Phase 5  AllStar/GoldenGlove/Mvp Edition 실제 생성 + Edition 확률 분포 + Award Scout +
         해당 특수 팀컬러 + AiEditionUnlockPolicy (03절 나머지, 04절 나머지, 05절 §3.2/§7.1)
Phase 6  전술카드 (06절), 선수모드 연동(07절), Golden Generation/Dynasty(02절 §6)
```

Phase 3~4를 Normal 카드만으로 먼저 끝내는 이유는, Edition 확률·Award Scout·특수 팀컬러
(04절 §7~§9)까지 한 번에 얹으면 "카드 모델 자체가 맞는지"와 "특수 카드 확률/밸런스가
맞는지"가 뒤섞여 검증하기 어렵기 때문이다. Normal 경로가 먼저 안정화된 뒤 Phase 5에서
Edition을 얹는다.

각 Phase는 앞 Phase가 통계적으로 검증된 뒤에만 착수한다(`CLAUDE.md`의 "밸런스 수치를
바꿨다면 대량 시뮬레이션 근거 필수" 원칙을 그대로 적용).

## 2. Phase별 완료 기준

### Phase 1

- Synthetic 생성 선수 집단의 분포가 Reference 분포와 통계적으로 유사함을 EditMode 테스트로
  확인.
- 동일 Seed 재현성 확인.
- 실존 선수 유사도 검사(01절 §6)를 통과하지 못하는 조합이 최종 산출물에 남지 않음을 확인.

### Phase 2

- 10,000 TeamSeason 규모 승강 시뮬레이션에서 `ReferenceStrength`와 실제 승격 속도의 상관관계
  확인(강제 순위 없이 확률적 경향으로).
- Club DNA 변화폭이 시즌당 ±5를 넘지 않음을 테스트.
- 리그 등급이 능력치에 직접 배율을 곱하지 않음을 코드 검증(Rookie 배율 금지 원칙).

### Phase 3

- Cost 백분위 구간이 설정값과 일치하는지 테스트.
- `PlayerCardDefinition.Edition` 타입이 4종(Normal/AllStar/GoldenGlove/Mvp)으로 정의되어
  있으나, 이 Phase에서 실제로 생성되는 카드는 Normal뿐인지 확인(Edition 생성 로직은 Phase
  5에서 켠다).
- 04절 §4~§6(YearFranchise/Franchise/Year) 각 단계 경계값 테스트.
- 2슬롯 자유 조합 시 각 팀컬러가 조건을 만족하는 카드에만 정확히 적용되고, 조건을 만족하지
  않는 카드에는 해당 팀컬러 보너스가 새지 않는지 테스트(예: YearFranchise+Franchise 동시
  장착 시 2011 Comets 선수는 두 보너스를 모두 받고, 타 연도 Comets 선수는 Franchise
  보너스만 받는지).

### Phase 4

- Cost 확률 분포(§05절 §3.2)를 Normal 카드 기준 대량 시행으로 검증하고 실측치를 이 폴더
  문서에 근거로 남긴다. Edition 확률 검증은 Phase 5로 미룬다(이 Phase의 EditionWeights는
  Normal 100%로 고정).
- 강화 +5 상한, 실패 없음, AI에 강화 필드가 존재하지 않음을 테스트.
- 판매가가 항상 동급 스카우트 비용보다 낮음을 검증(무한 순환 방지).
- Pity Gauge가 100에서 정확히 발동하고 Cost 7 이상을 보장하는지, Cost 7+ 후보가 없는
  필터는 선택지에서 제외되는지 테스트.

### Phase 5

- 특수 Edition 카드가 원본 Normal 카드와 동일한 `OriginYear`/`FranchiseId`/`TeamSeasonKey`를
  유지하는지 테스트.
- `SyntheticAwardResolver`(01절 §5.2)의 AllStar/GoldenGlove/Mvp 선정 로직(연도당 인원 수
  상한, 포지션 쿼터, MVP 후보 부족 시 슬롯 비움)이 지켜지는지 테스트.
- Edition 확률 분포(§05절 §3.2, Award Scout 포함)를 대량 시행으로 검증하고 실측치를 문서에
  근거로 남긴다.
- 04절 §7~§9 팀컬러 경계값 테스트(Golden Glove는 8명 조건 기준).
- MVP 카드 자체 보너스 + MVP덱 보너스 합산이 의도한 상한을 넘지 않는지 확인.
- `AiEditionUnlockPolicy`가 실제 수상 기록이 있는 카드에만 Edition을 부여하는지 테스트.

### Phase 6

- 전술카드 조건 평가/카운터 상쇄가 데이터 기반으로 동작하고 신규 카드 추가 시 Resolver
  코드 변경이 필요 없는지 확인.
- 대량 시뮬레이션으로 카드별 기대 승률 영향이 06절 §6 목표 범위 안에 드는지 확인.
- 선수 커리어 모드 기존 테스트 스위트가 전부 회귀 없이 통과하는지 확인(07절 §6).
- Golden Generation/Dynasty 판정이 실제 플레이 결과에서만 발생하고 사전 정의 콘텐츠로
  대체되지 않는지 확인.

## 3. 공통 자동 테스트 카테고리

`CLAUDE.md`의 4대 테스트 범주를 이 기능에도 동일하게 적용한다.

```text
규칙 테스트     — TeamColor 단계 경계, Cost 구간, Edition 선정 인원 상한, 2슬롯 자유 조합의
                카드별 적용 대상 정확성
결정론 테스트   — 동일 Seed로 생성/스카우트/승강/전술발동 결과가 완전히 일치
통계 테스트     — 대량 시뮬레이션 결과가 목표 범위(승률 영향, Cost 분포, 승강 상관관계) 안
기록 집계 테스트 — 감독모드 세이브의 카드 보유/강화 상태와 UI 표시 합계 일치
```

## 4. 문서 간 의존 관계

```text
01 (Synthetic 생성)
  → 02 (TeamSeason/Club DNA)
    → 03 (카드 모델/Cost/Edition)
      → 04 (팀컬러)
        → 05 (경제/스카우트) — 04, 03에 의존
        → 06 (전술카드) — 02의 감독 AI 전술 성향에 의존
      → 07 (선수모드 연동) — 04, 02에 의존, 05/06과는 무관
```

07절은 05·06절 구현 여부와 무관하게(즉 감독모드 경제/전술카드가 아직 없어도) 02·04절만으로
착수할 수 있다 — 선수 커리어 모드에 필요한 최소 집합이 02·04이기 때문이다.
