Mandatory

필수 지시 사항

본 작업은 카드 훈련·구단 정보 두 화면만 수정하는 작업이 아니다.

프로젝트에 존재하는 구단주 모드 내 모든 UI를 전수조사하고, 발견되는 모든 화면·팝업·탭·오버레이·공통 상태를 개선 대상으로 등록하여 수정한다. 아래 화면 목록은 조사 시작용 기준이며 최종 범위를 제한하지 않는다.

  • 필요한 신규 프레임, 버튼, 탭, 배지, 게이지, 아이콘, 텍스처 및 배경 이미지는 ImageGen으로 생성한다.
  • 기존 캐릭터·선수 카드·구단 로고는 자산 정체성을 유지하며, 별도 승인 없이 교체하지 않는다.
  • 화면마다 임의 스타일을 만들지 않고 본 문서의 공용 토큰과 Prefab을 우선 사용한다.
  • Unity Editor 실행, Play Mode, Edit Mode 및 에디터 기반 테스트는 진행하지 않는다.
  • 에디터 테스트 미진행으로 인해 런타임 배치·앵커·9-Slice·폰트 폴백은 후속 확인 항목으로 명시한다.
Diagnosis

현황과 개선 목표

동일한 사각형의 반복

검색창, 정보 셀, 말풍선, 버튼이 같은 남청색 면으로 보여 기능적 차이가 없다.

과도한 중첩 프레임

화면→패널→하위 패널→셀을 모두 테두리로 감싸 엑셀·툴 UI처럼 보인다.

미설계 공백

카드 그리드 옆과 정보 패널 중앙의 공백이 의도된 여백보다 미완성 영역처럼 보인다.

혼재된 시각 언어

고전적인 금색 코너, 회색 기본 패널, 현대적인 카드 FX가 서로 다른 제품처럼 충돌한다.

목표 경험

“야구 구단의 업무 공간”이라는 맥락은 살리되, 장식이 기능을 덮지 않는 프리미엄 PC 매니지먼트 UI를 지향한다. 정보 밀도는 유지하고, 시선이 화면 제목 → 핵심 지표 → 선택 대상 → 다음 행동 순서로 흐르게 한다.

Inventory First

구단주 모드 UI 전수조사

디자인 변경 전에 코드와 리소스를 기준으로 실제 화면 목록을 확정한다. 기획서에 알려진 화면만 골라 수정하는 방식은 금지한다.

진입 경로 조사
구단주 모드 메인 메뉴, 하단·상단 내비게이션, 버튼 이벤트, 라우터, 씬 전환 경로를 수집한다.
UI 자산 조사
Scene, Prefab, View/Presenter, Canvas, Addressables, Resources, Sprite Atlas에서 UI 후보를 검색한다.
상태 변형 조사
기본·Hover·Pressed·Selected·Disabled·Loading·Empty·Error·Locked·Reward 상태를 별도 항목으로 기록한다.
인벤토리 표 작성
화면 ID, 진입 경로, Prefab, 담당 스크립트, 해상도, 공용 컴포넌트, 문제점, 수정 여부를 매핑한다.
누락 화면 편입
조사 중 아래 기준 목록에 없는 화면이 발견되면 신규 범위로 즉시 추가한다.

전수조사 완료 조건

모든 진입 버튼이 화면 인벤토리의 대상 ID와 연결되고, 모든 UI Prefab 또는 View가 어느 화면에 사용되는지 역방향으로 추적되어야 한다. 고아 Prefab과 미연결 화면도 별도로 기록한다.

Design System

공용 디자인 시스템

표면 깊이: 3단계만 사용

레벨역할표현 규칙
Level 0페이지 배경구장·클럽하우스 이미지 + 75~88% 어두운 오버레이. 정보 가독성을 방해하지 않는다.
Level 1주요 콘텐츠 Surface남청색 반투명 면, 1px 외곽선, 미세 텍스처. 화면당 2~4개 권장.
Level 2조작·선택 컴포넌트입력, 탭, 버튼, 선택 카드에만 높이·음영·강조를 부여한다.

공용 Prefab 후보

UI_Surface / SectionHeader

대형 패널과 아이콘·제목·보조 설명·구분선을 통일한다.

UI_Input / Dropdown / FilterChip

검색·필터 조작의 높이, 패딩, 상태 이미지를 통일한다.

UI_Button_Primary / Secondary

금색 핵심 행동과 남청색 보조 행동을 분리한다.

UI_StatRow / KpiCard

현재 값, 예상 값, 증감, 게이지 표현을 재사용한다.

UI_BadgeSlot / RewardItem

업적·우승·보상·잠금 상태를 공용화한다.

UI_Dialog / Tooltip / Toast

확인·경고·도움말과 시스템 피드백을 일관화한다.

UI_Empty / Loading / Error

데이터가 없을 때 큰 빈 패널이 남지 않게 한다.

UI_FocusFrame

키보드·게임패드 포커스를 마우스 Hover와 구분한다.

9-Slice 및 이미지 사용 규칙

  • 프레임은 모서리 장식과 테두리가 늘어나지 않도록 Sprite Border를 지정한다.
  • 금색 코너 장식은 최상위 Surface 또는 핵심 모달에만 사용하고 셀마다 반복하지 않는다.
  • 질감은 텍스트 대비를 떨어뜨리지 않는 3~8% 불투명도로 제한한다.
  • 버튼 상태는 Default, Hover/Focus, Pressed, Disabled, Selected를 모두 준비한다.
  • 그림자와 Glow는 정보 우선순위 표현에만 사용하며 장식 목적으로 중첩하지 않는다.
Screen Direction

대표 화면별 개선 방향

카드 훈련

  • 카드 그리드 컨테이너 폭을 실제 열 수에 맞추고 남는 공백을 제거한다.
  • 필터는 밝은 기본 Image 대신 입력형 컴포넌트로 통일한다.
  • 우측은 선택 카드, 기본 정보, 현재→예상 능력치, 비용, 훈련 CTA 순으로 정렬한다.
  • 상승 수치는 금색 예상 막대와 초록색 증감치로 표현한다.

구단 정보

  • 로고·구단명·연고지를 구단 ID Hero 카드로 통합한다.
  • 명성·팬 기반은 숫자만 있는 빈 패널 대신 게이지로 시각화한다.
  • 시즌 기록은 121승 22패를 중심으로 재편하고 보조 지표는 한 줄로 압축한다.
  • 누적 기록은 트로피·승격·강등 배지 슬롯으로 표현한다.
  • 매니저 도움말은 캐릭터에 연결된 말풍선으로 변경한다.

Asset Production

ImageGen 이미지 제작 지침

신규 UI 시각 자산은 ImageGen으로 제작한다.

임시 Unity 기본 Sprite를 최종 리소스로 사용하지 않는다. 먼저 화면 시안으로 전체 방향을 검증한 뒤, 프레임·버튼·탭·배지 등 실제 적용 가능한 단위 자산을 별도로 생성한다.

제작 대상

화면 시안, 대형 Surface 프레임, 검색·필터 프레임, Primary/Secondary 버튼, 탭, KPI 배경, 업적 배지, 보상 슬롯, 말풍선, 툴팁, 상태 아이콘, 빈 화면 일러스트, 구장·클럽하우스 배경, 미세 금속·직물 텍스처.

단위 자산 생성 규칙

  • 화면 목업과 실제 자산 생성 요청을 분리한다.
  • 텍스트는 Unity TMP로 출력하므로 프레임·버튼 이미지에는 원칙적으로 문자와 숫자를 굽지 않는다.
  • 아이콘은 의미별로 한 장씩 생성하거나 규격화된 시트로 생성하고 배경 투명도를 요청한다.
  • 9-Slice 자산은 중앙부가 균일하고 모서리 장식이 독립되도록 요청한다.
  • 기존 선수 카드와 캐릭터는 레퍼런스 이미지로 제공하고 외형 보존을 명시한다.
  • 생성 결과는 실제 알파 채널, 가장자리, 반복 텍스처, 작은 크기 가독성을 확인한 후 적용한다.
Execution

구현 절차

단계작업종료 조건
1. Inventory전체 화면·Prefab·상태·경로 전수조사진입점↔화면↔Prefab 추적표 완성
2. Foundation색·간격·폰트·Sprite·상태 토큰 정의임의 값 대신 공용 토큰 사용 가능

4. Pilot카드 훈련·구단 정보 우선 교체두 화면에서 스타일·밀도 규칙 확정
5. Rollout전수조사표 순서대로 구단주 모드 전체 확장모든 대상 상태가 완료 또는 사유 기록
6. Static QA참조 누락, Sprite 설정, 컴포넌트 사용, 텍스트 구조 정적 확인검수표와 잔여 위험 작성

우선순위

P0 글로벌 셸·내비게이션·공용 버튼·모달 → P1 홈·경기·선수·라인업·성장 → P2 구단 운영·연습게임·시즌 전환 → P3 설정·도움말·예외 상태 순으로 진행한다.

Definition of Done

검수 및 완료 기준

  • 전수조사표의 모든 항목이 완료, 제외, 보류 중 하나로 표시되고 제외·보류 사유가 있다.
  • 기본 Unity UI Sprite 또는 임시 단색 Image가 최종 노출 화면에 남아 있지 않다.
  • 화면의 Primary CTA는 원칙적으로 하나이며 Secondary와 시각적으로 구분된다.
  • 패널 깊이가 3단계를 넘지 않고, 동일 정보군은 박스보다 간격과 구분선으로 묶인다.
  • 검색, 필터, 탭, 버튼, 모달의 크기와 상태 표현이 모든 화면에서 일관된다.
  • Loading, Empty, Error, Disabled, Locked 상태가 큰 빈 패널로 방치되지 않는다.
  • 선수 카드·매니저·구단 로고 등 기존 핵심 자산의 정체성이 보존된다.
  • 신규 이미지의 파일명, 용도, 규격, 9-Slice Border, 생성 프롬프트가 자산 목록에 기록된다.
  • 화면 구조 변경으로 기존 버튼 이벤트와 데이터 바인딩이 누락되지 않았음을 코드상 확인한다.
해상도 기준

프로젝트 기준 해상도를 우선 적용하고, 최소한 16:9의 1920×1080과 2560×1440 설계를 고려한다. Safe Area, Canvas Scaler, 긴 한국어 문자열, 숫자 자릿수 증가에 대한 여유를 레이아웃에 포함한다.

Explicit Exclusion

테스트 범위 및 제외 사항

에디터 테스트는 진행하지 않는다.

본 작업 범위에서는 Unity Editor를 실행하지 않으며, Play Mode·Edit Mode·Game View·Prefab Mode·실기기 실행을 통한 테스트도 수행하지 않는다. 가능한 검증은 파일 구성, 코드 참조, 직렬화 필드, 명명, 리소스 경로 등 정적 확인으로 한정한다.

후속 에디터 확인이 필요한 위험

  • Canvas Scaler와 해상도별 앵커·레이아웃 결과
  • 9-Slice Border와 Sprite Import 설정의 실제 렌더링
  • TMP 폰트 폴백, 줄바꿈, 긴 문자열, 숫자 오버플로
  • Hover·Pressed·Selected·Disabled·게임패드 Focus 상태
  • ScrollRect, Mask, 카드 풀링, 애니메이션 및 트윈
  • 버튼 이벤트, 데이터 바인딩, 팝업 스택, 뒤로가기
  • Draw Call, Atlas, 이미지 메모리 및 로딩 성능

따라서 정적 작업 완료는 런타임 정상 동작을 보증하지 않는다. 위 항목은 후속 에디터 검증 단계의 인수인계 체크리스트로 전달한다.
