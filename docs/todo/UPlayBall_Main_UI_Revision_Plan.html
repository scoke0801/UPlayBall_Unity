1. 수정 방향

메인 화면의 최우선 목적은 다음 경기를 시작하는 것이다. 매니저 시스템은 별도 콘텐츠가 아니라 현재 상태를 해석하고 관련 메뉴로 연결하는 보조 내비게이션으로 동작한다.

전역 내비게이션상단 통합 헤더에서 목적지를 직접 선택한다.
진행 대시보드오늘의 경기와 시즌 현황을 우측에서 확인한다.
상황별 추천프런트 매니저가 현재 필요한 행동 하나를 제안한다.
운영 기록매니저 리포트에서 이전 분석과 미확인 항목을 관리한다.
핵심 원칙: 경기 시작 > 추천 행동 > 상태 확인 > 기록 열람 순으로 시각적 강도를 설정한다.

2. 현행 문제

문제영향수정 원칙
클릭 지점과 출력 위치 불일치우측 하단 버튼을 눌렀지만 중앙 하단에 팝업이 등장해 연결감이 약함클릭한 대시보드 안에서 확장
캐릭터와 대화창 분리매니저가 설명한다는 인상보다 이미지가 겹쳐 보임초상을 카드 내부 구성요소로 편입
행동·기록·공지 혼재투수진 확인, 다음 안내, 보관, 운영 소식의 우선순위가 불명확현재 추천과 기록 메뉴 분리
서로 다른 UI 문법남색 버튼, 흰 표, 검은 대화창이 한 화면에서 충돌네이비·차콜·아이보리·골드 디자인 토큰 통일
배경 과도한 차폐더그아웃 공간의 분위기와 몰입감 저하좌측 60% 이상 비차폐

3. 통합 헤더

상태 바와 메뉴 바를 완전한 한 줄로 합치지 않는다. 하나의 연속된 헤더 셸 안에 역할이 다른 두 밴드를 유지한다.

구역내용권장 규격
상태 밴드로고, 구단주 모드, 구단명, 시즌·주차·리그, 자금, 스카우트/육성 포인트, 1군 정원, 저장, 설정48–52px
내비게이션 밴드홈, 선수단, 전력보강, 메이커, 구단, 리그, 상점48–56px
전체동일 좌우 그리드와 배경을 사용하는 하나의 헤더96–104px
  • 개별 메뉴의 두꺼운 박스와 광택을 제거한다.
  • 선택된 탭만 골드 아이콘·텍스트·2~3px 하단선으로 표시한다.
  • 저장은 큰 하단 버튼이 아닌 상단 유틸리티 아이콘으로 이동한다.
  • 1280px 이하에서는 자금 외 재화 명칭을 아이콘 툴팁으로 축약한다.

4. 메인 대시보드

순서컴포넌트역할
1오늘의 경기라운드·홈/원정·상대·전력을 표시하고 경기 시작을 제공
2프런트 매니저가장 시급한 운영 제안 한 건과 관련 화면 바로가기 제공
3시즌 현황리그, 전력, 선수 정원을 한 줄로 요약
CTA 규칙: 화면 전체의 1차 CTA는 항상 경기 시작이다. 프런트 매니저의 추천 버튼은 2차 CTA로 두되, 카드 안에서는 가장 강하게 표시한다.

5. 프런트 매니저 카드

5.1 접힘 상태

[작은 매니저 초상] 프런트 매니저 미확인 7 > 최근 원정 경기에서 불펜 실점이 높습니다. [투수진 점검]

기본 화면에서는 한두 줄만 표시한다. 긴 설명, 보관, 다음 안내는 노출하지 않는다.

5.2 펼침 상태

  • 헤더: 프런트 매니저 / 안내 1·7 / 매니저 리포트 / 접기
  • 본문: 근거 요약과 질문형 제안, 최대 2줄
  • 주 행동: 관련 메뉴로 이동하는 버튼 1개
  • 보조 행동: 나중에 보기, 다음 안내
  • 초상은 카드 내부 좌측에 배치하며 본문 가독성을 침범하지 않는다.

5.3 명칭 변경

현재변경이유
구단 운영 안내프런트 매니저기능이 아니라 말하는 주체를 강조
보관한 안내 보기매니저 리포트분석 기록의 누적성을 표현

8. 데이터 명세

ManagerReportData reportId: string category: GamePrep | PowerAnalysis | Roster | Growth | Finance | Schedule priority: Normal | Important | Critical titleKey: string bodyKey: string recommendationKey: string evidenceItems: List<EvidenceItem> destination: MenuRoute createdAt: GameDate readState: Unread | Read isBookmarked: bool expiresAt: GameDate? deduplicationKey: string

생성·중복 방지 규칙

  • 동일 deduplicationKey의 미확인 리포트는 새로 생성하지 않고 근거 수치와 생성일만 갱신한다.
  • Critical은 최대 1건, Important는 최대 3건까지 메인 추천 후보로 유지한다.
  • 행동 시점이 지난 리포트는 자동 만료하고 기록에는 확인 완료 상태로 남긴다.
  • 버튼 목적지는 메뉴뿐 아니라 탭, 필터, 대상 선수 ID까지 포함할 수 있어야 한다.
  • 표시 문구와 판정 조건을 분리해 로컬라이징 및 밸런스 수정이 가능해야 한다.

10. 검수 기준

레이아웃

  • 2048×1152에서 좌측 배경 58% 이상이 주요 패널에 가려지지 않는다.
  • 헤더 전체 높이는 화면의 10%를 넘지 않는다.
  • 우측 패널은 안전 여백 24px 이상을 유지한다.
  • 1280×720에서도 본문 글자 14px 상당, 주요 버튼 44px 이상의 클릭 높이를 확보한다.

사용성

  • 메인 진입 후 1초 이내에 다음 경기와 경기 시작 버튼을 식별할 수 있다.
  • 매니저 추천을 열고 관련 메뉴로 이동하기까지 2회 이하의 클릭만 필요하다.
  • 미확인, 중요, 보관 상태가 색상만이 아니라 점·아이콘·텍스트로도 구분된다.
  • 리포트에서 뒤로와 닫기의 결과가 서로 다르며 예측 가능하다.

예외 처리

  • 추천 없음: “현재 확인할 중요 제안이 없습니다”와 리포트 바로가기만 표시한다.
  • 경기 없음: 오늘의 경기 카드를 다음 일정 또는 오프시즌 할 일 카드로 교체한다.
  • 목적지 잠김: CTA를 비활성화하지 말고 잠금 사유와 해금 조건을 표시한다.
  • 저장 직후 화면을 복원할 때 펼침 상태가 아닌 기본 메인 상태로 진입한다.
최종 완료 정의: 메인 화면에서 경기 진행, 상황별 추천, 운영 기록의 세 역할이 서로 경쟁하지 않고 하나의 우측 대시보드 흐름으로 인식되어야 한다.
