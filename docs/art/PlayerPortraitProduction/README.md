# 선수 피규어 초상화 양산 지침

## 현재 배경 생성 규약

향후 생성 원본은 후속 투명 도구 처리를 위해 **균일한 단색 크로마키 배경**을 사용한다.
기본은 녹색 `#00FF00`이며 의상 등 전경에 녹색이 있으면 마젠타 `#FF00FF` 등 겹치지 않는 색으로
선택해 실제 프롬프트에 남긴다. 배경의 질감·그라데이션·그림자·체크무늬와 전경으로 번지는 색은 금지한다.
생성 원본의 크로마키 배경과 최종 자산의 실제 알파 투명은 별도 단계다.
투명 도구 고도화 중에는 생성 → 프로젝트 경로 저장까지만 수행한다. 분할·배경 제거·후처리는 별도 요청을 따른다.

이 규약이 아래의 과거 투명/회색 배경 생성 지시보다 우선한다. 화풍 기준은 그대로 `figurine-v1`이다.
새 생성에는 `master-prompt-chroma-v2.txt`, `master-prompt-576-sheet-v2.txt`,
`uniform-edit-576-v2.txt`를 사용한다. 기존 v1 마스터와 이미 사용한 프롬프트는 보존한다.
v2는 배경 정책 변경 버전이며 첫 생성 후 파일럿 검수를 다시 수행한다.

현재 양산 목표는 [576개 고유 외형·10개 유니폼 기획](Production576.md)을 따른다.
해당 기획은 기존 10×10 파일럿을 대체하며, 다인 시트 제작·인물별 배경 제거·의상 결합·
구단 계보 내 얼굴 중복 방지 규칙에서 이 문서보다 우선한다. 기존 단일 생성 마스터는 보존한다.

## 기준과 범위

사용자가 선택한 정면 피규어 초상화를 `references/player-figurine-anchor-v1.png`로 고정한다.
원본은 1254×1254 RGBA PNG이며 `output/imagegen/player-figurine-profile-transparent.png`의 보존 사본이다.
검정색처럼 보이는 뷰어 배경은 디자인 요소가 아니다. 최종 배경은 투명이다.

현재 버전은 `figurine-v1`이다. 이전 스포츠 벡터·반실사·미소년 일러스트와 여성 매니저는
선수 양산의 참조로 다시 섞지 않는다. 이번에 선택한 피규어가 선수의 유일한 화풍 기준이다.
매니저 자산의 변경은 이 규약에 포함하지 않는다.

이번 작업의 산출물은 제작 규약·프롬프트·변주 데이터·기준 이미지다.
대량 생성, Unity 등록, 런타임 배정과 자동 합성 시스템이 구현됐다는 뜻은 아니다.

## 고정할 것과 바꿀 것

| 영역 | 고정 | 변경 허용 |
| --- | --- | --- |
| 화풍 | 둥근 피규어 조형, 부드러운 입체감, 과하지 않은 광택, 날카롭지 않은 윤곽 | 없음 |
| 구도 | 정면, 수평 어깨, 곧은 고개, 손·소품·동작 없는 상반신 | 없음 |
| 비례 | 큰 머리와 작은 몸의 기준 비율, 모자 포함 여백, 동일 얼굴 배치 | 얼굴 폭·볼·턱의 제한된 변주 |
| 조명 | 기준의 부드러운 정면 조명과 색조 | 없음 |
| 외형 | 한국인 성인 야구선수의 캐릭터화 | 얼굴형·눈·눈썹·코·귀·피부톤·짧은 머리·연령감 |
| 유니폼 | 모자 실루엣, 셔츠 재단, 버튼 위치, 소매 길이 | 모자·몸판·소매·언더셔츠·파이핑 색, 단순 패턴 |
| 표정 | 차분한 중립 또는 양쪽이 균등한 작은 미소 | 중립 / 작은 미소 / 집중 |
| 배경 | 실제 알파 투명 | 없음 |

모자와 흰 옷도 각각 불투명 전경이다. 손 들기·허리 짚기·팔짱·배트·글러브·고개 기울임·
비웃는 입꼬리·치아를 드러낸 큰 미소는 넣지 않는다. 수염·주름·질감으로 실사화하지 않는다.
로고·글자·등번호·스폰서는 기본적으로 금지한다. 구단 엠블럼이 필요하면 승인된 별도 자산을
후처리하는 확장 작업으로 다루고 생성 모델에 글자를 그리게 하지 않는다.

## 프롬프트 조립 계약

최종 요청은 아래 순서를 그대로 이어 붙인다. 영어 블록은 이미지 생성 입력 원문이며 운영 문서는 한국어다.

1. `master-prompt.txt` 전체. 작업자가 임의로 요약하거나 미형·실사 강화 문구를 추가하지 않는다.
2. `uniform-prompt.txt` 또는 `appearance-prompt.txt` 중 하나.
3. `variants.json`에서 선택한 객체 하나를 JSON 그대로 첨부한다.

요청당 선수 한 명만 생성한다. 격자 이미지는 승인 결과를 모아 만든 검토용이며 생성의 입력 단위가 아니다.
내장 ImageGen을 사용하고 API/CLI 대량 호출로 임의 전환하지 않는다.
동일 프롬프트도 동일 픽셀을 보장하지 않는다. 참조 이미지·불변 항목 검수로 일관성을 관리한다.
변주 데이터가 마스터와 충돌하면 생성 전에 데이터를 수정한다.

## 유니폼 디자인 양산

1. 기준 초상화를 편집 대상으로 사용한다. 얼굴·눈·머리·피부·표정은 전부 고정한다.
2. `UniformId`와 색상·패턴만 변경한다. 예시 데이터는 실존 구단 또는 게임 구단에 배정되지 않은 후보다.
3. 한 번에 한 벌을 만들고 모자부터 셔츠까지 같은 디자인인지 확인한다.
4. 얼굴이 바뀌면 유니폼이 좋아도 반려한다. 직전 실패작을 계속 수정하지 말고 기준에서 다시 시작한다.
5. 합격한 완성 초상화를 해당 유니폼의 `UniformReference`로 등록한다.

색 HEX는 목표값이다. 조명·음영 때문에 모든 픽셀이 HEX와 같지는 않다. 작은 카드에서 구단 간 색 구분을 확인한다.
새 재단·모자 형태·액세서리는 단순 변주가 아니라 규격 변경이므로 별도 버전으로 평가한다.

## 외형 디자인 양산

1. 기준 초상화를 화풍과 구도 참조로 사용한다. 기본 유니폼 `uniform-neutral-v1`을 고정한다.
2. `AppearanceId`마다 얼굴 구조를 명시한다. 단순 헤어 색상 변경을 새 인물로 계산하지 않는다.
3. 외형 후보 12명을 개별 생성해 64 / 128 / 256px에서 서로 구분되는지 확인한다.
4. 기준과 나란히 비교해 머리 크기·모자 높이·시선·조명·재질이 유지된 것만 통과시킨다.
5. 나이가 다른 동일 인물은 `AppearanceFamilyId`를 공유하고 같은 얼굴의 수정으로 제작한다.
   어린 외형의 청년을 미성년자로 설정하지 않는다. 연령은 성인 선수의 캐릭터화다.

포지션은 얼굴을 결정하는 필수 분류가 아니다. 단단한 체형·날렵한 인상 등은 외형 변주이며
포지션 변경 시 얼굴을 바꾸지 않는다. 이번 풀에는 외국인 선수 외형을 포함하지 않는다.

## 외형과 유니폼 결합

외형과 유니폼을 처음부터 동시에 새로 디자인하지 않는다.
합격한 외형 초상화를 **편집 대상 이미지 1**, 합격한 유니폼 초상화를 **의상 참고 이미지 2**로 둔다.
마스터 + 유니폼 프롬프트 + 유니폼 데이터를 사용해 의상만 교체한다.
이미지 2의 얼굴이 섞이거나 이미지 1의 얼굴이 바뀌면 반려한다.

최종 결과는 `AppearanceId × UniformId`의 완성 PNG다. 생성 이미지가 독립 레이어를
제공한다고 가정하지 않는다. 외형 1,000종 × 유니폼 20종을 무조건 생성하면 20,000장이 되므로
초기에는 실제 필요한 조합만 만든다. 대규모 자동 재색칠·얼굴/의상 레이어 합성은 별도 구현과
경계 검증 이후 도입한다. 현재 문서는 그런 합성 도구가 있다고 가정하지 않는다.

## 배경 제거 및 저장

생성 시 투명 PNG를 요청한다. 실제 알파가 없거나 배경 제거가 필요하면 반드시
`Tools/ImageBackground/Remove-ImageBackground.ps1`을 사용한다.
체크무늬를 다시 그리게 하는 반복 생성으로 해결하지 않는다.

```powershell
powershell -NoProfile -File Tools/ImageBackground/Remove-ImageBackground.ps1 -InputPath output/imagegen/player-portraits/figurine-v1/raw/appearance-001__uniform-neutral-v1__r01.png -OutputPath output/imagegen/player-portraits/figurine-v1/final/appearance-001__uniform-neutral-v1__r01.png -ProtectPolygonPath output/imagegen/player-portraits/figurine-v1/masks/appearance-001__uniform-neutral-v1__r01.json
```

흰 유니폼은 배경과 섞여 지워질 수 있으므로 해당 이미지의 보호 영역을 지정한다.
보호 다각형은 이미지 크기·윤곽마다 다르며 기존 선수용 JSON을 다른 결과에 복사하지 않는다.
현재 제거 도구는 무채색 배경과 단일 연결 전경용이다. 복잡한 배경은 도구 확장 또는
단순 배경으로의 재생성 후 처리한다. 도구의 제약은 `Tools/ImageBackground/README.md`를 따른다.

디렉터리 규칙:

```text
output/imagegen/player-portraits/figurine-v1/
  raw/        생성 원본 PNG
  final/      검수한 RGBA PNG
  prompts/    실제 전송한 프롬프트 전체
  masks/      이미지별 전경 보호 다각형
  manifests/  manifest-template.json을 채운 제작 기록
  previews/   밝은/어두운 배경과 카드 크기 비교 이미지
```

파일명은 `{AppearanceId}__{UniformId}__rNN.png`로 고정한다. 원본과 이전 결과는 덮어쓰지 않는다.
기준 이미지·프롬프트 변경은 `figurine-v2`처럼 새 버전을 만들고 기존 양산분과 섞지 않는다.
특정 결과를 다음 작업의 임의 기준으로 계속 사용하지 않는다. 승인된 기준과 외형 정본만 사용한다.

## 검수 통과 조건

- 기준 이미지와 같은 둥근 피규어 재질인가? 반실사·날카로운 만화·납작한 벡터로 변하지 않았는가?
- 정면·수평 어깨·무동작·손 없는 프로필인가? 모자와 귀가 잘리지 않았는가?
- 기준의 모자 상단·눈높이·턱·어깨 위치와 전체 크기가 맞는가?
  초기 허용 오차는 정규화 캔버스 높이의 약 3%이며, 단순 비례 조정으로 해결되지 않으면 재생성한다.
- 유니폼 편집에서 얼굴과 머리 모양이 유지됐는가? 외형 편집에서 유니폼이 유지됐는가?
- 다른 선수와 얼굴형·눈·눈썹·코·귀 중 두 가지 이상이 눈에 띄게 다른가?
- 실제 RGBA인가? 외부 alpha=0, 피부·모자·유니폼 내부 alpha=255인가?
- 밝은 배경과 남색 배경에서 체크무늬·회색 테두리·유니폼 손실이 없는가?
- 64 / 128 / 256px 축소에서 눈·얼굴·구단 색이 읽히는가?
- 실제 카드 프레임에 넣었을 때 이름 영역을 가리지 않고 얼굴 크기가 일관되는가?

생성 후보는 `draft`, 시각·알파 검수를 통과하면 `reviewed`, 실제 카드 표시까지 통과하면
`ready`로 기록한다. 현재 기준은 화풍 기준으로 선택된 이미지이며 게임 적용 검증을 의미하지 않는다.

## 양산 확대 순서와 런타임 경계

유니폼 3벌 → 외형 12명 → 외형 3명에 유니폼 3벌을 교차 적용한 9개 조합으로 얼굴 유지 확인 →
100명 파일럿 → 검수 합격률·수정 시간·중복률을 보고 1,000명으로 확장한다.
재시도 비용과 수동 마스크 작업량을 포함해 산정한다. 샘플 수와 통과율은 실제 측정 전까지 추정하지 않는다.

향후 게임 연결은 선수에게 외형 ID를 고정 배정하고 유니폼 ID를 별도 조회하는 구조로 한다.
같은 선수의 카드 등급은 얼굴을 공유한다. 이적은 얼굴 변경 사유가 아니다.
Core/Simulation에는 Sprite나 텍스처를 넣지 않는다. 이미지가 경기 난수·능력치·밸런스에 영향을 주지 않는다.
아틀라스는 검수한 개별 이미지로 후처리하며 이번 범위에서는 자동 패킹·런타임 배정을 구현하지 않는다.
