# 구단 계보 기준 576개 고유 외형·10개 유니폼 양산 기획

## 유니폼 변환 실행 규약

사용자의 유니폼 10종 제작 요청에 따라 의상 변환·분할·투명화 작업을 진행한다.
`Tools/PlayerUniforms`의 인물별 색/위치 마스크를 사용하며 색상 데이터는 `uniforms.json`이 소유한다.
이번 디자인의 챙은 모자와 같은 색, 소매는 몸판과 같은 색으로 유지한다. 작은 카드에서
읽히는 모자·몸판·파이핑 색 조합과 레드 핀스트라이프로 10종을 구분한다.
이는 아래 초안 표의 별도 소매·챙 배색을 조정한 실행안이다. 임의의 절개 경계를 추가하지 않고
원본 재단·음영과 얼굴을 보존하기 위한 결정이다.
최종 출력과 검증 결과는 `Uniforms10.md`를 따른다. 생성 전용 범위 제한은 이번 후속 요청으로 확장됐다.

## 배경 정책 갱신

향후 생성은 README의 단색 크로마키 규약을 우선 적용한다. 새 시트 마스터는
`master-prompt-576-sheet-v2.txt`(`sheet-576-v2`), 의상 편집은 `uniform-edit-576-v2.txt`다.
기존 v1은 제작 이력으로 보존한다. 기본 배경은 `#00FF00`이며 전경과 겹치면 다른 단색 키를
프롬프트에 명시한다. 아래의 투명/무채색 생성 지시는 과거 규약이다.
현재 작업 범위는 생성 원본과 프롬프트의 프로젝트 저장까지이며 분할·투명화·후처리는 별도 요청을 따른다.

## 1. 목표와 결정

한 구단의 전체 역사 계보(Lineage)를 통합했을 때 가장 많은 선수가 576명이라는 사용자 집계를
기준으로, **서로 구분되는 고유 외형 576종**과 **유니폼 10종**을 제작한다.
예를 들어 MBC 청룡과 LG 트윈스는 동일 계보로 묶는다. 이 예시는 데이터 그룹 기준이며
실제 이름·엠블럼·유니폼을 이미지에 재현하라는 지시가 아니다.

576은 이번 기획의 입력값이다. 저장소 전체 데이터를 재집계해 검증한 수치는 아니다.
착수 감사에서는 시즌별 카드 수가 아닌 **계보별 서로 다른 인물 ID 수**인지 확인한다.

| 항목 | 목표 | 의미 |
| --- | ---: | --- |
| 고유 외형 | 576 | 얼굴 디자인 자체가 다른 인물 |
| 유니폼 | 10 | 가상 구단의 구분 가능한 모자·상의 디자인 |
| 전체 조합 | 5,760 | 576 × 10개의 외형/유니폼 조합 |
| 기본 외형 생성 시트 | 36 | 시트당 16명, 4열 × 4행 |
| 전체 조합을 시트로 표현할 경우 | 360 | 유니폼별 36장; 생성 횟수와 동일하지 않음 |

유니폼만 다른 같은 얼굴은 별개의 고유 외형으로 세지 않는다.
전 세계 모든 선수가 다른 얼굴을 갖는 목표가 아니라, **같은 계보의 서로 다른 인물은 얼굴이
겹치지 않는 것**이 기본 목표다. 다른 계보 간 재사용은 허용하되 동일 인물의 얼굴은 유지한다.
프레임 등급·강화·시즌·포지션이 바뀌어도 얼굴을 다시 추첨하지 않는다.

앞선 10외형 × 10유니폼 제작은 파일럿 자료로만 취급한다. 생성 중단 또는 미검수 결과를
576종 완성분에 자동 산입하지 않는다. 이번 요청의 실행 범위는 기획 문서 작성이며
576종 생성·배정 알고리즘·합성기 구현은 다음 제작 작업이다.

## 2. 얼굴 중복과 동일 인물 유지 계약

식별자는 다음과 같이 분리한다. 이름 문자열로 매핑하지 않는다.

| ID | 소유하는 정보 |
| --- | --- |
| PersonId | 연도·소속 변경을 관통하는 동일 인물의 내부 안정 ID |
| PlayerSeasonId | 해당 인물의 특정 시즌 데이터 |
| LineageId | 개명·승계 구단을 통합한 계보 |
| AppearanceId | `face-0001`부터 시작하는 얼굴 정본 |
| UniformId | `uniform-01` ~ `uniform-10` 의상 디자인 |
| PortraitKey | `AppearanceId + UniformId + ArtVersion` |

`PersonId → AppearanceId`는 고정 매핑이다. 외부 Source ID를 공개 UI에 노출하지 않는다.
`PlayerSeasonId → LineageId → UniformId`로 역사 카드의 의상을 선택한다.
현역 화면의 현재 소속 의상을 표시하려면 화면 규칙으로 별도 조회한다. 과거 카드의 유니폼을
현재 소속으로 일괄 변경하지 않는다. 계보 내 과거 유니폼 변천·홈/원정 추가는 10종 밖의 확장이다.

**576개면 반드시 충분하다고 단정하지 않는다.** 계보마다 독립 순번을 배정하면 이적한
같은 인물이 다른 얼굴을 받는다. 반대로 전역 ID의 단순 해시 `% 576`은 동일 계보에서 충돌한다.

착수 시 전체 Person/Lineage 관계로 충돌 그래프를 만든다.

1. 각 정점은 PersonId다.
2. 동일 계보에 한 번이라도 소속된 서로 다른 두 인물을 연결한다.
3. 연결된 정점은 다른 AppearanceId를 사용한다. 같은 인물은 어느 계보에서나 같은 정점이다.
4. 결정적 DSATUR 등으로 배정을 시도한다. 동점은 차수 내림차순, PersonId 오름차순으로 고정한다.
5. 결과를 전체 간선과 계보별 집합으로 다시 검사하고 정본 매핑으로 저장한다.

최대 계보 인원 576은 필요한 색 수의 **하한**이지, 여러 계보가 겹치는 전체 그래프의 상한은 아니다.
탐욕 배정 실패도 수학적 불가능 증명이 아니다. 재배정·백트래킹 등으로 확인하고, 576 안에서
검증된 배정을 얻지 못하면 부족 수를 보고한 뒤 외형 풀을 확장한다. 얼굴 중복을 숨기거나
동일 인물 얼굴을 구단마다 바꾸어 수량을 맞추지 않는다.

기존 매핑은 새 이미지 추가 때 유지한다. 새 선수에게 사용 가능한 외형이 없으면 새 외형을
추가한다. 은퇴했다고 같은 계보의 다른 선수에게 얼굴을 재사용하지 않는다. 역사 카드에 남기 때문이다.
세이브에 새 필드가 실제 추가되는 구현 단계에서는 기존 SaveVersion·마이그레이션 계약을 따른다.

## 3. 아트 기준 고정

`references/player-figurine-anchor-v1.png`가 유일한 선수 화풍 기준이다.
큰 머리·작은 몸, 말랑한 피규어 조형, 둥근 눈·볼·턱, 부드러운 명암, 적당한 재질 광택을 유지한다.
매니저 이미지·이전 반실사·벡터·스포츠 만화풍을 새 참조로 섞지 않는다.

- 정면 상반신, 수평 어깨, 고개 기울임 없음, 손·소품·액션 포즈 없음.
- 모자·귀·어깨가 잘리지 않게 한다. 모든 셀에 동일한 여백과 눈높이를 적용한다.
- 중립 또는 작은 대칭 미소만 허용한다. 비웃음·찡그림·과한 웃음은 금지한다.
- 한국인 성인 선수의 캐릭터화다. 현재 외형 풀에는 외국인 디자인을 포함하지 않는다.
- 외형은 능력치·등급·선악·성격을 암시하는 게임 수치가 아니다.
- 글자·등번호·로고·실존 선수 닮은꼴·실제 구단 브랜딩을 생성하지 않는다.
- 배경은 실제 알파 투명이며, 검정 배경이나 체크무늬를 자산에 포함하지 않는다.

기존 단일 초상화 마스터는 그대로 보존한다. 이번에는 사용자가 여러 장을 한 이미지에
제작하도록 요청했으므로 `master-prompt-576-sheet-v1.txt`를 별도의 시트용 고정 프롬프트로 사용한다.
단일 생성 마스터의 `ONE`과 시트 지시를 한 요청에 충돌시켜 넣지 않는다.

## 4. 고유 외형 576종 구성

아래 분산은 기획의 제작 슬롯이며, 조합 수만으로 얼굴이 실제로 다르다고 판정하지 않는다.

| 축 | 개수 | 예시 |
| --- | ---: | --- |
| 얼굴 구조 | 12 | 둥근형, 넓은 타원, 좁은 타원, 둥근 사각턱, 넓은 볼, 긴 볼, 역삼각형을 둥글게 완화한 형, 배형, 큰 귀형, 도드라진 광대형, 짧은 턱형, 넓은 아래턱형 |
| 눈·눈썹 조합 | 8 | 둥근 눈/직선 눈썹, 가는 눈/굵은 눈썹, 내려간 눈꼬리/완만한 눈썹 등 |
| 코·귀·헤어 구성 | 6 | 둥근 코/작은 귀/짧은 옆머리, 넓은 코/큰 귀/크루컷 등 |
| 총 슬롯 | 576 | 12 × 8 × 6 |

각 슬롯에 피부톤·체격·성인 연령감·중립/미소를 교차 배치한다. 한 축이 특정 연령·피부톤에
몰리지 않게 한다. 전부 같은 얼굴에 머리색만 바꾸거나 같은 얼굴을 좌우 반전해 수를 채우지 않는다.
외형 계획표의 코·귀·눈·턱 등 구체 필드가 비어 있으면 생성하지 않는다.

연령 초안은 청년 192 / 중견 240 / 베테랑 144로 분산하되 이는 **서로 다른 576인**이다.
동일 인물의 노화 3단계는 이번 수량에 포함하지 않는다. 초기에는 인물의 대표 외형을 전 연도에
유지한다. 노화 도입 시 `AppearanceFamilyId + AgeStage`를 추가하며 별도 자산 수를 산정한다.
포지션별 얼굴 풀을 강제로 나누지 않는다. 소속·포지션 변경 때 외형 후보가 부족해지는 것을 방지한다.

## 6. 제작 경로: 외형 생성과 의상 조합 분리

**권장 양산 경로는 ImageGen으로 576개 외형을 만들고, 검수된 마스크 기반 의상 변환으로
10개 유니폼을 적용하는 방식이다.** 얼굴까지 5,760번 다시 생성하면 얼굴 유지 검수가 커지기 때문이다.

이 경로에 필요한 유니폼 변환 도구는 현재 미구현이다. 기존 배경 제거 도구는 의상 합성기가 아니다.
다음 기능을 구현·검증한 뒤 양산한다.

- 각 외형별 모자 몸통/챙, 셔츠 몸판/소매, 이너, 파이핑 마스크를 승인한다.
- 보호 영역인 얼굴·머리·귀의 RGBA는 의상 변환 전후 픽셀 단위로 동일해야 한다.
- 그림자와 하이라이트를 보존해 색을 바꾸고, 세로줄 등 패턴은 승인된 의상 영역 안에만 적용한다.
- 색칠 마스크와 배경 제거 보호 마스크는 목적이 다르므로 별도로 보관한다.
- 10종 디자인을 실현하지 못하는 마스크/재색칠 방식이면 기능을 보강하거나 해당 의상만 ImageGen
  편집으로 처리한다. 후자의 얼굴은 별도 시각 검수 대상이며 픽셀 동일성을 주장하지 않는다.

모자 뒤 머리·목·옷 경계는 사람마다 다르다. 한 장의 마스크를 576명에 그대로 복사하지 않는다.
몸통만 일괄 붙이는 방식도 목 접합부와 그림자 검증 없이 사용하지 않는다.
내장 ImageGen 경로를 유지하며 API 대량 호출·모델 다운로드를 자동으로 가정하지 않는다.

## 7. 시트 생성·분할·아틀라스 규격

4×4 시트에서 16명씩 생성하는 것을 기본안으로 한다. 36장으로 기본 576슬롯을 채운다.
기존 5×2 시트는 파일럿 비교 자료로 활용할 수 있다. 품질 실패 시 2×2 또는 개별 생성으로
바꾸며, 시트 수 절약을 위해 축소·잘림을 승인하지 않는다.

- 생성 시 목표 캔버스는 2048×2048 이상, 셀당 명목상 512×512를 요청한다.
  실제 반환 해상도를 확인한다. 요청 해상도가 그대로 나올 것이라고 가정하지 않는다.
- 셀 상하좌우 약 6~8% 여백, 동일 눈높이, 모자 포함 상반신. 격자선·라벨은 생성하지 않는다.
- `SheetId + row + column → AppearanceId`의 매핑을 생성 전에 기록한다.
- 경계가 흔들리면 셀별 실제 crop rect를 보정한다. 인물과 이웃이 겹치면 재생성한다.
- 배경 제거는 **셀 분할 후 인물별**로 수행한다. 현재 도구는 가장 큰 전경만 남기므로
  16명 원본 시트 전체를 그대로 넣으면 안 된다.
- 실제 최종 해상도는 256×256 RGBA를 기본 카드용으로 계획하고, 더 큰 원본은 보존한다.
  512px 상세판은 원본 해상도와 카드 표시 시험을 통과할 때 추가한다. 업스케일을 원본 디테일로 보고하지 않는다.
- 동일 캔버스·피벗·얼굴 위치를 정규화하되 얼굴을 비균등 확대하거나 변형하지 않는다.
- 게임용 아틀라스는 분할·검수 결과로 다시 패킹한다. 생성 시트 자체를 좌표 정본으로 쓰지 않는다.
  스프라이트 간 여백과 가장자리 색 확장을 두고 검정/흰 테두리 번짐을 검사한다.

5,760개를 256×256 RGBA로 보관할 때 순수 픽셀 총량은 약 1.406GiB다.
512×512면 약 5.625GiB다. 이는 압축 전·패딩/밉맵 제외 계산이며 실제 빌드 크기나
동시 GPU 메모리 실측이 아니다. 한꺼번에 모두 로드하지 말고 필요한 유니폼/페이지 단위로
로드한다. 패킹·압축·해제 정책은 Unity 연결 시 실측하며 얼굴 품질과 함께 결정한다.

## 8. 바로 사용하는 프롬프트와 기록 규약

영어 프롬프트 원문은 함께 제공한 파일을 사용한다.

- `master-prompt-576-sheet-v1.txt`: 모든 외형 시트의 고정 마스터.
- `appearance-batch-template.json`: 한 셀의 외형 데이터 예시. 16개 객체로 채워 마스터 뒤에 붙인다.
- `uniform-edit-576-v1.txt`: ImageGen 의상 제작/보완 편집 전용. 승인 외형을 대상, 의상 기준을 참고로 사용한다.

원문을 줄이거나 작업 중 별도 미형·실사 키워드를 덧붙이지 않는다. 변경할 때는 PromptVersion을 올리고
파일럿을 다시 검수한다. 동일 프롬프트는 생성 결과의 결정론을 보장하지 않으므로 원본을 보존한다.

```text
output/imagegen/player-portraits/production-576-v1/
  sheets/raw/       sheet-001__r01.png
  faces/raw/        face-0001__r01.png
  faces/approved/   face-0001.png
  masks/background/face-0001.json
  masks/uniform/   face-0001__cap.png 등 부위 마스크
  uniforms/        uniform-01 기준 이미지·색상 정의
  portraits/       face-0001__uniform-01__r01.png
  atlases/         패킹 결과와 좌표 메타데이터
  prompts/         실제 전송 원문
  manifests/       입력 참조·해시·셀 좌표·상태·실패 사유
  previews/        전체 비교 및 카드 크기 합성
```

기록 필수값: ArtVersion, PromptVersion, AppearanceId, UniformId, SheetId, CropRect,
참조/원본/최종 파일과 SHA256, 실제 프롬프트, 생성 방식, 배경 제거 명령, 의상 마스크 버전,
검수 상태, 재생성 사유. 파일은 덮어쓰지 않고 revision을 올린다.

## 9. 배경 제거 규칙

```powershell
powershell -NoProfile -File Tools/ImageBackground/Remove-ImageBackground.ps1 -InputPath output/imagegen/player-portraits/production-576-v1/faces/raw/face-0001__r01.png -OutputPath output/imagegen/player-portraits/production-576-v1/faces/approved/face-0001.png -ProtectPolygonPath output/imagegen/player-portraits/production-576-v1/masks/background/face-0001.json
```

예시의 `approved` 경로에 파일이 생겨도 검수 통과를 뜻하지 않는다. 상태는 별도 기록으로 관리한다.
실제 알파가 없다면 생성 결과를 투명하다고 보고하지 않는다. 배경 제거가 필요하면 위 도구를 사용한다.
흰 의상 보호·색 겹침·경계의 잔여가 있으면 보호 다각형을 보정한다. 현재 도구의 정밀 매팅 한계는
`Tools/ImageBackground/README.md`를 따르며 복잡한 배경을 자동 처리한다고 주장하지 않는다.

## 10. 검수·확대·완료 조건

1. **데이터 감사:** 576명 집계의 중복 인물 처리와 계보 통합을 확인하고, 576색 배정 가능성을 검증한다.
2. **16명 파일럿:** 같은 시트 안에서 각기 다른 얼굴과 기준 화풍·구도가 유지되는지 확인한다.
3. **유니폼 10종 시험:** 16명 × 10종 160조합으로 의상 마스크·흰색 보존·얼굴 동일성·카드 가독성을 검수한다.
4. **96명 검증:** 6개 시트 규모에서 외형 중복 후보·시트 간 화풍 변화를 확인한다.
5. **576명 확장:** 실패 셀만 보충한다. 일부가 실패한 시트 전체를 재생성해 승인된 얼굴을 바꾸지 않는다.
6. **5,760조합 출력:** 마스크/의상 변환 도구를 통과한 모든 조합을 생성하고 실제 알파·누락·중복 키를 검사한다.
7. **게임 통합:** 실제 카드/라인업에 넣어 잘림·이름 침범·리소스 메모리·이적/역사 카드 매핑을 확인한다.

576개 기본 외형은 가까운 후보끼리 나란히 비교한다. 이미지 유사도는 검수 후보를 고르는 보조이며
눈·코·턱·얼굴형이 실제로 구분된다는 자동 증명이 아니다. 전체 비교표와 64/128/256px에서 사람이 검수한다.
최소 두 가지 얼굴 구조 차이가 보이지 않는 후보는 재생성한다. 머리색·피부색만 다른 후보는 통과시키지 않는다.

최종 완료 기준:

- 검수된 고유 외형 576개 이상, UniformId 10개, 조합 5,760개 누락 없음.
- 같은 PersonId는 모든 시즌/계보/카드 등급에서 같은 얼굴. 같은 계보 내 다른 인물의 얼굴 중복 0건.
- 전경 보존·외곽 투명도·밝고 어두운 배경 합성 검수 통과.
- 의상 도구 변환에서는 얼굴 보호 영역 픽셀 변경 0건. ImageGen 보완분은 별도 얼굴 유지 검수 통과.
- 자세·화풍·크롭·실제 카드 가독성 검수 통과. 통과 전 상태는 draft/reviewed로 구분한다.
- 원본/프롬프트/마스크/배정표로 재작업 가능. Core/Simulation 의존성과 경기 RNG 변경 없음.

비용·시간은 파일럿의 실제 합격률로 산정한다. 예를 들어 합격률 80%라면 576개 확보에
약 720개 후보가 필요하다는 계산만 가능하다. 720개가 실제 필요량이라는 뜻은 아니다.
배경 제거·마스크 보정·중복 검수·의상 결합 시간까지 포함하고, 파일럿 전에는 확정 견적을 제시하지 않는다.
