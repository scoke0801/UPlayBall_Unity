# 프로젝트 원칙

> 출처: `BaseballManager_PROJECT.md` 35절 (2026-08-28 `docs/지침`로 이동)

### 1. 야구 액션 게임을 만들지 않는다.

핵심은 직접 플레이가 아니라 의사결정이다.

### 2. 데이터가 콘텐츠다.

선수, 기록, 성장, 시즌 결과가 게임의 주 콘텐츠다.

### 3. UI보다 시뮬레이션을 먼저 만든다.

경기가 재미없으면 UI가 좋아도 게임이 성립하지 않는다.

### 4. 모든 시스템은 여러 시즌 플레이를 기준으로 설계한다.

1시즌만 보고 만든 데이터 구조를 피한다.

### 5. 자동화 테스트를 적극적으로 사용한다.

야구 시뮬레이션은 사람이 몇 경기 플레이해서 밸런스를 확인할 수 없다.

### 6. 설명 가능한 결과를 만든다.

완벽한 현실성보다 플레이어가 결과를 납득할 수 있어야 한다.

### 7. 초기 범위를 지킨다.

Football Manager 수준의 기능을 목표로 하지 않는다. 제외 대상은 `BaseballManager_PROJECT.md` 31절(MVP에서 제외할 기능) 참고.

### 8. 엔트리브소프트 `프로야구매니저`(프야매)를 레퍼런스로 삼는다.

새 기능을 구현할 때는 백지에서 설계하지 않는다. 프야매가 해당 기능(또는 유사 기능)을 어떻게
다루는지 먼저 웹에서 조사하고, 그 결과를 이 프로젝트의 범위와 방향(7절 초기 범위, 31절 MVP 제외
목록, 감독 AI가 소유하는 영역)에 맞게 취사선택해 설계·구현한다. 조사 없이 임의로 새 체계를
만들지 않는다.
