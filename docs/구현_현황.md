# 구현 현황

이 문서는 2026-08-30 기준으로 저장소에 **실제로 존재하는 코드**를 조사해 정리한 현황이다. 기획 의도는 `BaseballManager_PROJECT.md`가 기준이고, 이 문서는 "그중 무엇이 이미 만들어져 있는가"만 다룬다. `CLAUDE.md`의 "현재 단계: Phase 1 — Simulation Prototype / 아직 구현된 게임 코드가 없다"는 서술은 더 이상 사실과 다르다 — 실제로는 새 게임 생성부터 Rookie~Galaxy 다단계 리그 승강, 정규시즌·포스트시즌·오프시즌 성장·계약-은퇴 통합 흐름까지 커리어 전체 루프가 구현되어 있다. `CLAUDE.md` 갱신 여부는 이 문서 범위 밖이라 임의로 고치지 않았다.

이 문서의 초판(2026-08-28 조사)은 새 게임~시즌~오프시즌 성장~계약 1주기가 처음 갖춰진 시점을 기록한 것이었다. 이후 다단계 리그 승강(Rookie~Galaxy), 구위 기반 정밀 경기 엔진(`DetailedMatchEngine`), 감독 AI 라인업 편성, 계약-은퇴 통합 흐름과 은퇴 회고 시스템, 시즌 서사(내러티브)·연출, 상황별 BGM 재생 등 다수의 기능이 추가되어 이번 조사에서 반영했다.

각 항목은 클래스/파일 경로 중심으로 요약한다. 세부 동작·수치 근거는 코드와 EditMode 테스트를 직접 참고할 것.

## 2. Baseball.Core

`Assets/02.Scripts/Core/` — 데이터 모델과 밸런스 계수. 전부 Unity 비의존.

### 2.1 선수/구단 데이터 모델 (`Players/`, `Teams/`)

- `Player.cs` — 경기 입력용 선수 신원 + 현재 능력치. `GetPositionProficiency(position)` 제공.
- `BatterAttributes.cs` / `PitcherAttributes.cs` — 0~100 범위 불변 `readonly struct` 능력치.
- `PositionProficiency.cs` — 포지션별 0~100 적응도.
- `PlayerPosition.cs` — `PlayerType`, 수비 포지션·투수 역할 enum, `Handedness`.
- `BattingApproach.cs` — 타석마다 선택하는 타격 접근 방식(균형/컨택/장타/신중).
- `AttributeAllocation.cs` + `CharacterCreationBalance.cs` — 새 게임 캐릭터 생성 시 6개 능력치 배분이 규칙(기준값 40·보너스 72·항목당 상한 65) 안에 있는지 검증하는 로직. **다만 `docs/성장_시스템_현황.md` 3절에 따르면 실제 `UI_Scene_NewGame`은 이 경로를 호출하지 않는다** — 실사용 경로는 `NewGameFlow.SubmitCreationAttributes` → `CareerCreationRules`(기준값 50, 타자 자유배분 60/투수 40, 항목당 상한 75)이며, `AttributeAllocation`/`CharacterCreationBalance`와 그것이 검증하던 `SubmitBatterAttributes`/`SubmitPitcherAttributes` 경로는 죽은 코드로 보인다. 포지션 권장치와 어긋나는 배분 자체는 막지 않는다(플레이어 선택 존중).
- `Team.cs` — 라인업 + 선발투수 + 지정 이닝부터 등판할 구원투수 보관. `GetCurrentPitcher(inning)`.
- `Lineup.cs` — 9인 타순 + 중복 없는 수비 배치 검증, 포지션 적응도 반영 팀 평균 수비력 계산.
- `LineupSlot.cs` — 타순 한 자리(선수+포지션).
- `PlayerGameRole.cs` — 감독 AI가 경기 중 실제로 부여한 기용 역할.
- `TeamArchetype.cs` / `TeamArchetypeLibrary.cs` — 재정/육성/선수층/스카우트 등급 축과 5개 기본 구단 아키타입.
- `TeamIdentityDefinition.cs` — 팀 이름 후보/색상(`TeamColor`), 계약 시 예상 출장 역할.

### 2.2 성장 시스템 런타임 상태 (`Growth/`)

새 게임부터 시즌 성장·부상·계약까지 이어지는 커리어 성장 시스템의 데이터가 이미 상세하게 갖춰져 있다.

- `PlayerAbility.cs` — 성장/노쇠를 개별 추적하는 능력치 식별자, 노쇠 계통, 훈련 활동 계통, 타자/투수별 카탈로그.
- `PlayerGrowthState.cs` / `AbilityRatings.cs` — Base Ability·Potential·성장 이력. 능력치를 고정 순서 배열로 보관해 순회 결정론 보장.
- `GrowthResultRecord.cs` — 능력치 변화(`AbilityChange`), 재현용 입력 스냅샷(`GrowthInputSnapshot`), Seed 포함 세이브 가능 성장 결과.
- `CareerEvaluation.cs` — 스프링캠프 평가 입력/결과, 계약 시장 평가 입력, 감독 육성 스타일 enum.
- `InjuryState.cs` — 부상 기록(원인+예상 결장), 설명 가능한 부상 확률 입력, 심각도 enum.
- `OffseasonState.cs` — 12주 시간 예산 기반 오프시즌 활동 계획 + 조기 마감 처리.
- `SeasonUsageSummary.cs` — 시즌 자연 성장용 실제 출장 활용량 비율.
- `PlayerStudyState.cs` — 유학 프로그램 방문 이력.
- `TrainingProgramDefinition.cs` — 프로그램별 능력치 가중치/기간/비용/성장 채널.
- `SkillBlockDefinition.cs` / `SkillBoardState.cs` — 테트로미노 7종 스킬 블록 + 4×4 성장판 + Trait Socket 배치 상태(스킬 뽑기/보드 시스템 데이터 모델).
- `CareerEconomyState.cs` — 만원 단위 정수 Money + 수입지출 이력.

### 2.3 밸런스 테이블 (`Balance/`)

`BalanceTable.cs`가 아래 계수 묶음을 버전과 함께 최상위에서 컨테이닝한다. Game 레이어가 SO에서 이 구조체로 변환해 시뮬레이터에 주입한다.

| 구조체 | 조정 대상 |
|---|---|
| `PlateDisciplineBalance` | 투구별 Ball/Swing/Contact 확률 |
| `BattedBallBalance` | 인플레이 타구→안타/장타 변환(홈런·2루타·3루타 등) |
| `BaseRunningBalance` | 주자 추가 진루/득점/병살 확률 |
| `BattingApproachBalance` | 타격 접근 방식별 확률 보정 |
| `ContractOfferBalance` | 새 게임 계약 오퍼 여부/금액 |
| `ContractBonusBalance` | 계약 상여 조건 목표/보상 |
| `TeamGenerationBalance` | Rookie League 구단·포지션 경쟁자 생성 |
| `PlayerEvaluationBalance` | 신인 평가(포지션 적합도·구단 성향) |
| `CareerSeasonBalance` | 정규시즌 일정(기본 8구단 80경기), 기용 판단, 경기 후 상태 변화 |
| `RosterTurnoverBalance` | 시즌 전환 시 타 구단 로스터 변동 |
| `PostseasonBalance` | 포스트시즌 시리즈 길이(준결승 3전2선승/결승 5전3선승) |
| `SeasonAwardBalance` | 수상 후보 자격/평가 가중치 |
| `SeasonSettlementBalance` | 수상/포스트시즌 Money 배율 |
| `InjuryBalanceTable` | 경기/훈련 부상 위험 요인·심각도 분포 |
| `CareerGrowthEvaluationBalance` | 스프링캠프 평가 가중치, 계약 시장 가치 6요소 가중치 |
| `GrowthBalanceTable` | 나이-성장 곡선, 잠재력 격차, Work Ethic, 훈련 적합도, 컨디션, 반복, 자연 성장, 노쇠, 스킬 뽑기 확률 등 성장 관련 하위 테이블 묶음 |

`GrowthSkillContent.cs`는 기본 4×4 성장판 레이아웃과 타자/투수 계통별 스킬 뽑기 풀을 정적으로 제공한다.

### 2.4 규칙 상수 (`Rules/`)

`BaseballRules.cs` — 3아웃, 4볼, 9이닝 등 시뮬레이션 전역이 공유하는 야구 규칙 상수.

## 3. Baseball.Simulation

`Assets/02.Scripts/Simulation/` — Core 데이터 + 주입된 밸런스/RNG로 실제 확률 계산과 판단 로직을 수행.

### 3.1 타석/경기 시뮬레이션 (`PlateAppearance/`, `Match/`)

- `PlateAppearanceSimulator` (+ `IPlateAppearanceSimulator`) — 밸런스와 RNG를 주입받아 투구 수부터 타구 결과까지 계산. 입력은 `PlateAppearanceMatchup`(타자/투수/수비), 출력은 `PlateAppearanceOutcome`.
- `MatchSimulator.cs`(+ `.Baserunning.cs` `.Events.cs` `.Fielding.cs` `.Results.cs`) — 두 팀 타순+선발투수로 결정론적 9이닝 경기 진행. 인플레이 결과를 실제 야수 수비 기회로 귀속.
- `DetailedMatchEngine.cs`(+ `.State.cs` `.Tactics.cs` `.Events.cs` `.Results.cs`) — 구위(Stuff)·투구수 부하·전술 판단을 반영한 정밀 경기 엔진. 커리어 진행은 `CareerGameRunner`를 통해 이 엔진을 사용한다(`584bafa`). `MatchSimulator`는 대량 밸런스 시뮬레이션·EditMode 통계 테스트용 경량 엔진으로 별도 유지된다.
- `MatchEvent.cs` — `Pitch/Contact/Hit/RunnerAdvance/Score/Out/PlateAppearanceEnded/HalfInningEnded/MatchEnded` 이벤트 타입을 갖는 할당 없는 `readonly struct`. `IMatchEventSink`(`MatchEventSink.cs`)가 시뮬레이션→표현 전달 계약.
- `MatchInput.cs` / `MatchResult.cs` / `MatchDecision.cs` — SeasonId/GameId/RandomSeed 포함 입력, 완료 경기 결과(BoxScore+이벤트 스트림), 투구 전 플레이어 결정 요청.
- `BoxScore.cs` — 타격/투구/수비 라인 + 팀 이닝별 득점 누적.

`MatchSimulator`/`DetailedMatchEngine` → `MatchEvent` 스트림 → Presentation이라는 CLAUDE.md의 계약이 두 엔진 모두에서 실제 코드 구조로 구현되어 있다.

### 3.2 결정론적 RNG (`Random/`)

- `IRandomSource` — 시뮬레이터가 주입받는 난수 계약.
- `Pcg32Random` — 플랫폼 무관 PCG32 구현.
- `DeterministicSeed` — 기준 Seed에서 타석/성장/오프시즌 등 용도별 독립 Seed를 결정론적으로 파생.

### 3.3 성장 판정 로직 (`Growth/`)

- `PlayerGrowthFactory` — 캐릭터 생성 능력치에서 초기 Potential+성장 상태 생성.
- `GrowthResolver` — 훈련 프로그램 기대 성장값을 영구 능력치 변화로 변환.
- `NaturalDevelopmentResolver` — 시즌 활용 역할 기반 소폭 자연 성장.
- `AgingResolver` — Physical/Technical/Mental 계통별 시즌 노쇠 적용.
- `InjuryResolver` — 피로/나이/출장량/훈련강도/내구도 → 부상 결과.
- `ManagerRoleEvaluator` — 스프링캠프에서 현재 전력과 실제 경쟁자 차이로 역할 결정.
- `ContractMarketEvaluator` — 최근 성과+안정 전력 기반 0~100 시장 가치.
- `OffseasonScheduler` — 12주 시간 예산 겹침/유학/파트너/비용 제약 검증.
- `AiOffseasonPlanner` — AI 선수도 동일 공식으로 결정론적 오프시즌 계획 생성.
- `SkillBoardService` / `SkillGachaService` — 블록 배치 검증(회전/경계/겹침/Trait Socket)과 보장 카운트 있는 확률적 뽑기.

### 3.4 커리어/시즌 시뮬레이션 (`Career/`)

- `TeamGenerator` / `NewGameSetup` / `GeneratedTeam` — 새 게임 시작 시 Rookie League 구단 결정론적 생성(포지션 필요도, 같은 포지션 경쟁자 포함).
- `SeasonScheduleGenerator` — 정규시즌 일정 생성.
- `PostseasonBracket` — 4강 토너먼트 대진/라운드.
- `ContractOfferEvaluator` / `ContractOfferBoard` / `ContractOffer.cs` — PlayerValue×PositionNeed×TeamBudget×TeamPreference×ScoutVariance 공식으로 오퍼 여부·조건 계산, 구단별 오퍼를 점수순(동점 시 TeamId 오름차순)으로 정렬해 실제 제시 목록 생성. 새 게임 입단과 재계약이 같은 로직을 공유.
- `RosterCompetitor` / `RosterTurnoverResolver` — 시즌 전환 시 타 구단 로스터 Overall을 포지션 필요도 기준선으로 회귀+변동.
- `PlayerValueEvaluator` / `PlayerBuildAdvisor` — 선수 가치 계산, 포지션-능력치 배분 어긋남 경고(생성 차단 아님).
- `ManagerUsageAi` — 계약 역할+경쟁자+컨디션+감독 평가로 한 경기의 실제 기용을 결정. "구단 로스터 편성은 감독 AI가 소유한다"는 프로젝트 경계를 구현한 핵심 클래스.
- `ManagerLineupAi` — 감독 AI가 매 경기 타순과 수비 위치를 결정(`8723702`). 플레이어가 직접 라인업을 편성하지 않는다는 경계를 실제로 지킨다.
- `PlayerRetirementResolver` — 나이·전력·시장가치·성향 계수로 은퇴 여부를 결정론적으로 판정(`9bcc015`). 계약 오퍼의 상위 리그 이적 조항·강등 시 이적요청권 판단과 함께 계약-은퇴 통합 흐름의 시뮬레이션 축을 이룬다.

## 4. Baseball.Game

`Assets/02.Scripts/Game/` — Unity 의존. 세이브 대상 런타임 상태 소유 + 서비스 계층 + 매니저 부트스트랩.

### 4.1 커리어 진행 (`Career/`)

**상태 클래스 (세이브 루트)**
- `CareerState` — 새 게임 계약 완료 후 선수/리그/계약 상태 묶음.
- `SeasonState` — 시즌 식별자, `LeagueLevel`, `SeasonPhase` 진행 상태.
- `LeagueState` / `TeamState` / `PlayerState` — 구단·선수 세이브 상태. 구단은 ID로만 참조.
- `PostseasonState` — 4강 토너먼트 대진/진행/우승 구단.
- `SeasonScheduleState` — 시즌 경기 Seed·대진·완료 결과·구단 순위 기록.
- `SeasonAwardState` 계열 — 수상 후보 점수 + 확정 수상.
- `SeasonReviewState` — 시즌 결산 화면 진행 순서.
- `LeagueSeasonStatisticsState` 계열 — 리그 전체 원본 타격/투구/수비/경기 기록.
- `PlayerSeasonStatisticsState` — 내 선수 시즌 누적 기록.
- `PlayerContractState` — 현재 계약.
